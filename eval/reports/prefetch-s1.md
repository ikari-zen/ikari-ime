# ADR 0038 S1: 左文脈を縮めて、案 1 と今と案 4 の上限を比べる

- 日付: 2026-10-29
- 根拠: [ADR 0038](../../docs/adr/0038-prefetch-context-tolerance.md) §6.2 / §11、issue #1 の測定 (a)
- 範囲: 評価だけ。本体（`core/` `engine/` `macos/`）は変えていない。実装の可否は決めない（リードとユーザーが決める）
- コード: [eval/scripts/prefetch_s1/](../scripts/prefetch_s1/)（`make_stale.py` → `run.sh` → `analyze.py` / `compare.py`。捨てるスクリプトだが再現のために置く）

## 1. 先に結論

- **採る基準（すべての重み付きで Y 対 X の「期待 → 外れ」が「外れ → 期待」以下）は満たさない。** 切り方 A・B のどちらも、3 つの重みのすべてで Y は X より悪い（差し引き 4.4〜7.2 ポイント）。
- 1 位の正解率は、A: X 80.9% / Y 72.2% / Z 90.8%、B: X 77.1% / Y 74.0% / Z 87.7%。案 4 の上限（Z）は X より両方で明らかに良い。
- ADR §11 Q1 で承認済みの手順どおりなら、案 1 は実装せず、案 4 への切り替えを検討する材料になる（§5）。

## 2. 方法

3 つの腕（ADR §6.2）。

| 腕 | 意味 | セット | LM |
|---|---|---|---|
| X（今） | 外れて、新しい文脈・LM なしで返る | 元のセット | なし |
| Y（案 1） | 古い文脈の先行計算（LM つき）を当てる | stale（context の末尾から確定の単位を 1 つ取り除いた） | あり |
| Z（案 4 が当たったときの上限） | 新しい文脈の先行計算が当たる | 元のセット | あり |

- 共通: `--ranker full --repeat 1`、辞書は実機の `~/Library/Application Support/ikari-ime/dict`、モデルは同 `models/zenz-v3.2-small-Q5_K_M.gguf`、user-dir は空（既定の一時ディレクトリ）。読むだけで、ユーザーデータは書き換えていない。LM ありは別 target（`CARGO_TARGET_DIR=target/lm … --features lm-metal`）で、`--lm … --lm-deadline-ms 2000`。全 18 セット・各腕で LM の時間切れは 0（開始時の load average 12 / 6 / 4 と高めだったが、時間切れがないので順位には影響しない）。
- 対象: `eval/sets/*.tsv` のうち context が空でないケース。単位が 1 つしかない context と、取り除く単位が 12 字を超えるものは除く。reading と expected は変えない。
- 単位の切り方は測定 (a) と同じ規則による近似（issue #1 の記述から再実装。(a) の元のスクリプトは見つからなかったので、件数が少し違う）。
  - A（文節の近似）: 「かな以外の連続（漢字・カタカナ・英数）+ 続くひらがなの連続」を 1 単位。句読点は直前の単位に付ける。752 件（(a) は 776）。取り除く単位の長さは 1 字 24、2 字 248、3 字 281、4 字 87、5 字 53、6 字 31 ほか。
  - B（字種の変わり目）: 漢字・ひらがな・カタカナ・英数の変わり目。「ー」は直前の字種に続ける。1,506 件（(a) は 1,508）。1 字 978、2 字 336、3 字 92 ほか。
- 「期待 → 外れ」= 左の腕で 1 位が期待、右の腕で期待でない。「外れ → 期待」はその逆（`--out-cases` の rank が 1 かどうか）。`ikari-eval compare` の「改善 / 悪化」は順位全体の変化なので、数が少し違う（§4）。
- 重み付き: 単位の長さ L ごとの率を、診断ログ（`engine.log` と `engine-*.log.gz`。読むだけ）の `ctx_change` の `commit_chars` の分布で平均する。ケースのない L は除いて正規化する。重みは 3 通り。
  - a: 測定 (a) の分布（2026-10-28。n=59: 3 字 21、4 字 12、2 字 12、5 字 5、7 字 4、1 字 3、6 字 1、11 字 1）
  - log(convert): 今のログの `req=convert` で `dleft == commit_chars > 0`（n=66: 1 字 4、2 字 13、3 字 22、4 字 13、5 字 6、6 字 1、7 字 4、8 字 1、10 字 1、11 字 1）
  - log(全 req): 今のログの全 `req` で `dleft == commit_chars > 0`（n=589。1 字 156、2 字 87、3 字 121、4 字 74、5 字 56 ほか。13〜14 字の分は評価側にケースがない）

## 4. 分かったこと

- Y（案 1）は X（今）より、評価セットの上で悪い。A・B とも、3 通りの重みのどれでも差し引きが負（-4.4〜-7.2 ポイント）。採る基準を満たさない。
- 悪化が集中するのは取り除く単位が 2〜3 字のとき（A: 2 字 -52、3 字 -20。B: 2 字 -65）。ログの重みでは 2〜3 字が約 53%（35 / 66）を占めるので、重み付きでも負になる。
- 単位の長さごとの差し引きを 1 字から累積すると、A は一度も 0 以上にならない（最小 -73）。B は 1 字だけが +26 で、2 字で -39 になる。**差し引きが 0 以上に保たれる D_max は、A では 0、B では 1 字**（1 字から途切れず 0 以上が続く最大の長さ）。ただし B の 1 字は大半が助詞で、ログの重みでは 4 / 66（6%）と小さい。
- 長さごとに見て差し引きが 0 以上の長さは、A が 4、5、6、8、10、11、12+（件数は 87、53、31、7、2、1、3）、B が 1、4、6、10 ほか。4 字以上だけを足すと A は +8（199 件）、B は +1（100 件）で、ほぼ 0。ログの重みの約 41%（27 / 66）。
- Z（案 4 の上限）は X より良く、悪化がほとんどない（Z 対 X の「期待 → 外れ」は A で 0、B で 8）。重み付きの差し引きは +9.6〜+13.5 ポイント。Z 対 Y の差し引きは +15〜18 ポイントで、案 1 の副作用（伸びた分が LM と辞書の文脈から抜ける）の大きさがこれ。
- 「外れ → 期待」が Y 対 X でも一定数ある（A 63、B 116）のは、LM の利得。LM の有無だけの差は、Z 対 X のうち Z で LM が効いた分（A +75、B +160）に近い。stale の文脈の害は Z 対 Y（A +140、B +207）。
- セットでは、hiragana（表記のセット）の悪化が大きい（A -12、B -43）。Z 対 X では hiragana の悪化は 0 なので、原因は LM ではなく、古い文脈である。逆に verbs、funhen、rightctx は Y 対 X で良くなる。
- homophones-ext が A で 86%（648 / 752）、B で 74%（1,112 / 1,506）を占める。全体の数字はほぼこのセットの数字。

## 5. 採る基準と、案 4 に切り替える材料

- 基準（重み付きで Y 対 X の「期待 → 外れ」≤「外れ → 期待」）: **満たさない**（A・B・3 重みのすべて）。
- ADR §11 Q1 は、基準を満たさないとき案 4 に切り替えてよいと決めている。材料:
  - Z の上限は X より 9.6〜13.5 ポイント良く、Z 対 X の悪化は A で 0 件、B で 8 件。案 4 が当たれば、今より悪くならない。
  - 案 4 が当たる割合は S1 では分からない。S1 の Z は「補った left が実際の文脈と完全に一致する」仮定。ADR §8 の 3 のとおり、補った文脈が Space の文脈と一致する割合を診断ログで測る必要がある（外れれば今と同じ LM なしに戻るだけなので、一致した分だけ得になる）。
  - 案 1 を一部だけ使う選択肢（推測）: 確定の単位が 4 字以上のときだけ当てる、という条件を足せば、評価セットでは差し引きがほぼ 0（A +8 / 199 件、B +1 / 100 件）になる。ただし、救えるのはログの約 41%、得もほぼ 0 で、標本が小さく、この規則に値を掃引する根拠はまだない。実装の複雑さに見合わないと思う。

## 6. 推測と限界

- 評価セットは文脈が正解を決める落とし穴を集めている（homophones-ext が大半）。実利用では、続きの読みが直前の確定に依存する割合が低いと思われ、Y の害は実利用でこれより小さい可能性がある（ADR §6.2 の見込みと同じ。数字は出ていない）。逆に、LM の利得も実利用では評価セットほど大きくない可能性がある。どちらが大きいかは S1 からは言えない。
- 単位の切り方は規則による近似（測定 (a) と同じ限界。(a) の元のスクリプトは見つからず、A は 752 件で (a) の 776 件と 24 件違う。句読点・記号の扱いの差と思う）。実際の確定の単位は、ログの `commit_chars` どおりに分かれていない評価セットの文脈とは一致しない。
- 重みは、`dleft == commit_chars` の行の `commit_chars`。ログの量が少ない（66 行）ので、重みの形は変わりうる。3 通りの重みの結論は同じだった。
- X・Y・Z とも `--repeat 1`、学習なし（空の user-dir）。実機の学習の効果は含まない。
- 付録に全表（`analysis.md` の出力）を置く。
