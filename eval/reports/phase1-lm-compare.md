## 4. 貪欲生成（`ikari-eval gen`）: プールの外から出す

採点（`--lm`）は変換器の N-best（50 件）の中から選ぶ。ところが **AJIMEE では、正解が 50 件以内に入っているのは 116/200（58%）しかない**（R3 / R6 いずれも同じ）。LM の採点は、入っている 116 件のうち 101/116（87%）を1位にしており、**上限はプールの網羅率で決まっている**。そこで、LM が読みから直接出力する（貪欲、`</s>` まで）ときの1位正解率を測った。

| モデル | AJIMEE 全体 | ext test 全体（話題 kind） | AJIMEE 生成の時間 p50 / p99 | ext 生成の時間 p50 / p99 |
|---|---|---|---|---|
| edge Q8_0 | **80.5%** (161/200) | 72.4% (131/181; 話題 123/173) | 19.9 / 76.2 ms | 4.6 / 25.9 ms |
| edge f16 | 80.5% (161/200) | 72.4% (131/181) | 25.5 / 94.6 ms | 6.1 / 23.2 ms |
| zenz small | **85.5%** (171/200) | 79.6% (144/181; 話題 136/173) | 37.0 / 135.7 ms | 10.9 / 15.9 ms |
| zenz xsmall | 69.0% (138/200) | 66.3% (120/181; 話題 112/173) | 16.0 / 61.4 ms | 4.1 / 37.8 ms |
| （比較）採点 R6、300ms | edge 50.5%、small 51.0%、xsmall 45.0% | edge 71.3%、small 76.2%、xsmall 71.3% | edge 24.7 / 90.8 | edge 7.3 / 9.6 |

- **生成は、採点より同じ時間で AJIMEE を大きく上げる**（edge: 50.5% → 80.5%、small: 51.0% → 85.5%）。時間は採点より短い（候補のバッチを作らず、プロンプトの続きを 1 本だけ出すため）。
- ext（短い読み、辞書のプールが強い）では差が小さい: edge 71.3% → 72.4%、small 76.2% → 79.6%、xsmall は 71.3% → 66.3% と下がる。
- 生成と採点で正解が違う: ext の edge で、生成だけ正解 10 件、採点だけ正解 8 件（和集合 139 件 = 76.8%）。small は生成だけ 16、採点だけ 10（和集合 154 件 = 85.1%）。AJIMEE は edge で生成だけ 66、採点だけ 6。**採点と生成は補い合う**。
- 生成の出力は読みと矛盾しうる（辞書の制約がない）。実用では、生成の結果を**候補として N-best に足し、Topic と学習、LeftContext と一緒に採点する**か、読みとの整合を検証する（Zenzai の方式）必要がある。この検証はここでは測っていない。
- ここでの生成は、左文脈を末尾 100 文字（zenz は 40 文字）、`max_new_tokens=192` で行った。

## 5. 段階的な使い方のシミュレーション（採点方式）

方法は phase1-topic.md §4.1 と同じ（CLI で各ケースを LM なし、edge、small、xsmall の4段で実行して候補とスコアを集め、前段の1位と2位のスコア差 T 未満のときだけ次段の結果を使う。待ち 5000ms で時間切れを除く）。単段の正解率は eval と一致した（ext: 58.6 / 71.3 / 76.2 / 71.3%、AJIMEE: 21.0 / 50.5 / 51.0 / 45.0%）。スクリプトはリポジトリに入れていない。

### 5.1 ext test（181 件）

| 段の組み | T | 後段を呼ぶ割合 | 1位正解率 |
|---|---|---|---|
| edge のみ / small のみ / xsmall のみ | - | - | 71.3% / 76.2% / 71.3% |
| xsmall → small | 1000 / 2000 / 4000 | 12.2% / 25.4% / 50.3% | 71.3% / 74.0% / 75.7% |

| LM なし → edge → small | (2000, 2000) | edge 70.2%、small 25.4% | 74.6% |

|---|---|---|---|

### 5.3 読みの長さで切り替える（AJIMEE）

| 切り替え（L 文字以下 / それより長い） | 1位正解率 | 前の方を使う割合 |
|---|---|---|
| small / xsmall（L=10） | 46.0% | small 16% |
| small / xsmall（L=20） | 49.0% | small 46.5% |
| small / edge（L=10） | 51.0% | small 16% |
| small / edge（L=20） | 50.5% | small 46.5% |
| edge / small（L=20） | 51.0% | edge 46.5% |

- **速い段を xsmall から edge に替えると、同じ呼び出し割合で正解率が上がる**: 長い読み（AJIMEE）で、small を 22% だけ呼ぶ edge → small（T=1000）は 51.5%（small 単独 51.0% を超える）。xsmall → small は small を 27% 呼んで 49.0%。
- 短い読み（ext）では edge → small（T=2000）が small を 28% だけ呼んで 75.1%（small 単独 76.2%、xsmall → small は 25% で 74.0%）。小さな改善。
- 読みの長さによる切り替えは、速い段を edge にすれば、small を短い読みだけ（16%）に使っても AJIMEE で 51.0% に達する。

## 6. 推奨案（ADR 0003 §7.1 #1 の判断材料）

### 6.1 事実の整理
1. **edge(Q8_0) は、採点で使うと xsmall と同じ速さ・メモリで、長文の正解率は small に並ぶ**（AJIMEE 50.5% 対 small 51.0%、xsmall 45.0%）。短い読みの ext では xsmall と同じ（71.3%）で、small より約 5 ポイント低い。Topic を外したときは xsmall より +7 ポイント。
2. **edge の本領は生成にある**: プールの網羅率が 58% しかない AJIMEE で、貪欲生成なら 80.5%（README の 0.805 と一致）。zenz small の生成は 85.5%。採点（約 51%）より約 30 ポイント高く、時間は同じかより短い。長い読みでは、生成が最大の改善点になる。
3. edge は 36MB（Q8_0）で zenz small の約半分、RSS は small の約 55%。重みは Apache-2.0（語彙は CC BY-SA 4.0 で zenz と同じ扱い）。
4. 弱点: 話題・プロフィールの条件を持たない（Topic で補う）。数字や記号を含む入力、192 トークンを超える文脈は精度が落ちる（README）。ext の「話題」では small に及ばない。

### 6.2 推奨
**LM の組み合わせ: 「短い読みは zenz small、長い読みは edge。迷ったときだけ small」**を、採点と生成の両方で組む案を推す。

| 場面 | 推奨 | 根拠 |
|---|---|---|
| 短い読み（10 文字以下。FR-04 のこまめな確定の大半） | **zenz small で採点**（ADR 0003 §2.2 のとおり）。先行計算が成り立たなければ **edge(Q8_0)**（xsmall と同じ 7ms 台で、Topic なしでも強い） | ext で small 76.2%、edge 71.3%。edge は xsmall と同じ速さで正解率は同じ（xsmall への置き換えは、同等以上で、メモリは小さい） |
| 長い読み（11 文字以上） | **edge(Q8_0)**。edge の 1位と2位の差が 1000 未満のとき、時間が残っていれば small も使う（edge → small、T=1000） | AJIMEE: small を 22% だけ呼んで 51.5%（xsmall → small は 27% で 49.0%）。edge 単独で 50.5% |
| 長い読みで採点が頭打ち（プールに正解がない） | **edge の貪欲生成の結果を候補としてプールに足す**（フェーズ2の先行計算の枠で） | AJIMEE の網羅率 58%。生成で 80.5% |

- **「xsmall」の席は edge に替える**（ADR 0003 §2.2 の長い読みの xsmall）。速度とメモリは同じで、正解率は AJIMEE で +5.5 ポイント（p=0.007）、Topic なしの ext で +7 ポイント。xsmall を残す理由は、ほぼない。
- **edge と small の両方を常駐させる場合のメモリ**: 約 360MiB（small）+ 約 80〜120MiB（edge の追加分）。ADR 0003 §6-10 の約 500MiB の見積もりの範囲。edge だけに絞れば RSS は約 200MiB。
- **edge だけで済ませる選択**（モデル 1 つ、約 200MiB）: ext で small より約 5 ポイント低い代わりに、メモリが半分、速度は 2.4 倍、AJIMEE では同等。NFR-02（16ms）を同期でも満たす。ADR 0003 §7 #1 の「短い読みに small を常用するか」に対する、**xsmall よりずっと良い代替**になる。
- 優先順位の提案: (1) 長い読みの xsmall を edge に替える（実装済みで、変更が小さい）。(2) 生成の候補への追加（フェーズ2。AJIMEE で +30 ポイント級の期待。ただし読みとの整合の検証が要る）。(3) 短い読みの small か edge かは、先行計算の実測（フェーズ2）の後に決める。

### 6.3 この比較の限界
- ext は LLM（Claude）が作った文脈で、ユーザーの抜き取り確認が済んでいない（ADR 0003 §7 #4）。生成モデルに有利な偏りがありうる。取り込んだ自分の文章での確認が必要。
- ext test の否定・文法は 3 件・5 件。差が出る規模ではない。
- AJIMEE は edge の README が評価に使っているデータ（学習データに近い分布の可能性。README の 0.805 は同じベンチの結果）。edge の AJIMEE の数値は、zenz より有利に出ている可能性がある。ext は edge の README にない。
- 生成の出力が読みと整合するかは測っていない（辞書の制約なし）。
- 時間は Apple M4 + Metal の値。GPU が混んでいるときや電池駆動時は測っていない（ADR 0003 §6-9）。
