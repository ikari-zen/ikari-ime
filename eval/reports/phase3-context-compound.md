# フェーズ3 左文脈の語と候補が1語の複合語になるときの加点（ADR 0007 のスパイク）

- 実行日: 2026-10-13 / 基準は main f9ebf3a（辞書は `data/build/dict`。sha256 が基準の snapshot `main-f9ebf3a` と一致）/ release ビルド / Linux のコンテナ（LM なし）
- 実機の IME とユーザーデータには触れていない（CLI は一時ディレクトリを `IKARI_USER_DIR` にした）
- **コードはコミットしていない**。`core/src/ranker/left_context.rs` を一時的に書き換え、設定のキー（`left_context.cb` など）で規則の形と値を切り替えて測った。測ったあと元に戻した
- 判断は [ADR 0007](../../docs/adr/0007-left-context-compound.md)。原因の調査は fix/suffix-ka のレーンのレポート（phase3-suffix、未マージ）の §2.3、§6

## 1. 測ったもの

LeftContextRanker の中で、候補ごとに次を調べる規則を足した（案 A）。

> 左文脈の最後のトークンの表記 + 候補の表記 が、辞書の1つの項目の表記と一致する

当たった候補に加点する。規則の形（どの条件を付けるか）と加点の大きさを、次のつまみで切り替えた。

| つまみ | 意味 |
| --- | --- |
| `cb` | 加点の大きさ（0 で無効） |
| `cmode` | 0: LeftContextRanker の差分に `-cb` を足す。1: 差分を上限（`-max_total` = -6000）まで引き上げてから `-cb` を足す |
| `cfirst` | 0: 1語の候補だけ。1: 複数語の候補は最初の語で調べる |
| `ctail` | 0: 最後のトークン。N: 左文脈の末尾 1〜N 文字（トークンの区切りによらない） |
| `cnoun` | 1: 最後のトークンが名詞（品詞1 = 名詞）のときだけ |
| `creading` | 1: 複合語の読みが候補の読みで終わる。3: 複合語の読み = 左の語の読み（同じ表記の項目のどれか）+ 候補の読み |
| `cpos` | 1: 複合語が 名詞,普通名詞。2: 名詞,普通名詞 か 名詞,固有名詞,地名 |
| `cbest` | 1: 当たった複合語のうち、cost + penalty がいちばん小さいものと同じ lemma の候補だけに加点する |
| `ckanji` | 1: 候補が漢字を含むときだけ |

評価は `ikari-eval --ranker full --repeat 1 --split dev`（katakana-suffix、homophones-ext、hiragana、homophones）で、基準と1位が変わったケースを数えた。値は dev で選び、test は確かめるのに使った。

## 4. セットにない入力（CLI、文脈 + 読み、LM なし。119 件 + 地名 16 件）

評価セットでは悪化が出にくい（phase3-suffix §3 で、本当か のような入力がセットにないことが分かっている）。そこで、名詞のあとに1文字か短い語を打つ自然な入力を集めて、基準と1位を比べた。下は最終形（cb 3000、cpos 2）で**1位が変わったもの**だけ。ほかは1位が同じ（子供 + たち、私 + たち、彼 + ら、予定 + どおり、会社 + の、父 + と、犬 + と、本当 + か、無理 + か など）。

### 4.2 悪くなったもの、間違いのままのもの

| 入力 | 基準の1位 | 変更後の1位 | 期待 | 当たった複合語 | 評価 |
| --- | --- | --- | --- | --- | --- |
| 水 + と | と | 都 | と | 水都（スイト） | **悪化**。水 に スイ の読みがある |
| 人 + ごと | ごと | 事 | ごと（人ごと） | 人事（ヒトゴト） | **悪化**（表記の好みの範囲。人事 も正しい表記） |
| 本 + と | 都 | 途 | と | 本途（ホント） | 間違いのまま |
| 人 + じ | 寺 | 事 | ? | 人事（ジンジ） | 間違いのまま（期待が決まらない） |
| 中 + し | 史 | 士 | 止 / 市 | 中士 | 間違いのまま |
| 東京 + と | 兎 | 都 | と / 都 | 東京都（地名。cpos 2） | どちらとも言える（基準の 兎 は誤り） |

- 「名詞 + 1文字の助詞」を、名詞を確定してから**助詞だけ**で変換したとき、名詞 + 漢字1文字 の複合語が辞書にあると、助詞が負ける（水 + と）。複数の語に分かれる入力（水 + とおゆ）は、規則の対象外（1語の候補だけ）なので変わらない。
- `cbest` がないと、当たった複合語のうち珍しいもの（年官、目路、部課）が勝つことがあった（年 + かん → 官、目 + じ → 路、部 + か → 課）。`cbest` でいちばん安い複合語（年間、目次、部下）だけに加点するようにして消えた。子供 + たち は 子供たち と 子供達 が同じ lemma なので両方に加点され、基準どおり たち のまま。
- 条件ごとに消えた失敗:
  - 名詞の条件がないとき: できる + かぎり → 限り（できる限り）、た + いし、は + しよう。
  - 読みの条件がないとき: 私 + たち で 私立（シリツ）が当たる、三日 + ほど で 日程 が当たる。
  - 普通名詞（と地名）の条件がないとき: 犬 / 猫 / 人 + と → 都（犬都、猫都、人都。どれも 名詞,固有名詞,人名,名）、一 + じ → 児（一児。人名）。
  - 読みを「解析器が選んだ左の語の読み」1つに絞ると（creading 2）、日本 + ご（ニッポン と解析される）、店 + いん（ミセ）、国 + さい が直らなくなった。同じ表記のどの読みでもよい形（creading 3）にした。

## 5. 速さ

`SPIKE_TIME` で LeftContextRanker の `rank` 1回の時間を測った（katakana-suffix と homophones-ext の全件、`--repeat 20`、27552 回）。

| 構成 | p50 | p99 | p99.9 | 最大 | 1回の表記の検索 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 基準（規則なし） | 1.6 µs | 4.1〜4.6 µs | 30 µs | 1.0〜1.5 ms | 0 |
| 最終形 | 2.9〜3.1 µs | 24〜26 µs | 55〜57 µs | 263〜304 ms（最初の1回） | 平均 2.0 |

- 最大の 263〜304 ms は、最初の呼び出しで読みの逆引き表（`Dictionary::reading`。ADR 0006 §16.5）を作る時間。eval は逆引き表を先に作らないので、最初のケースに乗る。エンジンは起動のあとに裏で作る（`warm_reading_index`）。
- 変換全体の warm p99（snapshot の summary）は基準 0.20〜0.44 ms、変更後 0.21〜0.51 ms で、同じ辞書で取り直したときの揺れ（基準どうしで 0.19〜0.44 ms）と区別できない。p99 2 ms の予算に対して、Ranker の増加は p99 で約 20 µs。

## 6. ユーザー辞書

一時ディレクトリのユーザー辞書に `にほんごばん 日本語版 名詞` を登録すると、日本語 + ばん が 板 → **版** になった（`DictionarySet` が表記の検索をユーザー辞書にも広げるため、規則はそのまま効く）。`いかりばん 錨版 固有名詞` は、cpos の条件（普通名詞と地名）で当たらなかった。
