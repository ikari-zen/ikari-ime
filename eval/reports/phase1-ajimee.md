- データ: AJIMEE-Bench `JWTD_v2/v1/evaluation_items.json`（200 件。左文脈なし 100、あり 100。CC BY-SA 3.0。`eval/scripts/fetch_ajimee.sh` で取得、リポジトリには入れない）
- 辞書: `data/build/dict`（形式 v2、`policy/chive.tsv`、grammar_id=0xb570a1f4bdffbbfb）
- 1位正解 = 出力全体が別解のどれかと完全一致。許容解は複数。入力はカタカナをひらがなにしたもの。
- 値の調整には使っていない（調整は `homophones-ext.tsv` の dev 分割のみ）。

## LM あり（full + zenz-v3.2、Metal、`--lm-budget-ms` を変えた）

| モデル | 待ち時間の上限 | 全体 | ajimee | ajimee-文脈 | 時間切れ | cold p50 / p99 (ms) | 最大 RSS |
|---|---|---|---|---|---|---|---|
| なし | - | 21.0% | 23.0% | 19.0% | - | 1.0 / 1.6 | 約 85 MiB |
| xsmall (21MB) | 30（既定） | 38.0% (76/200) | - | - | 55.4% | 26.7 / 41.5 | - |
| xsmall | 300 | 45.0% (90/200) | - | - | 0% | 21.5 / 80.4 | - |
| small (74MB) | 30（既定） | 21.0% (42/200) | 23.0% | 19.0% | 100%（すべて時間切れ） | 39.1 / 41.4 | 158.5 MiB |
| **small** | **300** | **51.0% (102/200)** | 52.0% | 50.0% | 0% | 58.6 / 209.5 | - |
| small | 3000 | 51.0% (102/200) | 52.0% | 50.0% | 0% | - | - |

- AJIMEE は 1 文が長い（数十文字）ので、small の採点は 1 回に約 58ms（p99 約 210ms）かかり、既定の 30ms では間に合わない。待ち時間を 300ms に伸ばすと 51.0% で、LM なし（21.0%）の 2.4 倍。
- xsmall は速い（cold p50 21〜27ms）ので、30ms でも 38.0%（時間切れ 55%）まで届く。
- 時間切れ率の数え方に不具合がある（`lm/src/ranker.rs`）: 「同じ要求がまだ処理中なら、重ねて送らずに時間切れとして戻る」分も `timeouts` に数えるが、`requests` には数えない。評価が同じ変換を続けて呼ぶと、処理が長引くたびに `timeouts` だけが増え、small の既定（30ms）の行のように「時間切れ 666 / 要求 200（333%）」と 100% を超える。ext セットのように処理が間に合う場合（0.3〜1.1%）は影響が小さい。直すなら分母を `rank()` の呼び出し数にする（未対応）。
- `ikari-eval` の LM 付きビルド: `CARGO_TARGET_DIR=target/lm cargo build --release -p ikari-eval --features lm-metal`（cmake 4.4.4）。

## 失敗の主な型（full、LM なし）

- 同音異義語の選択（`成年市`/青年誌、`返信ベルト`/変身ベルト、`他変数`/多変数）: 文脈 1〜2 語では足りない。LM で大きく改善する。
- 低コストのカタカナ書き（`ココ`、`ヨコハマ`）: `katakana_variant` +5000 で多くが消えたが、lemma がカタカナのもの（`ココ` の lemma は `ココ`）は述語に当たらない。
- 数字の書式（期待 `３年９月１５日`、出力 `三年九月十五日`）: 変換結果の数字の正規化は未実装。
