# 漢字で書く人名の加算を軽くする（person_name_kanji。#89）

日付: 2026-10-30。`たどころこうじ`（LM なし）で 田所浩二 は 29 位。ポリシーに述語 `person_name_kanji` を足し、値は掃引で決めた。目的は部分的にしか達しない（LM なしでは 29 → 19 位。LM あり 2000ms では 2 → 1 位。§4）。

## 1. 原因（測った値、`--ranker cost`）

- 1 位は 誰どころ工事 15054（誰 + どころ + 工事。誰 の読みが た）。田所浩二 は 22038 で 29 位。田所工事 18593、田所コウジ 18745。
- 田所浩二 と 田所工事 の差 3445 の内訳: 人名の行（姓 + 名）は、それぞれ `proper_noun` +1000 と `person_name` +1000 を受ける（**姓と名の 2 語で、合計 +4000。二重にかかる**。確かめた: 辞書の行ごとに判定している）。残りは 浩二 のコストが 工事 より高い分。
- すべての人名の加算（`proper_noun`、`person_name`）を 0 にしても、田所浩二 は 11 位（15054 の 誰どころ工事 には届かない）。加算の大きさだけでは 1 位に届かない。
- LM あり: 実機に近い既定の締め切り（72ms。読み 7 文字）では LM が効かず、LM なしと同じ順位。待てるとき（2000ms、時間切れ 0）は 基準で 2 位（田所浩二 が 2 位、誰どころ工事 が 1 位）。

## 2. 掃引（基準は main b36d647 の辞書。全 `eval/sets/*.tsv` + AJIMEE の LM なし = cost / full、LM あり = full + zenz 2000ms は issue のセットだけ）

| 1000 / 750 | （全セットは未実施） | | 26 位 | 2 位（変化なし） | |
| 1000 / 500 | 1 | 5 | 21 位 | 1 位 | はる: 春 → ハル |
| 1000 / 250 | 1 | 7 | 19 位 | 1 位 | 同上 |

悪化 0 の点がない。悪化はカタカナの人名（ハル、キク、ノボル、ポーっと）が漢字の普通名詞・動詞に勝つもの。

### 2.2 採った案: 漢字を含む人名の行だけを軽くする（`person_name_kanji`。カタカナの人名は変えない）

人名の行（姓・名）のうち、表記に漢字を含むもの（473425 行）に値を足す。

| 値 | 1 位の悪化 | 1 位の改善 | 田所浩二（cost / full） | LM 2000ms | 悪化の例 |
| --- | --- | --- | --- | --- | --- |
| 0（基準） | ― | ― | 29 位 | 2 位 | |
| **-500（採用）** | **0（snapshot）** | 3 | 19 位 | 1 位 | |
| -1000 | 0 | 5 | 16 位 | 1 位 | |
| -1500 | 3 | 5 | 9 位 | 1 位 | すずき（スズキ → 鈴木。brand-katakana） |
| -2000 | （全セットは未実施） | | 7 位 | 1 位 | |

- 悪化 0 の範囲は -1000 まで確かめた（-1500 で スズキ が 鈴木 に負ける）。崖から余裕を残した保守的な -500 を採った（1 位の動きを最小にする）。
- 1 位が変わったケース（期待に関係なく）は、-500 で 6726 件中 3 件（place-names の うめだ。梅だ → 梅田 で、改善）。-1000 でも 7 件で、すべて place-names（梅田、太田、タカシ → 敬）。AJIMEE は -500 でも 1 位の表記が変わるのは 1 件（順位に影響しない文）。
- 珍しい人名が上に出すぎる副作用（ADR 0012）は、評価セットでは 1 位の変化として現れなかった。ただしセットは人名が少ないので、実機で確かめる必要がある（ユーザーの判断を仰ぐ）。

## 3. snapshot（`eval/scripts/snapshot.sh --lm … --ajimee`）

- snapshot の eval（LM なし・あり）は、ajimee を除いて基準と一致（ケース別の順位の差 0）。AJIMEE の 1 件（ajimee-2100）が、LM なし・ありとも「正解の順位が 49 位 / 42 位 → 50 位より下」になる（1 位だった文ではない。1 位の数は 52 / 200、111 / 200 のまま）。`snapshot.sh` はこれを「悪化」として数えるので、終了コードは 1（差分あり）。
- 学習のシナリオ 14 本は一致、segments は一致、LM の時間切れ 0。CLI golden の差 28 行（人名の候補の順位）。
- warm p99 の警告 2 件: homophones-cost が 0.186 → 0.306ms、verbs-full-lm が 40.7 → 149.7ms。辞書の差は加算 1 種類で、順位付けのコードは同じ。推測: ほかのプロセスの負荷による揺れ（LM の呼び出しが入る構成。取り直していない）。

## 4. 目的の達成の程度

- LM なし（cost / full）: 田所浩二 は 29 → 19 位。1 位は 誰どころ工事 のまま。人名の加算を下げるだけでは、誰 + どころ + 工事 の経路（15054）に届かない（加算をすべて 0 にしても 11 位。§1）。
- LM あり（待てるとき、2000ms）: 2 → 1 位。実機に近い既定の締め切り（72ms）では LM が効かず、LM なしと同じ。
- 残る原因は、誰（読み た）+ どころ + 工事 という分割の安さ。これは人名の加算と別の問題で、この PR では扱わない。

## 5. 再現
