# Web のカタカナ語の収集 PoC（ADR 0039 §7 の 2。#113）

日付: 2026-11-06。main = dfc32fb。**値は決めていない**（下の掃引は材料。採る値は PR で明示し、ユーザーに確認する）。公開の語だけを載せる（人名は載せない）。配布物には何も入れていない（ADR 0039 §10, §12 の条件）。

## 0. 要約

1. Wikipedia 日本語版 20261001 の分割ダンプ 5 ファイル（約 93 万記事、約 20 億字）から、カタカナの連なりを数えた。df≥5 の連なりは 265,733 語（TSV で約 6.7MB）。辞書にある語（F1）、形の規則（F3）、手がかり（F4b）、固有名詞だけの部分への分解（F4c）、既知の普通名詞だけの連なり（F5）を除くと **47,516 語**。
2. **バージョニング（df 16）、シャーディング（df 6）、オブザーバビリティ（df 17）は入る。** ばーじょにんぐ の順位は、辞書に足さないとき LM なし・LM ありとも **32 位**、足す（df≥5、F5 あり、コスト 13000〜17000）と **LM なし（cost・full）・LM あり とも 1 位**。df の下限を 20 にすると 32 位のまま（df 16 のため）。しゃーでぃんぐ は同梱の語彙集（IT）で、足す前から full で 1 位（cost のみ 12 位）。
3. 既存の評価セット（snapshot の全セット、eval/sets/*.tsv の全部、AJIMEE。LM なし・あり）で **1 位の悪化は 0**。katakana-like は 85 → 89（LM なし）、88 → 92（LM あり）。ほかのセットは 1 位が 1 件も変わらない。
4. 一方、**混入は多い**。抜き取り 150 語の下書きでは、普通名詞の単語は 5 語（3%）、普通名詞の連結が 47 語（31%）、固有名詞が 91 語（61%）、非語・断片が 7 語（5%）。F4b・F4c の効きは弱い（下 §5）。F4a（Wikidata の P31）は未実施（ユーザー決定待ち）。
5. 標本を増やすと再現率はゆっくり伸びる（1→5 ファイルで df≥5: 31.8% → 50.0%）。飽和していない。

## 1. 条件

- ダンプ: jawiki-20261001 の pages-articles（分割）の 1・2・4・5・6（後半の p4307948p5301321）。取得元は dumps.wikimedia.org のみ。sha1 は dumpstatus.json と一致。sha256:

  - 3 番と 6 の前半は取っていない。**標本は ID の順で偏る**（1・2 は古い記事、5・6 は新しい記事）。無作為抽出（索引から Range）は試していない。
- 収集（`eval/scripts/webwords_collect.py`）: 名前空間 0、リダイレクトを除く。題が「一覧」で終わるもの・曖昧さ回避を除いた（**ADR にない追加。名前の羅列で df が歪むため**。除いた記事は 5 ファイルで約 4.6 万）。記法は正規表現で除く。連なりは U+30A1〜U+30FA と ー。形態素解析なし。直後の手がかり（さん、氏、社、州、市、科、属、目、県…）の回数 cue も数えた。
- 記事数（数えた記事）: 55,325 / 96,777 / 225,658 / 286,498 / 266,088 = 930,346。
- 収集の時間は計っていない（1 ファイル Python 1 スレッドで数分〜十数分の桁）。
- 辞書: `eval/scripts/webwords_build_dict.sh` が xtask の手順と同じ引数で ikari-dict-builder を呼ぶ（data/ には書かない）。webwords は `--notcore-lex` と vectors の `--lex` に渡す。基準の辞書もこの手順で作った（実機の辞書とは label が違い、sha256 は一致しない。比較は同じ手順で作ったもの同士）。
- 読みはカタカナ → 表記のまま（Sudachi の lex の読みの列に表記のカタカナ）。品詞は 名詞,普通名詞,一般。

## 9. 未実施・限界

- F4a（Wikidata P31 を API で引く）は未実施（ADR §7、ユーザー決定の 2 が未決）。
- 無作為抽出（索引と Range）は未実施。標本は ID 順の 5 ファイル（約 64% の記事）。
- 混入率の判定は下書き 150 語。ユーザーの確認前。評価セット `webwords.tsv` は作っていない（期待はユーザー確認後）。
- 雑音の「頻度上位 3000 語」（R5）は、リポジトリで再現できないため、S0 の守る群 6,999 読みで代用した。
- 掃引は LM なしが中心。LM ありは 3 点（17000・15000・13000）の snapshot と、katakana-like などの 6 セットだけ。LOO は LM なしのみ。

## 10. ADR との食い違い・懸念（決めていない）

- **左右 ID**: ADR §0.3 は 5139/15000 が最頻とするが、今の Sudachi（20260723）で名詞,普通名詞,一般 のカタカナだけの行を数えると 5144/5144（約 3.4 万行）が最頻。5144 の多くはコスト約 2,148 の高頻度語（small）。5139/15000 は 6,364 行。LOO では 5139 の方がわずかによい。ID の決め方（最頻 / 5139 の周辺）は要判断。
- **一覧の大きさ**: §2.7 の「数万行・数 MB」に対し、df≥5 で 26.6 万行・6.7MB。
- **収集の追加条件**: 「一覧」の題と曖昧さ回避を除いた（ADR にない）。
- **ライセンス**: 一覧は Wikipedia の本文から数えた語と頻度で、PoC の間は scratch にだけ置いた（リポジトリにも配布物にも入れていない）。このレポートには語と df を少数載せている（人名は載せていない）。それも CC BY-SA 4.0 の表示が要るか、ADR §12 の確認できなかった点（一覧が翻案にあたるか、ShareAlike が辞書に及ぶか）は未解決のまま。
- **固有名詞が多い**: 方針 2（固有名詞は入れない）を守れる水準に F4b・F4c では届かない（§5, §6）。F4a の効きを測るまで、行を足す案は「普通名詞に絞れていない」。

## 11. 次に聞くこと（推奨つき）

1. 標本: 全 7 ファイルか、新しい記事に重みか（バージョニング・シャーディング は新しい側にだけ出た）。推奨: 新しい側（5・6）を含め、索引から無作為に取る。
2. F4a: Wikidata API で候補だけ P31 を引いてよいか（取得だけ。Wikimedia のみ）。推奨: はい。df≥5 の 4.7 万語なら 1,000 回弱の取得。
3. 採る点の範囲: F5 あり、df≥5〜10、コスト 13000〜17000（守る群が動かない範囲）で、最終は F4a の結果を見てから。

## 12. 再現

eval/scripts/webwords_loo.sh <scratch> base ; eval/scripts/webwords_loo.sh <scratch> 5,on,15000   # §8（katakana_s0_prepare.py の出力が要る）
