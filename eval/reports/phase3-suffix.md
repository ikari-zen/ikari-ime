## 2. 原因（測った値）

経路のコストは、`ikari --format tsv`（コストと score）と、Sudachi の lex.csv・matrix.def から計算し直した値が一致することを確かめてから分解した。
以下の「lemma_rank」「frequent_compound」は辞書のポリシーの加算。

### 2.1 化 と 終助詞の か（もじれつか、自動 + か）

| 経路 | 語のコスト | 前からの連接 | EOS への連接 | 合計 |
| --- | ---: | ---: | ---: | ---: |
| 文字列 + か（助詞,終助詞） | 6319 | -629 | **-2538** | **7330** |
| 文字列 + 家（接尾辞,名詞的,一般） | 9897 | -4895 | -819 | 8361 |
| 文字列 + 化（接尾辞,名詞的,サ変可能） | 6214 | -2274 | **+364** | 8482 |

（どれも 文字列 9671 + lemma_rank 2060 + frequent_compound -8000 + BOS 447 を含む。）

- 化 は語のコストも前からの連接も か より有利だが、EOS への連接で 2902 負ける。Sudachi のサ変可能の接尾辞（右ID 5765〜5770）は、後ろに「する」が続く前提で EOS への連接が正（+219〜+875）になっている。
- 自動 + か（左文脈あり）は、経路のコストが 家 4183、化 4304 で、LeftContextRanker が 家 に -6000（上限）、化 に -5096（連接 -2274 の超過分 × 4）を足す。1位は 家 -1817、科 -985、化 -792。
- **か と 化 のどちらが自然かは、前の名詞で決まる**（文字列化、文書化 / 本当か、無理か）。この区別は品詞やコストにない（§3.2 の実験）。

### 2.2 副詞「こう」「そう」の分割（こうぞうか、こうかそくてい、そうじき）

| 経路 | 内訳 | 合計 |
| --- | --- | ---: |
| こう（副詞）+ 増加 | BOS→副詞 -1304、こう 4167、副詞→名詞 695、増加 6498 + lemma_rank 609、EOS -1334 | **9331** |
| 構造 + 化 | BOS 447、構造 6922 + 330、連接 -2274、化 6214、EOS +364 | 12003 |
| 構造化（1語の項目） | 10822 + lemma_rank 2994（chiVe 31404 位）、BOS 447、EOS +364。**frequent_compound は 3万位までなので当たらない** | 14627 |
| こう + か（副助詞）+ 測定 | こう 4167、か 5253、連接 -1304 × 2、測定 6514 + 808 | **13407** |
| 硬化 + 測定 | サ変可能の名詞どうしの連接 -601 | 13865 |
| 効果 + 測定 | 普通名詞,一般 → サ変可能の連接 760 | 14203 |
| そう（副詞）+ 時期 | そう 4066、時期 **-372**（負のコスト）、EOS 601 | **3254** |
| 掃除機（1語の項目） | frequent_compound が当たって 5952 | 5952 |

- 指示副詞 こう・そう・どう（4066〜4200）と もう（3194）は、ひらがな2文字の副詞（374 件）の中で飛び抜けて安い（ほかは 5000 以上、多くは 8000 以上）。副詞から名詞への連接も +263〜+695 と小さい（「もっと前」「ちょっと時間」のような正しい並びがあるため）。漢語の読みの頭（こう、そう、どう）を副詞で切る経路が安くなる。
- 構造化、拡張性（33312 位）、規格外（30606 位）は1語の項目があるのに、`frequent_compound` の順位の上限（3万位）のすぐ外で加点が届いていなかった。

### 2.3 文脈のあとの1文字の接尾（器/機、板/版、次/時）

`--ranker-config` で Ranker を1つずつ止めて、どの項が決めているかを確かめた。

| 文脈 + 読み | 1位（score / 経路のコスト） | 期待（score / 経路のコスト） | `left_context.weight=0` の1位 |
| --- | --- | --- | --- |
| 洗濯 + き | 器 -1192 / 4808 | 機 3453 / 5348 | 機 |
| 日本語 + ばん | 板 933 / 6933 | 版 3810 / 7251 | 版 |
| 午後三 + じ | 次 -4852 / 1148 | 時 -4665 / -910 | 時 |

- 決めているのは **LeftContextRanker**。器・板・次 は 接尾辞 なので、左文脈の名詞との連接（-4895 など）が増幅されて上限の -6000 が付く。機・版・時 は 名詞,普通名詞,助数詞可能 で、LeftContextRanker は名詞で始まる候補を増幅しない（同音異義語の名詞どうしを乱さないための設計。`core/src/ranker/left_context.rs`）。経路のコストだけなら、3 件とも期待の方が1位。
- 同じ働き（名詞に付く1文字の漢字）が、Sudachi の品詞の分け方で 接尾辞 と 名詞 に分かれていて、その違いだけで最大 6000 の差が付いている。辞書のポリシー（語ごとの加算）では、LeftContextRanker の差を打ち消すには 6500 以上の加算が要り、文脈のない入力でも同じだけ下がるので、ポリシーでは直さない（§5）。

## 3. 試して採らなかった規則

### 3.1 述語 `sahen_suffix`（接尾辞,名詞的,サ変可能 に加点。10 件）

EOS への連接の不利を打ち消す案。katakana-suffix の dev（103 / 115 が基準）:

| 値 | dev | 直ったもの | 悪化 |
| ---: | ---: | --- | --- |
| -1000 | 103 | なし | なし |
| -1500〜-2500 | 105 | 文字列化、自動 + か → 化 | なし |
| -2750〜-3250 | 106 | 上に加えて 構造化 | なし |
| -3500 | 106 | 同上 | ext dev 775（ext-kouka-1-05: こうか → 鋼化） |

評価セットでは良く見えるが、セットにない自然な入力で 1位が崩れる（CLI、文脈なし）:

| 入力 | 基準 | -1000 | -1500 | -2000 | -3000 |
| --- | --- | --- | --- | --- | --- |
| ほんとうか | 本当か | 本当か | 本当化 | 本当化 | 本当化 |
| むりか | 無理か | 無理か | 無理化 | 無理化 | 無理化 |
| だめか | 駄目か | 駄目化 | 駄目化 | 駄目化 | 駄目化 |
| かのうか | 可能か | 可能化 | 可能化 | 可能化 | 可能化 |
| きかいか | 機会か | 機会か | 機会化 | 機会化 | 機会化 |
| しんじつか | 真実か | 真実か | 真実化 | 真実化 | 真実化 |
| しか | 市か | 市か | 市化 | 市化 | 市化 |
| せいか、かいか、ねんか | 成果、開花、年か | 同じ | 同じ | 同じ | せい化、会化、年化 |

文字列化 が勝つ値では、必ず 本当化、無理化 も勝つ。か と 化 の区別は前の名詞の意味で決まり、品詞の規則では分けられないので**採らない**。評価セットに「名詞 + 終助詞 か」のケースがないことも分かった（§6）。

### 3.2 述語 `short_kana_adverb`（ひらがな2文字以下の副詞にペナルティ。374 件）

| 値 | katakana dev | ext dev | segments | 悪化（セット） |
| ---: | ---: | ---: | --- | --- |
| +1000〜+2000 | 103 | 777（きょうそう → 競争） | 143 → 144（seg-stretch-16） | なし |
| +3000〜+6000 | 104（掃除機） | 777 | 144 | なし |
| +8000 | 104 | 777 | 144 | hiragana 134（まず → 先ず） |

セットでは +6000 まで悪化がないが、自然な入力で崩れる（CLI、文脈なし）:

- +1000: すぐ → **す‐ぐ**、もうすぐ → もうす‐ぐ、すぐに → す‐ぐに（Sudachi の解析用の項目「す‐ぐ」。§6）
- +2000: よく → 良く、つい → 付い、どうも → 道も、こうかな → 高価な
- +3000: 上に加えて どう → 道、もし → 若し、どうかな → 道かな
- +5000: そうですね → 層ですね、そうかもしれない → 層かもしれない、どうしたの → 如何したの

副詞そのものは正しく安い語で、悪いのは「副詞の直後に名詞」という並びの方。語ごとの加算では並びを表せないので**採らない**（§5）。

## 4. 採った変更: `frequent_compound` の順位の上限を 3 万から 4 万にした

- 規則そのもの（名詞,普通名詞で、表記が lemma と同じ、漢字だけの3文字以上。chiVe の頻度が高い1語の項目に -8000）は変えていない。対象の順位の上限 `COMPOUND_MAX_RANK`（`dict-builder/src/policy.rs`）だけを変えた。3 万は phase3-compound で値を振らずに決めた数で、構造化（31404 位）、拡張性（33312 位）、規格外（30606 位）が漏れていた。
- 当たる行は 2480 → 3674 件（+1194。`dict-policy-report.md`）。増えた分の無作為の 60 件は、一本化、月刊誌、人材紹介、街路樹、再雇用、試運転、狭心症、情報化 など普通の複合語がほとんどで、魚の名の漢字表記（虎河豚、沖醤蝦）がいくつか混ざる。
- 上限の調整（katakana-suffix と ext の dev、segments は全件。値は -8000 のまま）:

| 上限 | katakana dev | ext dev | segments 完全一致 / F1 | 直ったもの（dev） | 悪化 |
| ---: | ---: | ---: | --- | --- | --- |
| 30000（基準） | 103 / 115 | 776 / 1004 | 143 / 0.989 | ― | ― |
| 35000 | 105 | 776 | 143 / 0.989 | 拡張性、構造化 | なし |
| **40000** | 105 | 776 | 143 / 0.989 | 拡張性、構造化 | なし |

  3.5 万〜5 万が同じ結果。平坦な範囲の手前寄りの 4 万にした（上限を上げるほど、まれな漢字表記の複合語が分割に勝つ）。
- 上限 4 万での `frequent_compound` の値の確認（dev）: -5000 で 104（構造化が届かない）、-6500 と -8000 で 105、-10000 で 106（拡張子名 も直る）。phase3-compound では -12000 から区切りの F1 が下がったので、崖に近い -10000 には動かさず、-8000 のままにした。

コードの設計の変更が要る案（このレーンでは実装していない）:

- **案 A: 左文脈の最後の語と候補が、辞書の1語になるなら加点する**（新しい Ranker か LeftContextRanker の拡張）。自動 + 化 = 自動化、洗濯 + 機 = 洗濯機、最新 + 版 = 最新版 はどれも辞書に1語の項目がある（器、家、板 の組はない）。文脈のケース 6 件のうち 3 件（ka-ctx-01、ki-ctx-01、k-han-01）に当たる。日本語版、三時 は項目がないので直らない。実装していないので、効果と副作用は未確認。
- **案 B: LeftContextRanker の名詞の除外を見直す**。試しに一時的にコードを変えて測った（コミットしていない）:
  - 接尾辞も増幅しない: katakana +4（ki-ctx-01、k-han-01、k-han2-01、k-ji-01）、-2（kata-teki-ctx-01 的 → 敵（test）、kata-sei-ctx-01 性 → せい（dev））。他のセットは変化なし。
  - 名詞,普通名詞,助数詞可能 も増幅する: katakana +1（k-ji-01）、ext dev -2（しゅうかん の 4 件が入れ替わる）。
  - どちらも悪化があるので、そのままでは採れない。接尾辞 と 助数詞可能 の名詞を同じ扱いにする形（たとえば両方を増幅し、上限を下げる）を調べる価値がある。
- **案 C: 副詞から名詞への連接を、変換では重くする**（ラティスの連接の補正。今のポリシーは語ごとの加算だけで、連接は変えられない）。§3.2 のとおり、語ごとのペナルティでは すぐ、どう、もし などが崩れる。

その他の発見:

- Sudachi に「す‐ぐ」（副詞、読み スグ、lemma 直ぐ、コスト 8467。表記の ‐ U+2010 は読みに対応しない）という解析用の項目があり、「すぐ」（8075）の 2 位に出る。基本原則 1.1（入力していない文字を足さない）に当たるので、`ExclusionRule` の対象にするかを検討してよい（ハイフン入りの行は 53 件で、多くは英字の固有名や語の表記。U+2010 をかなの間に挟む行に限る規則になる）。
- 評価セットに「名詞 + 終助詞 か」（本当か、無理か）と、副詞だけの入力（すぐ、どうも）のケースがない。§3 の規則はセットでは悪化が出なかった。セットに足すと、同じ型の規則を早く見分けられる。
