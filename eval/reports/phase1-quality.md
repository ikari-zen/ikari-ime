## 1. リードが見つけた問題の原因と修正

### 1.1 「今日はここまでと」+しよう、「要件をまとめてドキュメント化」+しよう の1位が「使用」

BOS の右ID は正しかった（「と」= 793。「ドキュメント化」は接尾辞の右ID）。連接も ADR の値どおりで、`と → しよう（意志推量形, 左ID 1820）` は -2794。**ADR §0.3 の比較が間違っていた**: 比べた相手は 仕様（普通名詞・一般, 左ID 5145, +1459）だったが、実際の競合は 使用（普通名詞・**サ変可能**, 左ID 5133）。

| 候補 | 単語コスト | BOS 連接（と →） | EOS 連接 | 合計 |
|---|---|---|---|---|
| 使用 | 4672 | -214 | -1334 | **3124** |
| しよう（意志推量形） | 7517 | -2794 | -96 | 4627 |
| 仕様 | 6587 | +1459 | -483 | 7563 |

- 連接が効いても、**単語コストの差 2845** と **EOS 連接の差（サ変名詞は文末に来やすい: -1334 対 -96）** が残る。Sudachi の単語コストは「その表記が解析で選ばれやすいか」を表す値で、同音異義語どうしを比べる値ではない。
- ポリシー（固有名詞、カタカナ、記号の加算）は、どちらにも当たらないので効かない。chiVe の頻度（為る 9 位、使用 134 位）も、どちらも「無料」の範囲で差が出ない。

**修正**: `LeftContextRanker`（`core/src/ranker/left_context.rs`）。左文脈の最後の語から候補の最初の語への連接コストのうち、絶対値が 1000 を超えた分を 4 倍に増幅する。左文脈は実際に書かれた語なので、文法の手がかりとして他の連接より信頼できる。増幅する範囲は dev で絞った（下の 2.1）:

- 名詞で始まらない候補だけ（名詞どうしの比較に適用すると、希少な名詞「聖核」「製革」が偶然有利になった）
- 1つの辞書の語でできた候補だけ（複数に分かれた候補に適用すると、拘束形の分割「き会」「来海」が上がった）

結果（既定の構成、CLI）: 「今日はここまでと」+しよう 1位 しよう / 「ドキュメント化」+しよう 1位 しよう。

### 1.2 「なった〜」「の〜」

出所は SudachiDict の表記ゆれ用のエントリ（`た〜`・`の〜` など、波ダッシュを含む表記が 347 行）。読みと正規化表記は `タ`/`た`、`ノ`/`の` で普通の語と同じなので、既存の述語（katakana_variant など）には当たらなかった。

**修正**: ポリシーに述語 `wave_dash`（2文字以上で 〜 ～ ~ を含む表記、+3000）を追加（`dict-builder/src/policy.rs`）。「〜」そのもの（助詞）は対象外。結果: 「やっと春に」+なった の候補に `なった〜` は出ない。

### 1.3 「敵の攻撃を受けて兵士は」+ひんし の 浜死 と 瀕死

`rare_lemma`（lemma が chiVe の語彙にない）では直らない。**浜死の lemma（Sudachi の正規化表記）が 瀕死 だから**（異体字の正規化）。lemma が同じ2つは、chiVe の頻度でも話題スコアでも差が付かず、同点になる（8864 対 8864 で、`rare_lemma` を入れても同点のまま）。

**修正**: 述語 `variant_surface`（活用しない語で、漢字を含む表記が lemma と違う、+1500）。同じ原因の `ひん死`、`き会`（機会）なども下がる。結果: 1位 瀕死、3位 浜死。

`rare_lemma` は2値なので、より dev の成績が良い段階式の `lemma_rank`（chiVe の頻度順位の桁数に比例）に置き換えた（下の 2.2）。
- 注: `rare_lemma` は docs/refactor-plan-2026-10.md（E5。ADR 0003 §3.3）で削除した。この表の再現は、削除の前のコミット 6a58b73 で行う。


### 1.4 その他（AJIMEE の失敗から見つかったもの）

- `numeric_surface` がローマ数字（`Ⅲ`、`ⅰ`）を数字として扱っていなかった。AJIMEE で `Ⅲネン九ガツⅩⅤ日` のような出力が出ていた。除外するようにした（46 行）。
- カタカナ判定に小書きのカタカナ拡張（U+31F0〜31FF。`ㇲもう`）がなかった。
- `katakana_variant` の +3000 では、`ココ`・`ムスコ`・`ワガママ` のように Sudachi が低いコストを付けたカタカナ書きに勝てなかった。dev で +5000 にした（2.3）。

## 5. 残る問題

- `h-08`（外部API + しよう → 仕様、プロファイル it）は 3 位。プロファイルの効果は dev では変化なし（`--profile-ab` で悪化 0）。
- `a-04`（かきすすめる → 書き進める）は、辞書にない複合動詞なので 2 位（書きすすめる）。ユーザー辞書で解決する設計。
- AJIMEE の主な失敗（LM なし）は、同音異義語の選択（成年市、返信ベルト）、カタカナ書きの低コストなエントリ（ココ、ヨコハマ）、数字の書式（`３年９月１５日` に対して `三年九月十五日`）。
- 数字の書式は NumberRewriter の範囲外（読みが数字のときの Rewriter）で、変換結果の正規化は未実装。
