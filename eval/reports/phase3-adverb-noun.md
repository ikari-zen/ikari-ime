# フェーズ3 副詞の直後の名詞（こう／そう／どう／もう + 名詞）のスパイク（ADR 0008）

- 実行日: 2026-10-13 / 基準は main f9ebf3a（辞書は `data/build/dict`。sha256 は `target/baseline/main-f9ebf3a` の snapshot と同じ）/ release ビルド / Linux のコンテナ（LM なし）
- スパイクのコードはコミットしていない（捨てるコード。§5 に中身を書く）。値は環境変数で切り替え、1つのバイナリで比べた

## 2. 評価の方法

- セット: homophones（cost / topic / full）、homophones-ext の dev と test（topic / full）、hiragana（topic）、katakana-suffix（topic / full。dev と test を含む）、segments（full、split=all）、シナリオ a-02 / a-03 / a-04、CLI golden（40 入力）。snapshot.sh と同じ構成で流し、ケース別の結果（`--out-cases` の列 1〜7）を基準と比べた。
- 値は dev の分割と、セットにない自然な入力（§3）で選んだ。test の分割は確かめにだけ使った。
- **自然な入力**: セットには副詞だけの入力や副詞 + 用言の入力がない（phase3-suffix §6）ので、174 の読みを別に用意して、文脈なしの1位を基準と比べた。内訳は、副詞だけ（すぐ、どうも、どう、もし、つい、よく、まず など）、副詞 + 用言（そうですね、そうかもしれない、そうする、こうなる、どうしよう、そう思う、もう帰る など）、副詞 + サ変名詞 + する（どう対処する、こう表現する、そう判断した など）、正しい副詞 + 名詞（もう一度、もう時間、まだ時間、ちょっと前、ずっと前、ほぼ全部、ちょうど今、ちゃんと確認、是非今度、もう深夜、もう午後、すぐ後ろ など）、こう／そう／どう／もう で始まる漢語（動物、公園、相談、申し込み、後半、毛布、総理大臣、同級生 など）。

- B 系（並びに一律に加算）は、掃除機を1位にするのに要る値（そう時期 と 掃除機 の差 2698 を超える値）で、正しい 副詞 + 名詞 や 副詞 + サ変名詞 + する が、別の分割（接頭辞、用言の連用形、記号の ℃、カタカナの名詞）に負ける。正しい並びの次点との差は 是非今度 1958、もう深夜 2435、もう午後 1168 しかない。**一律の加算で、直したい入力だけを動かす値の幅はない**。
- B1 のように表記（ひらがな）で副詞を絞ると、同じ副詞の漢字の表記（可成、丁度、一寸、先ず）が加算を受けずに1位に上がる。副詞の絞り込みは、表記ではなく品詞か読みで行う必要がある。
- C は、加算するのが「その2語を1語で読める、ふつうに使う名詞がある」ときだけなので、もう一度、是非今度、もう深夜、どう対処する のように1語で覆う名詞がない並びには何もしない。

## 4. 案 C の値の幅（dev と自然な入力。test は確かめだけ）

### 4.1 加算する値（覆う名詞のコストの上限 10000）

| 値 | セット | 自然な入力の変化 |
| ---: | --- | --- |
| +3000 | katakana 129 | 掃除機、後半、騒音、どうし（毛布 は直らない。もう府 11038 → 毛布 9244 の差が足りない） |
| +4000 | katakana 129 | 上に加えて 毛布 |
| +6000 | katakana 129 | 同上 |
| +8000、+12000、+20000 | katakana 129 | 同上（すべて同じ） |

+4000 から +20000 まで結果が変わらない。加算した 2 語の経路は候補から消えず、N-best の後ろに下がるだけ（そうじき の3位に そう時期 9254 が残る）。

### 4.2 覆う名詞のコストの上限（加算 +6000）

`cost + penalty`（辞書のポリシーを足した変換用のコスト）で比べる。

| 上限 | 名詞の辺だけ | 名詞の辺 + か の辺 |
| ---: | --- | --- |
| 8000 | 騒音、毛布 が直らない | 同左 |
| 9000 | 騒音、毛布 が直らない | 同左 |
| 9500、10000 | 掃除機、後半、騒音、毛布、どうし。崩れなし | 同左 + 硬化測定。崩れなし |
| 10500〜12000 | 同上。崩れなし | **そうかもしれない → 層かもしれない** |
| 14000 | 上に加えて こう増加 → 構造か | ― |
| 上限なし | 上に加えて **こう修正する → 高修正する**（光周性 11854、公衆性 11815 が「覆う名詞」になる） | ― |

- 上限は、Sudachi の解析用のコストと `lemma_rank`（chiVe の頻度）で決まる「ふつうに使う名詞か」の代わり。名詞の辺だけなら 9500〜12000 が同じ結果になる。か の辺も入れると 9500〜10000 しかない。
- 品詞2 を 普通名詞 に限る条件（固有名詞を除く）は、上限 10000 では結果が変わらなかった。

## 6. 直らないもの（この規則の範囲外）

- **こうかそくてい**: 副詞と名詞の間に か（副助詞）が入る。か の辺も入れると区切り（こうか|測定 → 硬化測定 の1文節）は直るが、1位は 効果測定 ではなく 硬化測定（13865 < 14203）。効果 と 硬化 の区別は話題か LM の仕事。
- **どうしよう → どう使用**: 「どうしよう」を1語で覆う名詞がない。B 系では直るが、その値で どう対処する が崩れる。
- **副詞 + 用言の連用形の誤った分割**（自然な入力で基準から誤っていたもの）: どう来、もう仕分けない、もう行っ海、ただ行っ海、なお行っそう、ずっと行っしょ、とても来れい、同省もない、そう来、どう買い、まだ見てい、また来襲。名詞ではなく、読みの短い動詞の連用形（行っ、来）が安いのが原因で、別の課題。
- **その他、副詞の絡まない誤り**: 府と窓、層等（そうとう）、何故今日、まだ御前。

## 7. 再現

スパイクの差分（コミットしていない）は、`core/src/lattice.rs` の `Node` に分類のフラグ（副詞、名詞、覆う名詞、副助詞 か）を足し、
`build_inner` で「開始位置ごとの、覆う名詞の終了位置」の表を作り、前向き Viterbi の辺（`lattice.rs`）と後ろ向き A* の辺（`nbest.rs`）に同じ関数で加算するもの。
値は環境変数（`IKARI_SPIKE_P`、`IKARI_SPIKE_KA`、`IKARI_SPIKE_ADV`、`IKARI_SPIKE_NOUN`、`IKARI_SPIKE_SPAN`、`IKARI_SPIKE_COVMAX`）で切り替えた。
B 系は `IKARI_SPIKE_SPAN=0`、案 C は `IKARI_SPIKE_SPAN=1 IKARI_SPIKE_ADV=all IKARI_SPIKE_NOUN=all IKARI_SPIKE_P=6000 IKARI_SPIKE_COVMAX=10000`。

```sh
cargo build --release -p ikari-cli -p ikari-eval
target/release/ikari --format tsv -n 5 そうじき          # 経路のコストと語の分割
target/release/ikari-eval --ranker full --set eval/sets/katakana-suffix.tsv --out-cases x.tsv
target/release/ikari-eval segments --ranker full --set eval/sets/segments.tsv --split all
```
