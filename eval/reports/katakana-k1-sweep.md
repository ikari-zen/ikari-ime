# ADR 0037 §7 の 3: K1 の掃引の結果（#100）

- 日付: 2026-10-29
- 対象: [ADR 0037](../../docs/adr/0037-unknown-katakana-cost.md) §6.2〜6.5、§11（K1 だけで掃引。格子は [katakana-s0](katakana-s0.md) §8）。main = 7aac7c9（K1 の契約 `katakana_like.base` と `katakana_like.per_char`、既定 0 / 0 で無効）
- 測るだけ。**既定値は決めていない。コードの既定も変えていない。** 本体（core / engine / macos）は触らず、`eval/scripts/` の捨てるスクリプトだけで測った
- 区分: 判断の根拠（凍結）。値を決めるのはユーザー

## 0. 要点

**分かったこと**

1. 格子 404 点（K1 の `base` 10 通り × `per_char` 10 通り（0 と 500〜2500 を 250 刻み）に 0 / 0 を足した 101 点を、`strong_bonus`（0、5000）× `weak_bonus`（0、2000）の 4 通りで）を、LM なしで測った。**「既存の全セット（dev）と AJIMEE と疑似の守る側で、1 位の悪化が 0 件」の点は、K1 が有効な点で 8 点だけ**（すべて `strong_bonus` 5000、`weak_bonus` 0。`base` 20000〜24000、`per_char` 2000〜2500 の格子の端）。`strong_bonus` 0 の点と `weak_bonus` 2000 の点は 0 点（悪化の最小は、`strong_bonus` 0・`weak_bonus` 0 が 14 件、0・2000 が 23 件、5000・2000 が 14 件。§2）。
2. 不採用でない 8 点が格子の端にあったので、格子の外を 56 点（`strong_bonus` 5000、`weak_bonus` 0。`base` 26000〜32000 と `per_char` 2750、3000）足した。悪化 0 の点がさらに 30 点出たが、1 位が増える数は端の内側より少ない（最大 24 件。§4）。
3. 悪化 0 の点の中で、疑似の主の群（dev 707 件）の 1 位が最大なのは **`base` 20000、`per_char` 2250 の 32 件（4.5%）**。katakana-like の狙う群（dev 14 件）の 1 位は 3 件のまま変わらない。**ばーじょにんぐ（文脈なし、文脈つき）はどちらも 32 位のまま**。
4. ばーじょにんぐ が 1 位になる点は 232 点ある（2 本とも 1 位は、悪化 14 件以上の点だけ。1 本でも 1 位になる点は悪化 9 件以上）。**悪化 0 の点には 1 つもない**。ADR §6.5 の「K1 をやめる条件」の括弧（ばーじょにんぐ の 2 本がどちらも 1 位にならない）には当たる。前半（狙う群の dev の 1 位が今より増えない）は、疑似では +32 件増えるので当たらない。**どちらを採るかはユーザーが決める**（§5）。
5. 不採用の理由は AJIMEE が最も多い（404 点のうち 372 点で悪化）。次が katakana-like（327 点。擬音語の ぷぷぷ など）、small-kana（262 点。めぇ → メェ）。AJIMEE の悪化は、文の読み全体をカタカナにした候補が 1 位に出る型（§3.2）。
6. **悪化がちょうど 1 件の点が 19 点ある**。うち 17 点は small-kana の めぇ → メェ（1 件）、2 点は AJIMEE の ajimee-810。例: `base` 10000、`per_char` 2500 は、疑似の主の dev で 131 件が 1 位になり、悪化は めぇ → メェ の 1 件だけ（ばーじょにんぐ は 6 位と 8 位。1 位にはならない）。
7. LM あり（疑似は dev から FNV-1a64 の小さい順 1000 件。主の群は 99 件）。悪化 0 の 8 点は、LM ありでも全セット（dev）・AJIMEE・疑似の悪化が 0 で、時間切れも 0。だが**主の群の 1 位は基準 34 件 → 36 件（+2 件）にしかならない**（LM なしでは +32 件）。ばーじょにんぐ は LM ありでは基準が 3 位で、悪化 0 の点でも 3 位のまま（§7）。
8. ノイズ（守る群の読み 6864 本）。`base` 20000、`per_char` 2250 は、1 位がカタカナ（origin=katakana）に変わった読みが 0、最初の 3 件にカタカナが新しく入った読みが 8（そのうち 6 は反復の読み。ぽよぽよ など。§6）。
9. test は、`base` 20000、`per_char` 2250 を 1 回だけ流した（LM なし）。全セット（test）、AJIMEE、疑似の守る側で悪化 0。疑似の主の test 193 件のうち 14 件が 1 位に（§8）。

**推測**（確かめていない）

- 悪化 0 の点がこれだけ弱い効きにとどまる理由は、K1 の上限 `base + per_char × 文字数` が文の長さに比例して大きくなる一方で、AJIMEE の長い文では一部の語の連なり（まれな語を含む）の経路が上限を超え、読み全体をカタカナにした候補が勝つため、と読める。AJIMEE の悪化の例（§3.2）はすべて、現在の 1 位が読み全体のカタカナだった。上限の形を変えれば（例: 長い読みでは効かせない）変わるかもしれないが、今回は形を変えていない。
- ばーじょにんぐ（7 文字）は辞書の最小コストが 24228、最大 + 1 が 31403（S0）。K1 の上限が最小を下回るには `base + per_char × 7` が約 24000 未満でなければならない。悪化 0 の点（格子の中の 8 点）では `base + per_char × 7` が 35750 以上で、最大 + 1 の 31403 を超えるので、ばーじょにんぐ には K1 の上限が効かない、と読める（S0 の数字からの計算。順位が 32 位のままなのは測った事実）。

## 1. 方法

- 環境: S0 の再現手順（[katakana-s0](katakana-s0.md) §10）で、leave-one-out の辞書・除外表・TSV を作り直した（除外 8698 組、CSV から外した行 8888、辞書は約 19 秒（辞書 10 秒、vectors 7 秒、検証 1 秒）。件数と辞書のファイルの大きさは S0 と同じ）。辞書とスクリプトの出力はすべてリポジトリの外。`data/raw` は読むだけ。辞書の出力先は `data/build/dict` でもユーザーデータでもない。
- 基準 = K1 無効（`base` 0、`per_char` 0）、`strong_bonus` 5000、`weak_bonus` 0（今の main の既定）。ranker-config なしの結果と、K1 無効の ranker-config の結果が全ケースで一致することを確かめた。
- 守る群（LM なしの段階 (a)）。基準で 1 位だったケースが、点で 1 位でなくなったら 1 件の悪化:
  - eval/sets の全 31 セット（`--split dev`。katakana-like の追加ケースを含む）。ふつうの辞書（`data/build/dict`）。
  - AJIMEE（200 件、`--set-format ajimee`）。
  - 疑似の守る側: leave-one-out の dev 6917 件のうち基準で 1 位のもの（絞った辞書）。
- 狙う群（段階 (b)）:
  - 疑似の主の群（S0 §2.1 の定義: homophone-left を除き、カタカナの候補があり、カタカナの順位が 1 位でないか期待の順位が 1 位でない。900 件、うち dev 707 件、test 193 件）。基準では 1 位が 0 件。
  - katakana-like の dev のうち、kind が カタカナ語(弱い) と カタカナ語(分割負け) のもの 14 件（基準 3 件が 1 位）。
  - 本物: kl-split-01（ばーじょにんぐ）、kl-split-02（「APIの」+ ばーじょにんぐ）。
- 段階 (c)（LM あり）: `--lm zenz-v3.2-small-Q5_K_M.gguf --lm-budget-ms 2000 --lm-deadline-ms 2000`（`lm-metal` のビルド。バイナリは別の target ディレクトリ）。時間切れが 0 になるまで最大 3 回流し直す（時間切れは全測定で 0）。疑似は dev から FNV-1a64(id + `ikari-katakana-s0-v1`) の小さい順 1000 件（主の群は 99 件）。他のセット・AJIMEE は dev 全件。測定中のマシンの load average は 6〜8（他の作業と同居）だったが、時間切れは出なかった。
- ノイズ: S0 の守る群の読み（`katakana_s0_cases.py` の guard.tsv。eval/sets 2964、Core の乱数抽出 3000、補助（ぐ で終わる、反復、長音を含む）各 300。計 6864 読み）を `ikari --ranker full --format tsv -n 3` で単独に変換。

## 4. 格子の外の追加（56 点）

不採用でない点が格子の端（`base` 18000〜24000、`per_char` 2000〜2500）にあったので、`strong_bonus` 5000、`weak_bonus` 0 で次を足した: `per_char` 1000〜3000（250 刻み）× `base` 26000〜32000（2000 刻み）、`per_char` 2750 と 3000 × `base` 6000〜24000。結果は §2 の表の `base` 26000 以上の行と `per_char` 2750 以上の列。

- 悪化 0 の点が 30 点増えた。1 位が増える数は、端の内側の 32 件（`base` 20000、`per_char` 2250）を超えない。外側の最大は 24 件（`base` 18000、`per_char` 2750）、次が 15 件（`base` 18000、`per_char` 3000）。
- 悪化 0 の点は、境目から外へ離れるほど 1 位の増加が減る。**最大は格子の中の 1 点で、格子の外に最大はない**。
- 悪化ちょうど 1 件の点で最大は `base` 8000、`per_char` 2750（134 件。めぇ → メェ の 1 件）。ばーじょにんぐ は 4 位と 6 位。

## 5. 選び方（§6.5）

| 順 | 基準 | 結果 |
| --- | --- | --- |
| 1 | 悪化 0（LM なし・LM あり、dev）の点 | 格子の内側 8 点。外の追加を含めて 38 点 |
| 2 | 狙う群 dev の 1 位が最大 | katakana-like dev は全点 3 件で同じ。疑似の主 dev は `base` 20000、`per_char` 2250 が 32 件で単独の最大 |
| 3 | ノイズ最小 | 2 で決まったので使わない（参考: 3 件に入る読みは 20000 / 2250 で 8、22000 / 2000 で 8、24000 / 2000 と 24000 / 2250 で 3。1 位が変わる読みは全点 0。§6） |
| 4 | `per_char` 最大 | 同上 |

- **採る候補の点（ユーザーに見せる値。既定には入れていない）: `base` 20000、`per_char` 2250、`strong_bonus` 5000、`weak_bonus` 0。** 数字は LM なしで疑似の主 dev 707 件のうち 32 件（4.5%）が 1 位になる。LM ありでは主の群 99 件のうち +2 件。
- **K1 をやめる条件（§6.5）の判断をユーザーに仰ぎたい。** 文言は「狙う群の dev の 1 位が今より増えない（ばーじょにんぐ の 2 本がどちらも 1 位にならない）とき」。
  - 括弧の側: 悪化 0 の点で ばーじょにんぐ の 2 本はどちらも 1 位にならない（32 位のまま）。**当たる**。
  - 前半の側: 疑似の主 dev は +32 件。katakana-like の dev は 3 → 3 件（増えない）。LM ありの疑似は +2 件。本物（ばーじょにんぐ）の改善はなく、ADR §6.1.1 の「疑似が改善しても本物が改善しない点は採らない」に当たる。
  - 私の読み: ADR §6.1.1 の最後の規則（疑似が改善しても本物が改善しない点は採らない）に従えば、**悪化 0 の点は採れない**。ただし疑似の +32 件（4.5%）は、本物の数が 2 本しかないことを考えると、判断を分ける材料。
- 悪化を 1 件まで許す（めぇ → メェ だけ。ユーザーが決める）なら、`base` 10000、`per_char` 2500 で疑似 +131 件。LM ありでは、さらに ぐふふ → グフフ（katakana-like の kl-guard-50）が悪化して合計 2 件になり、ばーじょにんぐ は 2 本とも 1 位になる（§7）。これは基準を変えることになるので、私は選ばない。

## 7. LM あり

悪化 0 の 8 点（`base` / `per_char`: 20000 / 2250、22000 / 2000、18000 / 2750、20000 / 2500、22000 / 2250、24000 / 2000、18000 / 3000、24000 / 2250）と、参考の 2 点。全セット（dev）・AJIMEE・疑似 1000 件（dev）。時間切れは全測定で 0（1 回目で 0）。

| 点 | 悪化（全セット・AJIMEE・疑似） | 主の群（99 件）で 1 位 | katakana-like dev で 1 位（14 件） | ばーじょにんぐ 順位（文脈なし／文脈つき） |
| --- | --- | --- | --- | --- |
| 基準（K1 無効） | — | 34 | 7 | 3 / 3 |

- LM ありでは、悪化 0 の 8 点がすべて同じ値になる（主 36、katakana-like 7）。LM が基準の時点で、主の群 99 件の 34 件を 1 位に上げている（S0 §6 のとおり、LM はカタカナを 3〜7 位に上げる）。K1 が上乗せするのは、LM が上げきれなかった 2 件。
- ばーじょにんぐ は LM ありでは基準が 3 位。悪化 0 の点では 3 位のまま。1 位にするには、悪化が 2 件（10000 / 2500）以上要る。
- 疑似 1000 件の主の群 99 件は小さいので、+2 件の誤差は大きい（推測）。ただし LM なしの +32 件（707 件中）との差は明らか。
- LM ありの test は流していない（§8）。

## 9. 迷った点と測れなかった点

- ADR の格子「計 90 点前後」は、`per_char` 500〜2500 の 9 通り × `base` 10 通りの 90 点。`per_char` 0（`base` だけの上限）は意味があるので足した（10 通り × 10）。0 / 0 を含めて 101 点。
- 「疑似の守る側」は、疑似の 6917 件（dev）のうち基準で 1 位のもの（絞った辞書）。ADR の文言では定義がなかったので、この意味で数えた。
- 疑似の LM あり 1000 件は、dev 6917 件から選んだ（全 8698 件ではない。調整は dev だけで行うため）。
- 段階 (c) の「最大 5〜8 点」は、悪化 0 の点の上位 8 点（外の追加 2 点を含む）に、参考の 2 点を足した。
- 文字数は読みの文字数（モーラ版は今回は入れていない）。K6 は足していない。
- `weak_bonus` は 0 と 2000 の 2 通りだけ（2000 前後の他の値は測っていない）。
- 測っていない: LM ありの test、`snapshot.sh --compare`、モーラ版、K6、悪化 0 の点のうち外の追加の LM あり。
