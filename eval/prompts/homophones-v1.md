# 同音異義語の評価ケースの生成プロンプト（homophones-v1）

`eval/sets/homophones-ext.tsv`（`source=llm-v1`）を作ったときの指示。ADR 0002 §15.2 の方針に従う。
生成は Claude（Opus）が行い、ユーザーが `eval/sets/REVIEW.md` の1割を確認する。

## 指示

あなたは日本語 IME の評価セットを作る。次の形式で、同音異義語のケースを作る。

- 入力: 読み（ひらがな）と、その読みの表記の候補（2〜4個）。
- 出力: 表記ごとに約10個の「左文脈」。左文脈は、確定済みの文章の末尾で、その直後にこの読みの語が続く位置で終わる。
  - 左文脈の末尾に、期待する表記（またはその一部）を入れない。
  - 期待する表記が、他の候補より自然になるようにする。ただし、手がかりが強い文脈ばかりにしない。
  - 長さを混ぜる: 短い（1〜2語）4、中くらい（1節）4、長い（2文）2。
  - 助詞や活用の途中で終わらず、読みの語（動詞は終止形）が自然に続く形にする。
  - 個人名、実在の組織、機密になりうる内容を入れない。
- 否定ケースと文法ケース: 文法で決まる箇所（`〜としよう`、`〜になった`、`〜にする`、`〜している`、`〜について` など）は、
  プロファイル（`it`）や話題の手がかりがあっても、文法どおりの表記が1位になるべきケースとして、各20件以上作る。

## 検証（機械的）

1. 期待値が候補に出ること: `ikari-eval reach --set eval/sets/homophones-ext.tsv --write`。
   `max_rank` 以内に出ないケースには tags に `unreachable` が付き、既定の評価から除かれる。
2. `split` は `FNV-1a64(id) % 5 == 0` なら `test`、それ以外は `dev`（`ikari_eval::split_of_id`）。調整は dev だけで行う。

## 人手の確認

- `eval/sets/REVIEW.md` は、全件からシード固定（`random.Random(20261011).sample(sorted(ids), n)`）で1割を抜き出した一覧。
- 左文脈が弱い（別の表記でも自然）、読みと期待の対応が違う、を見つけたら、`homophones-ext.tsv` の行を直すか消す（id は変えない）。

## 既知の限界

- 短い文脈には、手がかりが弱いものを意図して含めている。1位正解率の上限は 100% にならない。
- 文脈は LLM が書いたため、書き言葉の偏りがある。自分の文章の評価（ADR 0002 §11.4 の取り込みの評価用2割）で補う。
