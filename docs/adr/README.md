状態の語は `提案` / `承認` / `一部置き換え（ADR XXXX §n）` / `置き換え（ADR XXXX）` を使う。各 ADR の先頭の「状態」の行と同じ語にする
（`scripts/check.sh` が、索引と本文の先頭の語が一致しているかを確かめる）。決定がどの節にあるかは「決定の節」の列で探す。
現在の構成は [docs/architecture.md](../architecture.md) にまとめてある（ADR は日付つきの判断の記録）。

## ADR の書き方

### テンプレート

```markdown
# ADR-XXXX: [判断のタイトル]

## 状態

提案 / 承認 / 一部置き換え（ADR XXXX §n）/ 置き換え（ADR XXXX）

## コンテキスト

なぜこの判断が必要だったのか、背景と制約を説明します。

## 決定

何を選んだか、一文で言える形で述べます。

## 検討した案

- **案A**: ...（採用しなかった理由）
- **案B**: ...（採用しなかった理由）

## 結果

この判断によって何が変わったか、得られたもの・失ったものを説明します。

## 参考

- 関連するIssue：#XXX
- 参考資料へのリンク
```

### ガイドライン

- **コンテキスト**: 技術的な制約、ビジネス上の要件、パフォーマンス目標など、判断に至った背景を具体的に述べる
- **決定**: 結論は簡潔に。その判断を要件の文脈で実装するための具体的な指針は「結果」や「参考」に記す
- **検討した案**: 棄却した理由を記すことで、後から同じ議論を繰り返すのを避ける
- **結果**: 長期的な影響や、他の部分への波及効果に触れる
- **参考**: 決定に参考にした要件、他のADR、外部ドキュメントへのリンク
