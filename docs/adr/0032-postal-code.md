- 状態: 承認（2026-10-23。§13 の 3 つは推奨どおりにユーザーが決定）
- 日付: 2026-10-23
- 対象: issue #203（住所 ↔ 郵便番号）、#204（`て` / `テ` / `te` + 数字で〒つきの候補）。core の新しい Rewriter、`dict-builder` の `town`、`scripts/fetch-data.sh`、設定、殻の英語のモード（段階 3）

## 2. 辞書の行ではなく Rewriter にする理由
1. **郵便番号 → 住所は辞書では作れない**: 辞書の読みはかなだけ（`is_indexable`）。数字の読みは入らない。
2. **住所 → 郵便番号を辞書の行にすると、文の途中に混ざる**: 辞書の行はラティスの部品になるので、`ちよだくに…` のような文の途中の区切りに数字の候補が出うる。Rewriter は読み全体の完全一致だけで働く。
3. **基本原則との関係**: 郵便番号は読みの文字に対応しない。日付（`きょう` → 日付）と同じく「同じものの別の書き方への変換」として、読み全体が住所と一致したときだけ、辞書の候補の後ろに出す。補完ではない（足りない部分を推測しない）。辞書の候補の並びは変えない。
4. **オン・オフが簡単**: Rewriter を組に入れるかどうかで切れる。辞書を作り直さなくてよい。
- 却下: 辞書の行（1・2 の理由）。殻で作る（日本語のモードでは学習・文脈と同じ流れに乗らない。データの場所はエンジンが持つ。ADR 0027 §9.1 と同じ考え）。

## 3. 表（`postal.tsv`。契約）
- `town` に `--postal-csv <変換表>` と `--postal-out <ファイル>` を足す。変換表の各行を (lg_code, machiaza_id) で町字マスターに結び、§3.1 で通った大字・町名に畳み、その町名の連なり（都道府県つき、都道府県を省いた形、郡を省いた形）ごとに 1 行を書く。読みは `chain_lex.csv` と**同じ関数**で作る（小書きの直しを二重に持たない）。
- 1 行: `読み<TAB>住所の表記<TAB>郵便番号（7 桁の半角。複数は , 区切り、昇順）<TAB>形`（契約コミットで 4 列目を足した。`f` = いちばん省略のない形、`s` = 都道府県や郡を省いた形。形は `dict-format/src/postal.rs` が定義し、書く側と読む側が共有する）。郵便番号 → 住所の向きはエンジンが読み込むときに逆引きを作る。逆引きの住所は `f` の行だけ（いちばん省略のない形。表記が都道府県名で始まるかでは、郡だけを省いた形と区別できないため列にした）。
- 結べなかった行、町名に畳めなかった行（小字だけなど）は数えて `TownReport` に出す。
- エンジン: `core::postal::PostalTable`（読み → 郵便番号、郵便番号 → 住所。ハッシュ表）。場所は `emoji.tsv` と同じ `dict/`。なければ空の表で、Rewriter は何も出さない（エラーにしない）。データの監視で辞書と一緒に読み直す。
- 大きさ・読み込みの時間・メモリは実装のレーンで測る（目安は、辞書の読み込みと比べて目立たないこと。超えたら形を見直す）。測った値は §3.1。

### 3.1 データ側の決め（レーン D の実装。2026-10-23）
- **結び方**: 変換表の行は (lg_code, machiaza_id) で町字マスターに結び、マスターのその行の大字・町名（`oaza_cho`。丁目と小字は消える）に畳む。読みと表記は `chain_lex.csv` と同じ関数（`convert`、`chain_part`、小書きの直し）で作り、ひらがなにする。丁目だけが違う町字は同じ連なりになるので 1 つの町にまとめ、郵便番号は和集合（昇順）にする。町の位置は、まとめた町字のうち (lg_code, machiaza_id) がいちばん小さいもの。
- **小字の行**: マスターの区分が小字（3）など、辞書の連なりを作らない行も、その行の大字・町名に畳んで表に入れる。変換表の行の約 72%（49 万行）は小字の行で、これを除くと郵便番号の多くが落ちるため。辞書に連なりのない町（小字だけの大字。約 4,500 町）は、郵便番号 → 住所のために入るが、住所 → 郵便番号は辞書の候補が先に出ないことがある（読み全体の完全一致のときだけなので害はない）。
- **`dlt_date` がある行は使わない**（廃止された町字。50 行）。
- **machiaza_id が空の行（市区町村だけ。例: 札幌市中央区 = 0600000）**は、同じ lg_code の町から作る「都道府県 + 市区町村」の連なり（ADR 0030 §13）の郵便番号に使う。その市区町村の連なりは `f`（都道府県つき・郡つき）と、郡を省いた形の `s`。都道府県を省いた形は、辞書の連なりと同じく作らない。
- **`s` の衝突**: 別の町の `s` が同じ (読み, 表記) になるとき（4 件）は、最初の町の位置に 1 行だけ書き、郵便番号は和集合にする。別の行の `f` と同じになる `s` は書かない（0 件）。
- **畳めない行**: 表記に数字・括弧・異体字を含む町（`北１条西` など。辞書の連なりと同じ除外）、読みが空・使えない町、読みが表記に対応しない町は表に入れない。変換表の行の約 6.7%（45,661 行）。**限界**: 郵便番号 → 住所でも、これらの町の郵便番号は出ない。ABR の読みに全角の数字が入るので、読みを作る方法（数字の読み）を決めてからでないと入れられない。要れば別の ADR・issue で扱う。
- **結べなかった行**: マスターにない (lg_code, machiaza_id) は 1 行、郵便番号が 7 桁でない行は 0 行（2026-09-24 版）。`town` の出力（`TownReport`）に毎回出る。
- **測った値**（郵便番号データ版 2609、手元の町字マスター）: 256,305 行（`f` 109,438、`s` 146,867）、21.8MB、郵便番号 115,125 種。`PostalTable::load`（契約の最小実装）の読み込みは約 91ms（release、5 回とも 91〜99ms）、`by_reading` は 5µs、`by_code` は 1µs 未満。辞書のビルドに足す時間は約 4 秒。

## 4. 郵便番号の形（読みの受け方）
- 受ける形: 数字 7 桁、または 数字 3 桁 + 区切り 1 字 + 数字 4 桁。数字は半角・全角（混在も可）。区切りは `ー`、`-`、`－`、`‐`、`−`。これ以外（6 桁、8 桁、区切り 2 つ）は何もしない（途中の補完をしない）。
- 表にない郵便番号は何も出さない。
- 1 位は打ったまま（入力を正とする）。住所はその直後（`rewriter_anchor` の位置）。`PostalRewriter` は組の中で `NumberRewriter` より前に置き、住所が数字の書き換え（`1,000,001` など）より先に出るようにする。
- 住所 → 郵便番号で出す数字は半角だけ（全角は出さない）。

## 5. 1 つの郵便番号に複数の町（2.9%）、1 つの町に複数の郵便番号（0.7%）
- 郵便番号 → 住所: 町をすべて候補にする。順は町字マスターの (lg_code, machiaza_id) の順（市区町村ごとにまとまる）。候補ウィンドウは 9 件ずつ進む（ADR 0014）ので、件数で切らない。市区町村までの共通部分（`東京都千代田区`）を候補に足す案は、作らない（使うかが分からない。要れば後で）。
- 住所 → 郵便番号: その町の郵便番号をすべて、昇順に、形ごとに出す（2 つなら 4 候補）。どの丁目がどの番号かは見せない（丁目で分ける情報は畳むと消える。§10）。

## 6. 町名だけでは郵便番号を出さない（#203 の案）
- `ちよだ` は全国の複数の市区町村にある。どの市区町村かを決めるのは推測（補完）になる。全部出すと候補が増えすぎる（issue の条件）。
- 町名は普通の語と同音のことが多く（ADR 0030 §3）、普通の語の変換の候補の後ろに数字が並ぶ。
- 都道府県 + 市区町村 + 町名まで打てば出る（それが連なりの完全一致）。市区町村 + 町名（都道府県を省いた形）も出る。

## 7. データの取得と出典
- 被覆は変換表（92.5%）。マスターの `post_code`（13%）は足りない。
- `scripts/fetch-data.sh --only postal`（新）: 上の URL から zip を取り、sha256 を固定して確かめる（ABR と同じ書き方。更新で sha が変わったら、手で更新する）。置き場所は `data/raw/abr/`。
- `scripts/build-dict.sh`: 変換表があれば `town` に渡し、`postal.tsv` を作る。なければ作らない（郵便番号の機能だけが働かない）。
- `THIRD_PARTY_NOTICES.md`: 変換表を ABR の項に足す（出典、取得日、郵便番号データの版、加工したこと: 町名に畳み、読みを付けた）。PDL1.0 の扱いは ADR 0030 §6 と同じ。**再配布の可否は確かめていない**（ikari は表を配らず、各自が取る形なので、今の使い方では問題になりにくい、という推測）。

## 8. 〒つきの入力（#204）
- 読み（`normalize_key` 済み）が `て` + §4 の形のときだけ働く。`テ` はひらがなに直るので同じ。ローマ字の `te1000001` も読みは `て1000001`。
- 候補: 1 位 `〒100-0001`、2 位 `〒1000001`、そのあと住所。1 位にする理由: スイッチを入れた人が、`て` + 郵便番号という普通の文では出ない形を打っている（評価セット 3,010 行で、`て` の直後が数字の行は 0）。打ったままの `て1000001` は住所の後ろに残す。
- Rewriter の候補を 1 位に置く手段は今ない。`RewriteCandidate` に位置（既定 = 今の位置 / 先頭）を足す（契約の変更。足すだけ）。
- 表にない郵便番号でも、形が §4 に合えば `〒` つきの 2 候補は出す（郵便番号の表が古いだけのことがある）。住所は出ない。
- `て` だけで〒を出すことはしない。`ゆうびん` → 〒 はそのまま（issue の推奨どおり）。`て` は助詞で、候補の列に記号を足すと邪魔になる。

## 9. 英語のモード（段階 3。スパイクのあと）
- 英語のモードは打鍵を素通しにする。郵便番号の候補を出すには、数字（`postal.english`）または `te`（`postal.te_prefix`）を、語の頭でためる必要がある（ADR 0027 のショートコードの `:` と同じ例外。B51 と同じく下線なし）。形から外れたキーが来たら、ためた分をそのまま確定してキーを渡す（打ち直し）。
- 候補を出すきっかけは、郵便番号の形がそろった状態での Tab または ↓（ショートコードと同じ）。候補は 1 そのままの入力、2 住所（`te` のときは 〒つきの 2 つが先）。Space・Enter・そのほかは打ち直し。
- 表の受け方: **(b) 郵便番号がそろった時点で、1 回だけ非同期に問い合わせる**（新しい `PostalLookupRequest { code }` → 住所のリスト）。返事が来たときに状態が同じなら候補に使う。間に合わなければ「そのままの入力」と〒つきだけを出す。
  - 却下 (a) 表を殻に丸ごと送る: 11 万件（住所の文字列で数 MB の見込み。未計測）を入力のセッションごとに受け取り、版の管理が殻とエンジンに分かれる。問い合わせは 1 打鍵に 1 回ではなく、郵便番号ごとに 1 回なので、非同期で足りる。
- 実機で確かめること（スパイク S1）: 語の頭の数字・`t` をためたとき、TextEdit、ブラウザ、Slack、表計算のセルで、見た目と打ち直しが崩れないか。非同期の返事を候補ウィンドウに出せるか。`te` をためると英語の語の頭（the、to）の多くで一瞬ためることになるので、遅れと見た目を確かめる。
- 除外アプリは `emoji.shortcode_exclude` と同じ考えで、ターミナルなどを既定で外す（キーは実装で決める）。

## 10. やらないこと・限界
- 丁目・番地ごとの郵便番号の見分け（大口の事業所の個別番号を含む）。変換表にない町（7.5%）。
- 郵便番号の途中（6 桁まで）での候補（補完になる）。
- 日本郵便のデータは使わない（2026-10-22 ユーザー決定）。

## 12. 懸念
- 学習: Rewriter の候補を選んだときの学習が、書式 ID（`format`）で読みをまたいで効くなら、ある住所で郵便番号を選ぶと、ほかの住所でも郵便番号が上がるおそれがある。レーン C で学習の鍵を確かめ、読みごとに効くことをテストで押さえる。
- 変換表と町字マスターの版のずれ（取得日が違う）。結べない行の数を毎回出して見る。
- 変換表の配布 URL は ArcGIS の項目で、置き場所が変わるかもしれない。

## 13. ユーザー決定（2026-10-23。3 つとも推奨どおり）
- **Q1. 郵便番号の 2 つの形の順**: issue #203 の例は `1000001` → `100-0001`、#204 の例は `〒100-0001` → `〒1000001`。推奨: **そのとおり分ける**（〒なしはフォームに入れる用途が多くハイフンなしを先に。〒つきは書いた住所の用途でハイフンありを先に）。
- **Q2. 町名だけでの郵便番号（#203 の案）**: 推奨: **出さない**（§6）。都道府県か市区町村から打てば出る。
- **Q3. 英語のモードの進め方**: 推奨: **日本語（#203、#204）を先に入れ、英語は語の頭の数字・`te` をためるスパイクのあとで決める**。候補を出すキーは Tab・↓（Space・Enter では出さない）。
