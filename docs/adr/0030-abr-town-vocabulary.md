## 0. 現状の把握（測った事実）

### 0.1 ABR の町字マスター（2026-10-22 に取得した版）
- `https://data.address-br.digital.go.jp/mt_town/mt_town_all.csv.zip`（zip 11,549,848 バイト、展開後 155,958,613 バイト。認証なし。UTF-8。この版は BOM なし。ヘッダ付き 38 列、727,522 行）。
  sha256: zip `d613bb1c…6a0e`、csv `c3e2ad32…0522`。版番号はなく、配布元が日付で更新する。
- 町字区分（`machiaza_type`）: 1 = 大字・町 106,510 行、2 = 丁目 94,512 行、3 = 小字 526,399 行、4 = 町名なし 70 行、5 = 通り名などの別名 31 行。使うのは 1 と 2（ユーザー決定。小字と京都の通り名は入れない）。
- 読み（`oaza_cho_kana`）は全角カタカナ。数字は全角（`北１条西` / `キタ１ジョウニシ`）。引用符を含む行は 0（単純に `,` で分けられる）。
- 丁目は、`oaza_cho` に町名、`chome` に `１丁目`（`東１１条北` などには `一丁目`）が別の列で入っている。町名だけを取れば、丁目の行から大字・町名が取れる。

### 0.2 Sudachi がすでに持っているもの
- SudachiDict（small + core + notcore）は、郵便番号の住所から作られた地名を大量に持つ。`名詞,固有名詞,地名,一般` だけで、辞書に入る行（左 ID が -1 でないもの）が 58 万行。千代田区千代田 などの住所は 1 語として入っている（`とうきょうとちよだくちよだ` は 1 位が 東京都千代田区千代田、`おおさかふおおさかしきたくうめだ` は 大阪府大阪市北区梅田。どちらも現行の辞書で変わらない）。
- したがって ABR で増えるのは、Sudachi にない町名（地方の町名、東京や大阪の町名の一部）だけ。
- 丁目は辞書の 丁目（名詞,助数詞可能）と数詞で作れる。`あさひがおかにちょうめ` は 旭ヶ丘二丁目、`あさひがおか2ちょうめ` は 旭ヶ丘2丁目（どちらも現行の辞書で出る）。町名が辞書にありさえすれば、`一丁目` と `1丁目` の両方が既存の仕組みで出る。

## 3. 変換の規則（`dict-builder/src/town.rs`）
### 3.1 規則（順に適用。理由は `TownReport` に出る）
| 規則 | 理由 | 行数（ABR の行。重複を数える） |
| --- | --- | ---: |
| `machiaza_type` が 1・2 でない行は使わない | 小字・通り名は入れない（ユーザー決定） | 526,500 |
| `status_flg` = 3 の行は使わない | 意味が未確認 | 1 |
| 読みが空 | 読みなしでは辞書にできない | 1,882 |
| 表記に使えない文字がある（英字、括弧、中黒、私用領域・拡張漢字・異体字選択子、﨑 U+FA11 など）。**全角の数字は半角にそろえて通す（§15。2026-11-10 に改めた）** | 入力できない字を出さないため。数字入りの町名（`北１条西`）は、元は読みに数字が入り辞書の読みにできないので除いていたが、§15 で入れる（単語の行にはせず、住所の連なりと郵便番号の表だけ） | 17,324（元。§15 で 108 に減った） |
| 読みにカタカナ・長音以外がある | `－`（全角ハイフン）などは辞書の読みにできない | 774 |
| 先頭の `大字` / `字` を外す（読みの `オオアザ` / `アザ` も外す）。読みに対応する接頭辞がなければ捨てる | 「大字」「字」は入力しない | 254（捨てた分） |
| `大字〇〇字△△` のように字が残る複合 | 住所の一部であって町名ではない | 1,158 |
| 表記が 1 文字 | 普通の語と同音になりやすい（北、西、乙） | 2,734 |
| 漢字を 1 字も含まない（かな・カタカナだけ） | かなだけの町名は、読みと同じ字を足すだけで役に立たない | 598 |
| 読みに 丁目 の読みがあり、表記に 丁目 がない（`エダヒガシイッチョウメ` に `荏田東`） | 入力にない 丁目 を落として変換する語になる | 91 |
| 表記が 町 で終わるのに、読みが チョウ・マチ で終わらない（`大幸町` / `ダイコウ`）。村 も同様（ムラ・ソン） | **読みにない「町」を足す変換になる**（基本原則: 入力にない文字を足さない） | 503 |
| 同じ（読み、表記）は 1 つ | 都道府県をまたいで同じ町名が多い | 91,976 |
| Sudachi に同じ（読み、表記）がある（小書きの違いを揃えて比べる） | 重複させない | 60,503 |
| 同じ読みに固有名詞以外の語がある、読みが 2 文字以下（notcore の d2s。ビルドの中） | 普通の語の読みを横取りしない（ADR 0002 決定 10、ADR 0012 §3.5） | 1,419（語） |

- **直す規則**: 町で終わる表記の読みの `チヨウ`（小書きにしていない）を `チョウ` にする（750 行）。他の位置の大書きは直さない（`チヨダ` の `ヨ` は正しい）ので、`相生町官有地無番地` のような途中の誤りは残る（入力されない読みなので害は少ない）。CJK 互換漢字（塚、渚、隆、琢の 4 字）は統合漢字に直す（NFKC と同じ。依存を足さないため、この 4 字の表）。
- **NFKC**: ABR の NFKC の対象は全角の数字・英字・記号が大半。NFKC の全体は入れない。全角の数字だけは半角にそろえる（§15。元は、辞書の読みにできないので表記から外していた）。英字・記号は今も外す。
- 括弧書き（大字 55 行ほど）は、表記に括弧が残るので捨てる（読みには括弧書きが含まれない）。
- 出力は 23,223 行の `town_lex.csv`（Sudachi 形式の 19 列。分割情報は `*`）。`ikari-dict-builder town --csv … --lex … --out …`。単体テストあり（9 件）。

### 3.2 丁目のエントリを作らない理由
- 町名の語（旭ヶ丘）を足すだけで、`あさひがおかにちょうめ` → 旭ヶ丘二丁目、`あさひがおか2ちょうめ` → 旭ヶ丘2丁目 が出る（辞書の 丁目 と数詞）。評価セット `abr-towns.tsv` の丁目 3 件（上祖師谷三丁目、羽田旭町1丁目、円山西町二丁目）は、町名を足す前は 1 位が別の語、足したあとは 1 位。
- 丁目つきの語を作ると 94,512 行に近い数が増え（辞書の行数が約 +3%）、一丁目/1丁目/１丁目 の読みと表記の組合せを持つことになる。得られるものがないので作らない。

## 4. 品詞とコスト
- 品詞: `名詞,固有名詞,地名,一般`。ID は Sudachi の同じ品詞の行で最頻の組（左 4792、右 4791）を `town` が読んで決める（固定の数値を持たない）。
- ポリシー: 既存の `proper_noun`（+1000）、`place_name`（-750）で合計 +250（ADR 0002 §4.1.1）。町名は chiVe にないので `lemma_rank` が乗る（notcore の固有名詞は `lemma_rank` を免除されない。ADR 0012 §2.5）。
- コストの掃引: ABR の語を別の辞書に分けず、`town --cost` を変えて辞書を作り直した。測るもの:
  - **wide**: 足した町名 23,223 件を、読みだけで入力したときの 1 位（足す前は 2,527 件）。**大きいほど有用**。

  - **phr**（横取り）: 普通の名詞（Sudachi の普通名詞でコストが小さく読みが 2〜5 文字のもの 46,252 語）から作った 11,000 件の連なり（A+B、AのB、AとB、Aをする、AのBです、A+B+C）の 1 位が、足す前から変わった件数。町名が普通の語の連なりを横取りした数の目安（実際の文章ではない。連なりの多くは意味のない並び）。

## 5. 重複・Sudachi にある組
- 同じ（読み、表記）は 1 つにする。読みが違えば別の語（`中町` の `ナカマチ` と `ナカチョウ`）。
- Sudachi（small + core + notcore。辞書に入る行だけ）に同じ表記と読みがあれば足さない。比べるときは、読みを平仮名にして拗音・促音の小書きを揃える（ABR は小書きにしていない読みがあるため）。
- 辞書のビルド（`dedup`）も同じ（読み、表記、左右 ID、品詞）の行を 1 つにする。

## 6. 出典の表記（PDL1.0）
- ライセンスは公共データ利用規約（第1.0版）。出典の記載と、編集・加工したことおよびその主体の記載が要る。国の未加工のデータに見せてはいけない。ユーザー決定で受け入れる。
- 置き場所: `THIRD_PARTY_NOTICES.md` に節を足した。ビルド（`macos/scripts/build.sh`）が設定アプリの Resources にこのファイルを入れ、「このソフトについて」に表示される（NFR-43。既存の仕組み。Swift は変えない）。`scripts/fetch-data.sh` の表の注にも書いた。
- 文言: 「アドレス・ベース・レジストリ 町字マスター」（デジタル庁）（URL）をもとに ikari-ime が加工して作成。加工の内容は §3.1。
- 町字マスターそのものは同梱しない。辞書（`system.dict`）は `scripts/install-data.sh` が利用者の `~/Library/Application Support/ikari-ime/dict/` に置く（アプリのバンドルには含めない）。再配布の可否は、規約に商用・再配布を禁じる文言がないことまでを確かめた（条文の法的な判断はしていない）。

## 12. 住所の連なりの完全一致（#202 第 1 段階。2026-10-23）

### 12.2 読みの小書き（ユーザー決定: 小書きに直した形だけを登録する）
- ABR の読みは拗音を大書きにしていることがある（`キヨウト`、`チユウオウ`、`カブキチヨウ`）。町の `チヨウ` だけ直していた規則（§3.1）を、読みの全体に一般化した。
- **規則の決め方（実測）**: 町字マスターの大字・町名で、Sudachi に同じ表記があり、読みが小書きの違いを除いて同じものが 55,064 組ある。その ABR の大書きの `ヤ`・`ユ`・`ヨ`・`ツ` のうち、Sudachi が小書きにしているものを、前後の字ごとに数えた。ABR が大書きで Sudachi が小書きなのは 558 字（`ヨ` 468、`ユ` 44、`ツ` 40、`ヤ` 6）。
  - **`イ段の字 + ヨ + ウ/ー` → `ョ`**（イ段の字は キ・シ・ジ・チ・ヒ・ビ・ミ・リ）: 小書き 464、大書きが正しい 5（99.0%）。`ジョウ` 41/41、`チョウ` 372/373、`ショウ` 20/20。イ段の字のうち ギ・ニ は例が少なく（0/2、0/1）直さない。
  - **`キ・チ・リ + ユ + ウ/ー` → `ュ`**: 小書き 27、大書きが正しい 2（93%）。`ジユウ`（自由ヶ丘）は大書きが正しい例が半分（12/18）、`シユウ` も 6/8 なので直さない。
  - 直さない: `ヨ` のあとが `ウ`・`ー` でないもの（`チヨダ`（千代田）、`キヨミズ`）、`ツ`（大書きが正しいものが 5,116 と多数。小書きは 40）、`ヤ`（6）。
  - 直る数は 約 490 / 558（88%）。直らない `ツ` は `ロツポンギ` のような読みが残る（打てない読みの行が残るだけで、害は小さい。`ろっぽんぎ` の行は別にある）。
- 失敗しても害は小さい（直し損ねた行は一致せずに今までどおり。直しすぎた行は、その読みを打っても一致しない）ので、規則は保守的にした。単語の町名の `readings fixed` は 750 → 1,725 行になった。

### 12.3 Sudachi の Core にある住所を置き換える理由
- Sudachi は郵便番号の住所を Core の地名として持つ。**連なりの 90%（202,199 / 224,617 表記）は、すでに Core にある**。ところがコストが高く（最小 2,708、中央値 20,657、最大 32,767）、1 位に出ない。連なりの読みを打った 1 位の一致率は **82.2%**（全件 224,083 の読み。LM なし）で、このうち Sudachi にない 22,418 件だけを足しても上がらない。
- 重複除去は「同じなら Core を残す」（ADR 0012）ので、notcore として同じ行を足しても、**コストの低い行は捨てられる**。実際、最初に notcore の入力だけで掃引したところ、コスト 3000〜13000 で 1 位が 92% 前後で変わらなかった（Core の行が残るため）。→ 連なりだけは、同じ行の Core に勝つ入力にした。
- ID が違えば別の行として残るので、Core の ID と違う行は元から足せていた。置き換えは、同じ ID の行（約 70%）で効く。

失敗の型（公開の地名の例。ABR にある町名だけを使った。個人の住所に当たるものは挙げない）:
1. **数字 + ばん → 版**（LM なし。例: `ふくおかけんおかがきまちまつがだい5ちょうめ6ばん2ごう` → 福岡県岡垣町松ケ台5丁目6**版**2号）。ADR 0019 §13.3 の「三 + ばん（板 → 版。番は 2 位）」と同じ根。`番`（8618）と `版`（7533）はどちらも `名詞,普通名詞,助数詞可能` で同じ bonus を受け、コストの差で 版 が勝つ。`番地` は一般の名詞なので bonus がなく、`5版地` に負ける。**LM ありでは 95〜97% に戻る**。
2. **数詞の読み + ばんち**: `ごばんち` → 御番地、`きゅうばんち` → 旧番地、`さんばんち` → サンバンチ、`いちばんち` → 1番地（期待が 一番地 なら不一致。表記は算用数字でよいかの確認が要る）。数詞か接頭辞かは、住所の文脈でないと決まらない。
3. **市区町村だけの連なりがない**（連なりは町名まで）: 町名の前で止まる入力で、都道府県が崩れる（`ぎふけんまつしたちょうにいく` → **ギフ**県松下町に行く、`ならけんならしにいく` → **なら県なら市**に行く、`おきなわけんなはしにいく` → 沖縄県**な橋**に行く、`ぐんまけんのべちょうにいく` → 群馬県延べ庁に行く）。第 1 段階の連なりは町名まで読んだときにしか効かない。→ §13.2 で直した。
4. **町名だけ（都道府県・市区町村なし）の同音**: `はいがわ` → はい側（早川）、`ひきだ` → 曳きだ（引田）。続きがなくても同じ（f0 61% = 続きあり 57〜63%）。**続きのせいではなく**、連なりでない町名と普通の語の競合なので、第 2 段階の対象外（#203、#204 の領域）。
5. **続きによる崩れ**: 市区町村だけ + 続き（型 3 の続き）と、町名だけ + 続き（続きなしで 1 位だったもの 184 件のうち、`にあるびる` で 20 件、`までいく` で 6 件が崩れる。`南九リヤマニアルビル` のように、読みの切り方が変わる）。連なりが町名まで揃ったものは、続きでも前でも崩れなかった（99〜100%）。

→ 元の問題（区のあとの町名が文の分割に負けて出ない）は、**町名まで揃った連なりでは起きない**（99〜100%）。起きるのは、連なりが途中で終わる（型 3）か、連なりでない町名だけ（型 4・5）のとき。

### 13.5 数詞 + 番 / 番地（型 1・2）を LM なしでも直す（ユーザー指示 2026-10-23。実装済み）

#### 方針（2 案の比較）
- 案 (a) **数詞 → 番 / 番地 の辺を軽くする lattice 規則**（ADR 0019 §15 の `numeral_counter` の延長）を採用。(b) 辞書のポリシーで `番` を安くする案は、`ばん` 全体（晩・板・版・番）と通常の文に波及し、辞書の作り直しが要るので採らない。
- 既存の `numeral_counter.bonus` は 助数詞可能の名詞（番 8618、版 7533）の両方を同じだけ軽くするので、差（1085）は埋まらない。`番地`（5159）は一般の名詞でそもそも対象外で、`5版地` に負ける。
- そこで、辞書のノードを作るときに**（読み, 表記）が `ADDRESS_COUNTER_SURFACES`（`ばん` + `番`、`ばんち` + `番地`）のものに `Node::address_counter` を立て**、数詞 → そのノードの辺から引く（ラティスの辺は表記を持たないため）。負の値の補正なので、前向き・後ろ向きが同じ関数を使い A* のヒューリスティックは正確なまま。
- 2 つの値（`--ranker-config`）: `lattice.numeral_counter.address_bonus`（前が読みの中の数字: `2ばん`、`5ばんち`。既定 4000）、`lattice.numeral_counter.address_kana_bonus`（前がかな読みから作った辞書の数詞: `さんばん`、`ごばんち`。既定 6000）。0 でそれぞれ止まる。かな読みの数詞は ADR 0019 §15 で「もういちど → もう一℃」を防ぐために除いていたので、**番 / 番地にだけ**当てる。
- 丁目・号・階・条は、足さなくても通る（`3ちょうめ`、`1ごう`、`2じょう` → 畳|条、`3かい` → 階|回）ので表に入れない。入れると 号 → 2号社 のような別の失敗は直らず、条|畳 は両方正解のまま。

## 15. 数字を含む町名（#5。2026-11-10）
- 状態: 実装済み（PR で確認）。**判断の置き場所: Rust**（`dict-builder` の `town`・`numeral`、`dict-format` の読みの契約、`core` の辞書と郵便番号の引き）。Swift には足していない。
- 対象: `北1条西`、`新野9線`、`桔梗が丘1番町1街区` など、表記に算用数字を含む大字・町名。§3.1 の「全角の数字を含む表記は使わない」を改める。

### 15.1 ユーザー決定（2026-11-10）
1. 読みは**両方**打てる: (A) 数字を読みにした形 `きたいちじょうにし`、(B) 数字を含む形 `きた1じょうにし`。
2. 全角の数字の読み（`きた１じょう`）も同じに扱う。
3. (A) の読みのゆれ（4 = よん/し、7 = なな/しち、9 = きゅう/く、促音 = いっちょうめ/いっせん など）は全部入れる。10 以上は数詞の規則どおり（じゅうに、にじゅう）。
4. 変換候補に、**半角の数字と全角の数字の両方**の表記が出る（`北1条西` と `北１条西`）。半角が先（公用文の既定）。
5. 表記は算用数字。`北一条西` は作らない。

### 15.2 決めたこと（実装で確かめて選んだ点）
| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 入れる先 | **住所の連なり（`chain_lex.csv`）と郵便番号の表（`postal.tsv`）だけ**。単語の行（`town_lex.csv`）には入れない | #5 の範囲。単語にすると、普通の語との同音の絞り込み（d2s）と Sudachi との重複の扱いを数字入りの読みで増やすことになる。頼まれていない |
| 表記 | 表の表記は半角の数字。連なりは半角に加えて全角の数字の行も書く。**全角はコストを 1 高く**（`FULLWIDTH_SURFACE_COST_DELTA`） | 同じ読みの 2 行が同点にならず、半角が先に出る。1 は同点を割るだけの値で、順位を作る大きさではない（掃引はしていない）。実測では、半角が 1 位、全角が 2 位に出る（§15.3 の評価セット） |
| 全角の数字の読み | **引くときに半角にそろえる**（`ikari_dict_format::reading::fold_fullwidth_digits`。ラティスの辞書の引き、`PostalTable::by_reading`）。全角の読みの行は持たない | 行を持つと読みが 3 通りになり、連なりの行がさらに約 +3.4 万行（今回の +6.8 万行の半分）。`normalize_key` に入れる案は、ほかの入力（全角の数字の未知語、数字の書式）の見た目を変えるので却下。ラティスの位置は 1 文字を 1 文字に替えるので変わらない |
| 数字の読みの作り方 | ABR の読みに数字がある町（約 75%。`キタ１０ジョウニシ`）は、数字の連なりを数詞の読みに置き換える。読みが数詞のもの（約 25%。`ニシカグラニセンヨンゴウ`、`ジユウイツセン`）は、表記の数と助数詞（条・線・番・号・区・街・地・字・基・丁目）から読みの中の位置を探し（小書きの違いは無視）、数詞の部分だけを置き換える。探せない行（39 行）は使わない | 読みの数字と表記の数字が一致する保証がない。位置を探せるときだけ作る（推測で読みを作らない） |
| 数詞の読みの規則表 | **コードに既存の規則表はなかった**ので、`dict-builder/src/numeral.rs` に純粋な関数で作った（1〜9999。数詞は辞書の Sudachi の行にあるが、数字 → かなの規則は持っていなかった）。辞書や評価の別の場所と共有する表はない | 調査で確認 |
| ゆれ | 4 = よん/し、9 = きゅう/く は一の位と十の位。7 = なな/しち は全部の位。百・千の位の 4、9 はよん・きゅうだけ。促音は、数詞のあとの読みが か・さ・た・ぱ行のとき、**促音の形（いっ・はっ・ろっ・じゅっ・ひゃっ）を先に、促音にしない形（いち・はち・ろく・じゅう・ひゃく）もあとに入れる**。`じっ`（10）は作らない。600、800 は ろっぴゃく/ろくひゃく、はっぴゃく/はちひゃく。1000 は せん/いっせん | ユーザー決定の「全部入れる」。百・千の位の 4、9 のゆれ（しひゃく、くせん）は日常の読みでないので入れない |
| 大きい数 | 10000 以上、先頭が 0 の数は使わない | 町名の最大は 240 |
| 読みの契約（索引） | **連なりの読みだけ、半角の数字（0-9）を辞書の索引に入れる**（`reading::is_indexable_with_digits`。`encode_dict` と検証はこれで通す）。Sudachi・notcore・ウェブ語彙の読みと、利用者の辞書の読みは、これまでの `is_indexable`（かなだけ）のまま（`lex.rs` の規則 5 で `adding_priority` のときだけ切り替える） | 数字を含む読みを辞書に入れる唯一の方法。ほかの行（Sudachi の `エービー1` のような読み）に数字の読みが入ると、今の辞書が変わる。`lex.rs` の単体テスト（`unindexable_readings_are_skipped`）で、数字を含む読みが連なり以外では捨てられることを確認 |
| `postal.tsv` | `f` の行は数字を読みにした形の 1 行（半角の表記）。ゆれの読みと数字を含む読みは `s` の行（郵便番号 → 住所は `f` の 1 行だけ）。全角の表記は入れない | 郵便番号 → 住所の候補が重複しない。`s` は「読み → 郵便番号にだけ使う」行で、意味が合う |

### 15.4 影響と限界
- **住所 → 郵便番号の順位が 1 つ後ろになる**: 数字を含む町は、辞書の候補が 半角の表記、全角の表記の 2 つになるので、郵便番号は 3 位から（ほかの町は 2 位から。postal-040〜 の within-3 / within-4）。全角の表記を候補に出す決定（15.1 の 4）の結果。
- 郵便番号 → 住所は、数字を含む町の表記が半角の数字で出る（`北海道札幌市中央区北1条西`）。
- 読みが 32 文字を超える連なり（郡つきの長い町名）は、これまでと同じく辞書に入らない（`postal.tsv` にはある）。
- 数字を含む町名の単独の語（`北1条西` だけ）は辞書の単語にしていないので、町名だけを打つ変換は今までどおり（連なりの読みで打ったときだけ出る）。
- ABR の数字の読みを使えない行（読みの数詞の位置が助数詞から見つからない 39 行）と、英字を含む町名（`Ｂ`）は入れない。
