# ADR 0010: 本動詞の漢字の加点を、同じ形の候補の中の表記の選択に限る（副詞＋用言の誤った分割）

- 状態: 承認（2026-10-14。§10.1 を参照）
- 日付: 2026-10-14
- 対象: core の KanaStyleRanker（`core/src/ranker/kana_style.rs`）の規則 `aux_verb` のうち、本動詞の漢字への加点（`aux_kanji_bonus`）だけ。ラティス、辞書、ほかの Ranker、表（`core/assets/kana_style.tsv`）は変えない
- 前提: main = f4fce68（B13、B14 を含む）。ADR 0002 §22（表記の既定、KanaStyleRanker）、ADR 0008 §7-4（この問題の最初の記録）。
  タスクは docs/tasks.md の B15。測定はこの ADR の §5（スパイクは捨てたコード。§9 に再現の手順）
- 関係: B18（同音の動詞の表記の選び方。ADR 0009 を準備中）とは規則が重ならない（§4）

---

## 0. 現状の把握

### 0.1 現象と、測った原因
文脈なし、LM なし、`--ranker full`。「スコア」は Ranker のあとの値、「経路」は辞書と連接のコスト（`--format tsv` の3列目と4列目）。

| 入力 | 1位（スコア / 経路） | 期待（スコア = 経路） | `--ranker cost` の1位 | 差の出どころ |
| --- | --- | --- | --- | --- |
| もういっかい | もう**行っ**海（9281 / 12781） | もう一階 9785、もう一回 11064 | もう一階 | 行っ に -3500 |
| とてもきれい | とても**来**れい（11025 / 14525） | とてもきれい 11762 | とてもきれい | 来 に -3500 |
| どうき | どう**来**（4829 / 8329） | 同期 7207 | 同期 | 来 に -3500 |
| もうしわけない | もう仕分けない（8674 / 8674） | 申し訳ない 12956 | もう仕分けない | 加点なし（経路のコスト。§0.3） |

- 前の3件は、**経路のコストでは正しい候補が勝っている**（`--ranker cost` で1位）。誤りの候補だけ、スコアが経路より **3500** 小さい。
- 3500 は KanaStyleRanker の `aux_kanji_bonus`（既定 3500）。`kana_style.tsv` の `aux_verb` に載る動詞（行く、来る、見る、置く、下さる、頂く など 15 語）の**漢字の表記**が、直前が「て／で」でない位置に現れると、その候補に加点する（ADR 0002 §22。「本動詞は漢字」）。
  副詞（もう、とても、どう）は `Before::Other` に分類されるので、副詞の直後の 行っ、来 が加点を受ける。
- `--ranker-config` で `kana_style.aux_kanji_bonus=0` にすると、3件とも期待が1位になる（もう一階、とてもきれい、同期）。

**ADR 0008 §7-4 の見立て（「読みの短い動詞の連用形が安い」）は、この3件については誤り**だった。連用形のノードは確かに安い（行っ 5122、来 7514。Sudachi の値）が、それだけでは負けている。決め手は、表記を選ぶための加点が、**区切りの違う候補どうしの比較**にまで効いていることだった。

### 0.2 加点の性質（コードの事実）
- `KanaStyleRanker::aux_bonus` は、候補の**すべての語**について、表に載る lemma の漢字の表記なら 3500 を足す（1候補あたりの上限 `max_total` 6000）。モジュールの説明には「最初の語だけを見る」とあるが、コードはすべての語を見ている（説明とコードが食い違っている。§8 で直す）。
- 活用形も、その語が候補の中で意味のある形か（行っ + 海、来 + れい）も見ない。だから、読みの一部を 行っ、来、置き、見 で切り出した候補が、加点のぶんだけ上がる。
- 加点が本来したいことは「同じ語を、ひらがなでなく漢字で書く」（いく → 行く、みる → 見る、おく → 置く）の選択で、区切りの選択ではない。

### 0.3 この ADR の原因に当たらない例
同じ「副詞 + 用言」の見た目でも、次は加点が原因ではない（`aux_kanji_bonus=0` でも変わらない）。

| 入力 | 1位 | 期待 | 原因 |
| --- | --- | --- | --- |
| もうしわけない | もう仕分けない | 申し訳ない | 経路のコスト。仕分け（未然形, 右ID 1101）→ ない（助動詞, 左ID 325）の連接が **-11968** で、もう仕分けない（Sudachi の素の値で 6525）が 申し訳 + ない（12055）より大幅に安い。申し訳ない を1語にした項目は Core の辞書にない |
| またらいしゅう | また来襲 | また来週 | 名詞どうしの同音の選択（来襲 6518、来週 8419） |
| どうかい | どう買い | 同会 / どうかい | 経路のコスト（期待そのものが確認待ち。adverbs.tsv） |
| どうしょうもない | 同省もない | どうしようもない | 口語の読み。副詞が絡まない |
| まだみてい | まだ見てい | まだ未定 | どちらも自然な読み |

- これらは LM（zenz-v3.2 small）が締め切りに間に合えば、まだみてい と どうしょうもない を除いて直る（§0.4）。規則で直す形ではないので、この ADR では扱わない（§6、§10-4）。

### 0.4 LM の効き方
`eval/sets/adverbs.tsv`（174 件）を LM ありで流した（モデルは `~/Library/Application Support/ikari-ime/models/zenz-v3.2-small-Q5_K_M.gguf` を読むだけ）。

| 構成 | 1位 | LM の時間切れ |
| --- | ---: | ---: |
| LM なし | 147 | ― |
| LM あり、締め切り 2000ms（snapshot と同じ） | 168 | 0 |
| LM あり、既定の締め切り（エンジンと同じ。`max(30ms, 6ms×読みの文字数)`、上限 300ms） | 167〜168 | 4〜14 |

- LM が間に合えば、もう行っ海、とても来れい、どう来、もう仕分けない は直る。
- 間に合わないとき（時間切れ、先行計算のない Convert、区切り直し。ADR 0008 §8 案 F）は、規則の順位がそのまま出る。既定の締め切りで流すと、時間切れのケースに ほぼ行っしょ、まだ行っ海、とても来けん、すごく来れい が残った（§5.3）。
- LM は最初のプールの並べ替えだけで、プールには規則が決めた候補が入る（ADR 0003）。**表記の規則が区切りを壊している状態は、LM の前に規則の側で直す**（ADR 0008 §8 案 F と同じ考え）。

### 0.5 加点を消すだけでは直せない
`aux_kanji_bonus` の値を振った（LM なし）。

| 値 | hiragana（140） | adverbs（174） | homophones-ext dev（1004） |
| ---: | ---: | ---: | ---: |
| 3500（今） | **135** | 147 | 778 |
| 3000 | 134 | 148 | 778 |
| 2500 | 134 | 150 | 778 |
| 2000 | 133 | 150 | 778 |
| 1500 | 131 | 151 | 778 |
| 1000 | 131 | 152 | 778 |
| 500 | 129 | 152 | 778 |
| 0 | 129 | 152 | 778 |

- 0 にすると、hiragana の 見る、行く、置く、物を置く が ひらがな（みる、いく、おく）に戻る（6 件が1位から落ちる）。adverbs を直すには 1000 以下が要り、hiragana を守るには 3500 が要る。**値の幅はない**。
- 加点は「同じ語の表記」の比較では必要で、「区切りの違う候補」との比較では有害。効く範囲を分ける必要がある。

### 0.6 実機の報告: 「下記」が か来 になる（2026-10-14）
ユーザーが「それと今「下記」ではなく」と打とうとして、かき が 書き になった。CLI（LM なし、空の学習）で、文脈が 「、今「、それと今「、今、 のどれでも、かき の1位は **か来**（か: 助詞,副助詞 + 来: 動詞,非自立可能,カ行変格,連用形-一般）。文脈なしなら 下記、かきのように なら 下記のように。

| 文脈 | 1位（スコア / 経路） | 2位 | 下記 の順位 |
| --- | --- | --- | ---: |
| それと今「 | か来（7931 / 11431） | 書き（7932 / 7990） | 11 |
| 「 | か来 | 書き | 5 |
| なし | 下記（7297） | 書き（7640） | 1 |

ikari-eval で Ranker を段ごとに足して（`--ranker cost / analyzer / doc / topic / full`）、どこで崩れるかを見た（文脈 それと今「）。

| 段 | 1位 | 下記 の順位 | 起きていること |
| --- | --- | ---: | --- |
| cost（文脈なしの BOS） | 下記 | 1 | ― |
| analyzer（左文脈の最後の語を BOS に） | 書き | 3 | 「 や 、 のあとは、名詞より動詞の連用形への連接が安い（書き 7990、下記 8901） |
| doc（LeftContext と **KanaStyle** を足す） | **か来** | 5 | か来 の経路 11431 に本動詞の漢字の加点 -3500。どう来、とても来れい と**同じ原因** |
| topic、full | か来 | 11 | GrammarGuard が か来 を「文法の候補」（助詞 + 非自立の動詞。`is_particle_plus_auxiliary`）とみなし、それより上に来た 書き、下記 の内容語の加点（話題）を、か来 のすぐ下まで戻す（書き 7932 = か来 7931 + 1） |

- リードの見立て（「非自立の 来 の連用形が安すぎて、1文字の助詞のあとにぶら下がる」）のうち、**根は どう来、とても来れい と同じ**で正しい。ただし決め手は連用形のコストではなく、本動詞の漢字の加点（§0.1）。経路のコストでは か来（11431）は 書き（7990）、下記（8901）よりずっと高い。
- さらに、加点で1位になった か来 を GrammarGuard が「文法の候補」として守るので、ほかの候補への話題の加点が打ち消され、下記 が 11 位まで落ちる。加点の漏れが、Guard を通して増幅されている。
- 同じ型: 今、 のあとの はき → は来、がき → が来、もき → も来（すべて -3500）。
- LM: 既定の締め切りでは、2文字の読みの締め切りは 30ms（`max(30ms, 6ms×2)`）で、評価では 6 回中 6 回が時間切れだった（先行計算のない Convert の再現。エンジンは先行計算が済んでいれば最大 300ms 待つ。ADR 0004）。**短い読みほど LM が間に合わず、規則の順位がそのまま出る**。締め切り 2000ms なら LM は 書き を1位にした（下記 は 2〜6 位）。
- §2.1 の規則（G）では、か来 は消え（か来 の組の最良は加点の前の値 11431 のままで、書き、下記 より下になる）、4つの文脈すべてで 1位 書き、2位 下記 になった（は来 → は気、が来 → ガキ、も来 → も木）。
- **書き と 下記 の選択は、この ADR では直らない**。analyzer の段ですでに 書き が上で、原因は「「 のあとは動詞の連用形が安い」という連接（同音の選択）。直すなら LM が間に合うこと（先行計算）か、話題、学習（下記 を一度選べば、同じ文脈で上がる）。§10-8 で聞く。

## 1. 決定の要約

| 項目 | 決定 |
| --- | --- |
| 規則 | 本動詞の漢字の加点（`aux_kanji_bonus`）は、**同じ形の候補の組の中だけ**で順位と差を変え、**組の最良のスコアは変えない** |
| 同じ形 | 辞書由来の候補で、語の数が同じで、各語の**読み**と**品詞1**（動詞、名詞、助動詞 など）が順に一致するもの。例: 行った・いった・言った は同じ形、もう行っ海 と もう一階 は違う形 |
| 組の中の扱い | 今と同じ加点を組の中で足したあと、組全体を一律にずらして、組の最良のスコアを加点の前の値に戻す（§2.1） |
| 変えないもの | ほかの規則（`phrase`、`formal_noun`、て／で のあとの補助動詞のひらがな）、表、値（3500）、ほかの Ranker、ラティス |
| 置き場所 | KanaStyleRanker の中だけ。Ranker の並び（LeftContext → KanaStyle → …）も変えない |
| 値 | 新しい値は持たない（§10-3） |

## 2. 規則

### 2.1 定義
KanaStyleRanker の `rank` で、候補ごとに加点を2つに分ける。

- `a` = 本動詞の漢字の加点（表の `aux_verb` の lemma の漢字の表記で、直前が「て／で」でない語ごとに `aux_kanji_bonus`。今と同じ条件）
- `r` = それ以外の加点（`phrase`、`formal_noun`、て／で のあとの補助動詞）。今どおり `min(r, max_total)` を足す

`r` を足したあと、候補を「同じ形」の組に分ける。

- 組のキー: 候補の語の列 `[(読み, 品詞1), …]`。品詞1 は `grammar.pos_name(pos_id)` の最初の欄。
- 組に入るのは `CandidateOrigin::Dictionary` の候補だけ。Rewriter の候補、ひらがな・カタカナのフォールバックの候補は組に入らず、`a` も受けない（§6-6）。

組ごとに、次のようにする（スコアは小さいほど上位）。

| 値 | 定義 |
| --- | --- |
| `best` | 組の中の最小のスコア（`a` を足す前） |
| `best_adj` | 組の中の `score - a` の最小（今の規則で加点したときの最良） |
| `shift` | `best - best_adj`（0 以上） |
| 新しいスコア | 組の全員について `score - a + shift` |

- 組の中の順位と差は、今の規則（`score - a`）とまったく同じになる。
- 組の最良のスコアは `best` のまま。**ほかの形の候補との比較は、加点がないときと同じ**になる。
- 組が1件だけ（漢字の候補しかない、など）なら、`a` を足さない。加点はほかの形の候補を追い越すためには使えない。

### 2.2 なぜこの形か
- **加点の意味に合わせる**: `aux_kanji_bonus` は「本動詞は漢字」という**表記**の規則（ADR 0002 §22）で、区切りを選ぶ根拠を持たない。区切りは辞書と連接（ラティス）、左文脈（LeftContext）、LM が決める。表記の規則が区切りを決めないようにするのが、原因（§0.2）に対する直接の直し方になる。
- **キーを 品詞1 にする（lemma でも pos_id でもない）**: スパイクで3通り測った（§7 の案 D、E、F）。
  - lemma をキーにすると、おく（lemma おく）と 置く（lemma 置く）が別の組になり、hiragana の 置く が2件落ちた（Sudachi は ひらがなの項目に別の lemma を持つことがある）。
  - pos_id をキーにすると、行った（動詞,非自立可能,…）と 言った（動詞,一般,…）が別の組になり、今は加点で 行った が勝っている よく行った、もう行った、すぐ行って、ちょっと行ってくる が 言った に替わった。
  - 品詞1 なら、行った・いった・言った が同じ組で、今と同じく 行った が勝つ。もう行っ海（副詞・動詞・接尾辞）と もう一階（副詞・名詞・名詞）は別の組になる。
- **組を一律にずらす（並べ替えだけにしない）**: 組の中のスコアを入れ替えるだけ（案 F）だと、LM なしでは同じ結果だが、**LM ありで 下さい が ください に負けた**（hiragana の hira-kan-08、09）。入れ替えでは 下さい と ください の差が元の小さな差に戻り、LM の点で逆転する。ずらす形なら、組の中の差は今と同じ（3500 を含む）で、LM と混ぜたときの表記の選択も今と同じになる。
- **Ranker の中で閉じる**: ラティスの規則（ADR 0008 の形）にすると、`--ranker cost` ではもともと正しい（§0.1）ものを、別の層で打ち消すことになる。原因の加点がある場所で直す。

## 3. 置き場所

- `core/src/ranker/kana_style.rs` の `KanaStyleRanker` だけ。`aux_bonus` の「本動詞は漢字」の分岐を、候補ごとの `a` として別に返すようにし、`rank` で §2.1 の組の処理をする。
- 組のキーは、候補ごとに1回だけ作る（`(読み, 品詞1)` の列。品詞1 は `pos_id` ごとに引いた結果を使い回せる）。プールは数十件なので、組分けは件数の2乗でも足りるが、キーのハッシュで分けてもよい（本実装で決める）。
- `Ranker` トレイト、`Candidate`、CompositeRanker、Guard は変えない。KanaStyleRanker は Guard の追跡の対象外（`CONTENT_RANKERS`、`GRAMMAR_RANKER` でない）なので、Guard の計算にも影響しない。
- ラティス（ADR 0008 の `edge_extra`）、N-best、文節（ADR 0006）は変えない。文節ごとの候補も Ranker を通るので、同じ規則が効く。

## 4. B18（同音の動詞の表記の選び方）との関係

- B18（すすめられる → 薦／勧／進、なおった → 治／直、かこう → 書こう）は、**同じ形の中で、どの漢字の動詞を選ぶか**の問題。B15 は、**表記の加点が形の選択に漏れている**問題。
- この ADR の規則は、表の `aux_verb` の 15 語（経つ、下さる、頂く、見る、置く、おく、仕舞う、行く、来る、上げる、呉れる、貰う、欲しい、戴く、差し上げる）の漢字の加点だけを変える。B18 の例の動詞（勧める、薦める、進める、治る、直る、書く）は表になく、加点を受けない。
  スパイクで、すすめられる、なおった、かこう の上位3件は、この規則の前後で同じだった（1位は 薦められる、治った、加工）。
- **干渉しないための約束**（B18 の ADR 0009 と合わせて決める）:
  1. B15 は `kana_style.rs` の `aux_kanji_bonus` の効く範囲だけを変える。表（`kana_style.tsv`）の `aux_verb` の語は増やしも減らしもしない。
  2. B18 が「同じ読みの動詞のどの漢字を選ぶか」を規則で扱うなら、その加点も**同じ形の組の中だけ**で効かせるのが、この ADR と同じ考え（表記の規則は区切りを選ばない）。B18 が KanaStyleRanker に足すなら、§2.1 の組の処理を共通にできる。別の Ranker にするなら、同じ考えを ADR 0009 に書く。
  3. どちらが先にマージされても、後の側が adverbs.tsv、adverb-verbs.tsv（§5.2）、hiragana.tsv と B18 の評価セットを両方入れた状態で取り直す。

## 6. 失敗のしかた（既知の限界）

1. **同じ形の中では、今と同じく加点で別の動詞が勝つ**: まだおきてる は 置き・て・る（置く）と 起き・て・る（起きる）が同じ形（動詞・助詞・動詞）で、置く の加点が組の中で勝つ（まだ置きてる）。行った と 言った を同じ組にした（§2.2）ことの裏返しで、今の振る舞いと同じ。
2. **LM と混ぜたときに、加点で守られていた語が負けることがある**: またいこう は、今は 行こう に 3500 が付いて、LM が また以降 を推しても勝っていた。G では 以降（別の形）との比較が加点なしになるので、LM の点で また以降 になった（締め切り 2000ms で 50 件中 1 件）。表記の規則が LM の判断を覆していたものが、なくなった形。
3. **もうしわけない は直らない**（§0.3）。経路のコストで もう仕分けない が 4000 以上安い。LM が間に合えば 申し訳ない になる。直すなら辞書の側（1語の 申し訳ない、または Full 辞書。docs/tasks.md A3-3）か、ユーザー辞書で、別のタスク（B17 と同じ扱い）。
4. **同音の選択は直らない**: 一回／一階、一個／一湖、気／木、味方／見方、来週／来襲。区切りが直ったあとの、話題か LM の仕事。
5. **形式名詞の漢字の加点（`formal_kanji_bonus`）にも同じ漏れがある**が、この ADR では変えない: ものごと → 物後と（物 に 3500）。同じ組の処理を `formal_kanji_bonus` にも広げると（§7 の案 H）、ものごと は直るが、hiragana の 物が足りない が 物語ない に落ちた（物 の加点が、物語 との区切りの比較で要る）。形式名詞の規則は、区切りをまたぐ比較（とき と と気）を意図して作られている（ADR 0002 §22、user-feedback.md §1.4）。
   （追記 2026-10-15: この漏れは ADR 0017（案 P。次が助詞のときだけ区切りをまたぎ、ほかは同じ形の組の中だけ）で直した。）
6. **ひらがなのフォールバックの候補は組に入らない**: スパイクでは組に入れなかった。読み全体のひらがなの候補（`CandidateOrigin::Hiragana`）と、辞書の 行く の候補は別の組になる。評価では差が出なかったが、語の列を持つなら組に入れるかを本実装で決める。
7. **品詞1 の粒度**: 動詞と動詞は、活用の種類が違っても同じ組になる（行く と 言う、置く と 起きる）。組を細かくする（品詞2 まで、活用形まで）と、ひらがなの項目と漢字の項目の品詞が違うとき（非自立可能 と 一般）に組が割れる（案 E）。品詞1 で測った結果を採る。

## 8. 結果

- 得るもの: 表記の加点が、区切りの選択に漏れなくなる。副詞や1文字の助詞のあとに 行っ・来・置き・見 を切り出す誤り（もう行っ海、とても来れい、どう来、か来 など）が、LM が間に合わないときにも出なくなる。本動詞の漢字（もう行く、また来て）、て のあとのひらがな（持っていく）、行った と 言った の今の選び方は変わらない。
- 失うもの: KanaStyleRanker の加点が、候補ごとの独立した足し算ではなくなる（同じ形の組を見る）。`--format tsv` のスコアを手で分解するときは、組のずらしも数える。
- 波及:
  - KanaStyleRanker のモジュールの説明（「最初の語だけを見る」）を、コードに合わせて直す（すべての語を見ている）。
  - GrammarGuard は、加点で上がった「助詞 + 非自立の動詞」の候補を守る（§0.6）。G で加点が漏れなくなれば、この増幅も起きない。Guard 自体は変えない（§7 の案 L）。
  - B18 の表記の規則も同じ考えに揃えるかを、ADR 0009 で決める（§4）。

## 9. 実装の進め方

規模が小さい（`kana_style.rs` とそのテスト、評価セット、snapshot）ので、レーンを分けずに1つの code-editor で行う。

1. テストを先に足す（`kana_style.rs` の単体テスト。小さな辞書で）: 同じ形の組の中では今と同じ順と差になる（いく と 行く、くる と 来る）。組の最良のスコアは加点の前と同じ（行っ海 が 一階 を、か来 が 書き を追い越さない）。組が1件なら加点しない。行った と 言った は同じ組。て のあとの補助動詞のひらがな、`phrase`、`formal_noun` は変わらない。
2. 実装（§2.1、§3）。モジュールの説明を直す。
3. 評価: `eval/sets/adverb-verbs.tsv` をユーザーの確認（§10-5）のあとに確定し、`eval/scripts/snapshot.sh` に足す。snapshot（基準 main）との差が §5.1 のケースだけであること。LM ありの snapshot（締め切り 2000ms）で hiragana が 135 を割らないこと。`scripts/check.sh --real --perf`。

## 10. ユーザーの判断が要る点

1. **原因の見立ての訂正**: B15 の4例のうち3例（もう行っ海、とても来れい、どう来）と、実機の報告の か来（§0.6）の原因は、動詞の連用形の安さではなく、表記の規則（本動詞の漢字への 3500 の加点）が区切りの選択に効いていたことだった（§0.1）。この理解でよいか。**推奨: この理解で進める**（ADR 0008 §7-4 には、この ADR への参照を足す）。
2. **規則の形**: 本動詞の漢字の加点を「同じ形（各語の読みと品詞1 が同じ）の候補の組の中だけ」に限り、組の最良のスコアは変えない（§2.1。案 G）でよいか。**推奨: この形で入れる**。
   - 副作用として受け入れるもの: またいこう が LM ありで また以降 になる（§6-2）。まだおきてる は直らない（§6-1）。
3. **評価のための切り替えのキー**: `kana_style.aux_kanji_scope = shape | global`（既定 shape）を `--ranker-config` に置くか。**推奨: 置かない**（今の振る舞いと比べるときは main のバイナリを使えばよい。使われない柔軟性を増やさない）。
4. **もうしわけない（§0.3、§6-3）**: この ADR の範囲外とし、LM に任せる（間に合わないときは ユーザー辞書に 申し訳ない を足すのが早い）。**推奨: 範囲外にする**。docs/tasks.md の B17（辞書にない複合語）に「申し訳ない（1語の項目がない）」を足すかを決めてほしい。
5. **評価セットの下書き**（`eval/sets/adverb-verbs.tsv`、56 件）: 期待の表記を確認してほしい（`eval/sets/REVIEW.md` の ADR 0010 の節）。特に、よくいった・もういった・すぐいって（行った と 言った の両方を正解にした）、ぜひ／是非、まだいっかい（一回 と 一階 の両方）、ずっとみかた（味方）、文脈つきの かき（下記 だけを正解にした）。**推奨: 確認のあとに snapshot に足す**。
6. **形式名詞の漢字の加点の漏れ（§6-5。ものごと → 物後と）**: 同じ組の処理を広げると 物が足りない が崩れるので、この ADR には含めない。別のタスクとして docs/tasks.md の B に積むか。**推奨: 積む**（形式名詞の規則は区切りをまたぐ比較を意図しているので、別の条件が要る）。
7. **どこで見た誤りか**: B15 の最初の4例は ADR 0008 のスパイク（LM のないコンテナ）で見つかったもの。かき は実機の報告。実機では、短い読みほど LM が締め切りに間に合わない（§0.6）。ほかの例も実機で見ているか。見ていれば、この ADR の優先度が上がる。
8. **「下記」の残り（§0.6）**: G のあとも、「 や 、 のあとの かき は 1位 書き、2位 下記 になる（連接による同音の選択）。この ADR では直さず、学習（一度 下記 を選ぶ）と LM に任せるか、別のタスクにするか。**推奨: この ADR では直さない**。括弧のあとの名詞と動詞の連接を補正するのは、ほかの入力への影響を測ってからにする。
