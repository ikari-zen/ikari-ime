# ADR 0054: 格助詞「の」の直後の「件」だけを安くする（連接表に「件」専用の左 ID を足す）

- 状態: 採用（2026-11-06 ユーザー決定。案 B（連接コスト）。§の「ユーザーに聞くこと」3 点はすべて推奨どおり: 「〜の県」が LM なしで 2 位に下がるのを受け入れる、連体詞は掃引だけで既定は入れない、目標は LM なしで 1 位）
- 日付: 2026-11-06
- 対象: `dict-builder`（新しいモジュール `connection.rs`、`lib.rs` の組み立ての順、`matrix.rs` の列の追加、`policy/default.tsv` の値の 1 行、`--policy-report` の出力）、`eval/sets/issue210.tsv`（足す）。`dict-format`（grammar.bin の形式）、`core`（ラティス、N-best、Ranker、文脈の解析）、LM、shell-core、Swift は変えない
- 前提: main = 128aa1b。辞書は SudachiDict Core 20260723（`data/raw/sudachi-20260723/`）。ADR 0001 §3.3（grammar.bin）、ADR 0002 §4（辞書のポリシー）、ADR 0008（ラティスの辺の補正。§8 の案 B5 と案 D）、ADR 0048（プールの大きさ）
- タスク: #210（「〜の件」が「〜の県」になる）
- ユーザーの決定（2026-11-06）: **連接コストで直す（案 B）**。単語コストの補正だけでは 1 位にできないことが計算で分かったため（§0.2）
- 判断の置き場所: Rust の `dict-builder`（辞書を作るときに連接表を補正する）。実行時のコードは変えない。OS の API も UI も関わらない

### 0.2 単語コストだけでは直らない（計算）
- 「けん」単独: 県 447 + 1822 − 522 = 1747、件 1146 + 8262 + 244 = 9652。差 **7905**。
- 「きのうのけん」: 「昨日の県」と「昨日の件」の差 **8252** = 単語 6440 + の→ 1046 + →EOS 766。
- 件の単語コストを Δ 下げるとき、「昨日の件」を 1 位にするには Δ > 8252、「けん」単独で県を 1 位に保つには Δ < 7905。**両方を満たす Δ はない**。差の 347 は「BOS → 件」と「の → 件」の連接の差（1046 − 699）。
- 単語単位の述語（`dict-builder/src/policy.rs`）は直前の語を見られないので、ここは連接で扱う。

### 0.3 基準（main、LM なし、`--ranker cost`）
きのうのけん 31 位、かいぎのけん 34 位、ごれんらくのけん 圏外、せんじつのけん 15 位、あのけんは 20 位、このけんについて 圏外。

### 0.4 コードの現状（設計に効く事実）
- 変換のラティス（`core/src/lattice.rs`）、N-best（`core/src/nbest.rs`）、文脈の解析（`core/src/analysis/`）は、どれも `grammar.connection_cost(right, left)` で grammar.bin の連接表を引く。
- 左文脈があるときの最初の辺は、左文脈の最後の語の右 ID から引く（`lattice.rs` の `starts`）。**連接表を変えれば、「きのうの」を確定してから「けん」を打つ場合にも同じに効く**（こまめに確定するコンセプトに合う）。ADR 0008 の辺の補正は BOS からの辺に効かない。
- grammar.bin のヘッダは、右 ID の数（`prev_right_size`）と左 ID の数（`next_left_size`）を別に持つ（ADR 0001 §3.3）。正方形を前提にしたコードは core にも dict-format にもない（テストを除く）。左 ID を 1 つ足しても形式は変わらない。
- 品詞表の代表の左右 ID（ユーザー辞書の語が使う ID）は、その品詞で最も多い ID。件の 1 行を別の ID にしても、助数詞可能の代表は 5154 のまま。
- 辞書のポリシーの `ime_penalty` は変換だけに効き、文脈の解析は `cost` だけを使う（ADR 0002 §4）。連接表は両方が共有する（§7-3）。

## 1. 決定の要約（提案）

| 項目 | 決定 |
| --- | --- |
| 形 | 辞書を作るときに、「件」（読みケン、名詞,普通名詞,助数詞可能）の 1 行だけに**新しい左 ID** を割り当てる。連接表に、その左 ID の列を 1 つ足す（元の左 ID 5154 の列をそのまま写す）。そのうえで「格助詞 の の右 ID → 新しい左 ID」の 1 マスだけを δ 下げる |
| 対象の前の語 | 表記「の」・品詞 `助詞,格助詞` の行の右 ID（今は 802 の 1 つ）。左文脈の最後の語が「の」の場合も含む（§0.4） |
| 対象外 | 準体助詞・終助詞の「の」、連体詞（この、その、あの、どの）、BOS、ほかの語。連体詞は同じ仕組みの 2 つ目の値として測るが、既定は 0（§3、§12-2） |

| 置き場所 | `dict-builder` の新しいモジュール `connection.rs`。規則（どの語・どの前の語）はコードに固定し、値はデータに書く（ADR 0002 §4 と同じ分け方） |
| 辞書の更新 | 語は ID ではなく表記・読み・品詞で探す。見つからない、前の語の右 ID がほかの表記と共有されている、δ が閾値以下、のどれかなら辞書のビルドを失敗にする（§6） |

## 2. 規則

### 2.1 定義
1. **件の行**: 表記「件」、読み「ケン」、品詞 `名詞,普通名詞,助数詞可能,*,*,*` の行。ちょうど 1 行でなければビルドを失敗にする。読みゲン・クダリ・クダンの行は変えない。
2. **前の語の右 ID の集合 P**: 表記「の」、品詞1〜2 が `助詞,格助詞` の行の右 ID の集合。今は {802}。
3. **新しい左 ID**: `L' = next_left_size`（今は 5981）。件の行の左 ID を L' にし、連接表の左 ID の数を 1 増やす。すべての右 ID r について `cost(r, L') = cost(r, 5154)` とする。
4. **補正**: P の各 r について `cost(r, L') = clamp_i16(cost(r, 5154) − δ)`。

- 件の右 ID、単語コスト、ポリシーの `ime_penalty`、ほかの行は変えない。
- δ = 0 のときは 1〜4 をすべて行わない（ID も列も足さない）。

### 2.2 なぜこの形か
- **並びを安くし、語は安くしない**: 「けん」単独、「件名」「件数」（別の語）、「件は」は変わらない。変わるのは「格助詞 の の直後の件」だけ。§0.2 の窓がない問題は、347 の差ではなく、の → 件 の 1 マスを別に動かせることで消える。
- **専用の左 ID にする**: 5154 の列を直接下げると、助数詞可能の名詞 277 行のすべてに効く（§8 の案 B）。専用の列にすれば、効く範囲は 1 行 × 1 マスに閉じる。
- **右 ID は分けない**: 件の後ろ（は、について、で、を）の連接は、助数詞可能の名詞のままでよい。分けると、確かめる範囲が増えるだけで得がない。
- **連接表で持つ**: ラティス、N-best、左文脈の最初の辺、文節の区切り直し、再変換が、何も変えずに同じ値を見る。ADR 0008 の辺の補正（`Lattice::edge_extra`）は BOS からの辺に効かず、語を見分けるために core に語彙（「件」）を持ち込むことになる（§8 の案 C）。

### 2.3 例（予想。実装のあとに §5 で測る）
δ = T + m（m は余裕）のとき、LM なしで次の順になるはず。
- きのうのけん、かいぎのけん、せんじつのけん、ごれんらくのけん: 〜の件 が 1 位、〜の県 が 2 位以内。
- けん: 県 が 1 位のまま（件は 12 位のまま）。
- となりのけん（隣の県）: **件が 1 位になる**（§7-1。連接表では、の の前の語を見分けられない）。県 は 2 位で、LM・学習・話題が選べる位置にある。

## 3. 直前の語が「の」以外のとき（決めること (2)）

| 直前 | 扱い | 理由 |
| --- | --- | --- |
| 格助詞「の」（昨日の、会議の、ご連絡の、先日の） | **対象** | §2.1 |
| 左文脈の最後が格助詞「の」（「きのうの」を確定してから「けん」） | **対象**（何もしなくても効く） | §0.4 |
| 準体助詞・終助詞の「の」 | 対象外 | 右 ID が別（826、854）。「〜のけん」で件になる文が思いつかない |
| 連体詞（この、その、あの、どの） | **同じ仕組みの 2 つ目の値 `matter_ken_after_rentai`。既定 0**。掃引で測り、ユーザーに聞く（§12-2） | 右 ID 5979 は連体詞の全体（大きな、小さな、いわゆる、ある など）で共有する。下げると「大きなけん」「あるけん」も件になる。閾値は 県 に対し 8346（6440 + 1140 + 766）。券・剣 に対しては差が小さい（券 に対し 3269） |
| 接頭辞「本」「別」（本件、別件） | 対象外 | 本件・別件は辞書に 1 語である |
| BOS（文頭の「けん」） | 対象外 | 「けん」単独で県を 1 位に保つため（§0.2） |
| 「〜について件」のような助詞以外 → 件 | 対象外 | 自然な並びではない |

## 4. 悪化させない保証（決めること (3)）

### 4.1 評価セット `eval/sets/issue210.tsv`
`fix/ken-cost` にある 17 行（対象 9、見張り 8）を元にし、次の見張りを足す（公開の語だけ。正解は実装の PR でユーザーが確かめる）。

| 種類 | 例（読み → 期待） | 見るもの |
| --- | --- | --- |
| の + けん で始まる別の語 | のけんさ → の検査、のけんとう → の検討、のけんきゅう → の研究、のけんり → の権利、のけんこう → の健康、のけんしょう → の検証、のけんすう → の件数 | 件 + 差・等・数 などの分割に崩れないか（件の実効の単語コストがほぼ 0 になるため、いちばん危ない） |
| の + 県・券・剣 | となりのけん → 隣の県、ほかのけん → 他の県、まえうりのけん → 前売りの券、ゆうしゃのけん → 勇者の剣 | §7-1 の代償の大きさ（LM なしでは県が 2 位になる想定。LM ありで戻るか） |
| 左文脈が「の」で終わる けん | 文脈「昨日の」+ けん → 件、文脈「隣の」+ けん → 県 | 確定してから打つ場合 |
| けん 単独・〜県・県〜 | けん → 県、かながわけんの、ほんけん、けんない、けんちょう、けんめい | 単語コストを変えていないので動かないはず |
| 連体詞（§3） | このけんについて、そのけんは、あのけんは、このけんをおもちのかた → この券をお持ちの方、おおきなけん → 大きな剣 | `matter_ken_after_rentai` の掃引のときだけ |

`fix/ken-cost` の `i210-toukyouto-c`（文脈「…隣の」+ けん → 県）は、LM なしでは崩れる想定の見張り。期待は変えず、§5.3 の判定で扱う。

### 4.2 全セット
`eval/scripts/snapshot.sh`（基準 main）で、全セットの 1 位の悪化が 0。**LM なし（`--ranker cost` と既定の topic）と LM あり（`--ranker full`）の両方**で取る。AJIMEE は参考。区切りのセット（segments）はレポートが一致すること。

## 5. 掃引の設計

### 5.1 振る値
- `matter_ken_after_no` = δ: **0（基準）、4000、6000、7000、8000、8250、8500、9000、10000、12000**。T = 8252 の前後を細かく、遠くを粗く。
- `matter_ken_after_rentai`: 0 と、の の値の結果を見てから T' = 8346 の前後（8500、9000、10000）。の の値を決めてから別に振る（2 つを同時に振らない）。
- 値ごとに辞書を作り直す（`ikari-dict-builder --policy <一時の TSV> --out <値ごとのディレクトリ>`）。新しいフラグは要らない。評価は `--dict` でそのディレクトリを指す。

### 5.2 測るもの
- 対象（ken-matter）の 1 位の数と順位、見張り（ken-guard）の 1 位の数、全セットの 1 位の悪化の件数。LM なし・LM あり。
- LM ありは、実機に近い締め切りとプール（ADR 0048。プール 30）で取る。

### 5.3 決め方
1. 対象がすべて LM なしで 1 位になる最小の δ を δ_min とする（予想は 8253 付近）。
2. δ_min から上で、全セットの悪化が 0 で、見張りの「の + けん で始まる別の語」が崩れない範囲（平坦な範囲）を探す。
3. 平坦な範囲の手前寄り（δ_min に余裕 m を足した値。ADR 0008 §2.2 と同じ考え方）を既定にする。
4. 「の + 県・券・剣」（隣の県 など）の LM なしの悪化は、§7-1 の代償として数を報告し、LM ありで何件戻るかを並べる。**この悪化を許すかは §12-1 でユーザーに聞く**。
5. 平坦な範囲がない（対象を 1 位にする値で、ほかの語が崩れる）なら、この ADR の形をやめてリードに返す（§10-4）。

## 6. 辞書の更新のたびの手順（決めること (4)）

Sudachi の更新（約 3〜4 か月に 1 回。`scripts/fetch-data.sh` のバージョンと sha256 を替えるとき）のたびに、次を行う。

### 6.1 ビルドが自動で確かめること（`connection.rs`。失敗ならビルドを止める）
1. 件の行（§2.1-1）がちょうど 1 行ある。
2. P が空でなく、P の右 ID を、表記「の」・格助詞以外の行が使っていない（共有されていたら、補正がほかの語に漏れる）。
3. 左 ID の数を 1 増やしても `u16` に収まる。
4. その辞書での閾値 T を、辞書の値から計算する: 読みケンの名詞（品詞1 = 名詞。件を除く）のうち、経路「の → 語 → EOS」の変換用のコスト（単語の `cost + penalty` と 2 つの連接）が最も安い語を競合とし、`T = 件の経路のコスト − 競合の経路のコスト`。今は競合が 県 で T = 8252（§0.2）。**目標を 1 位にした場合（§12-3）、δ ≤ T ならビルドを失敗にする**（補正が効かなくなったことを黙って見逃さないため）。連体詞の値が 0 でなければ、同じ確認を T' で行う。
- 版は `fetch-data.sh` で固定しているので、失敗するのは開発者が辞書を更新したときだけで、利用者のセットアップでは起きない。

### 6.2 記録
- `--policy-report` と `BUILD_INFO` に、件の行の元の左 ID と新しい左 ID、P、δ、T（と T'）、競合の語を書く。

### 6.3 開発者が行うこと
1. 新しい辞書でビルドし、§6.1 が通るか見る。T が変わっていれば記録する。
2. §5.1 の値のうち、新しい T の前後（T − 2000、T + 250、T + 500、T + 1000、T + 2000）と今の既定で、§5 の掃引を流す。
3. 既定を変えるときは、PR に表を貼り、ユーザーに確かめる（値は計測で決める）。
4. `eval/reports/` に結果を置き、索引に足す。

## 7. 失敗のしかた（既知の限界）

1. **隣の県、他の県、どこの県が、LM なしでは「〜の件」になる**: 連接表は の の前の語を見ない。「の + けん」の既定が 県 から 件 に入れ替わるだけで、どちらかは 2 位になる。2 位なら最初のプールに入るので、LM、学習、話題で選べる。「〜の件」の方が日常で多いという判断が前提（§12-1）。
2. **の + けん で始まる別の語**: 件の実効の単語コストがほぼ 0 になるので、件 + 接尾辞・名詞の分割が安くなる。名詞 → 接尾辞 は ADR 0008 §13 の規則（覆う名詞があれば +6000）が守るが、名詞 → 名詞 は守らない。見張り（§4.1）で測る。
3. **文脈の解析にも効く**: 連接表は解析と共有する。解析は書かれた表記の上で行うので、県 と 件 は競合しない。変わるのは、書かれた「の件」で読みケンの行が読みゲンより選ばれやすくなることだけで、正しい方向。解析のテスト（`core/src/analysis/` と `import/` の golden）が変わらないことを確かめる。
4. **ユーザー辞書**: 助数詞可能の語を登録すると、代表の左 ID 5154 になり、補正は効かない（意図どおり）。
5. **grammar_id が変わる**: grammar.bin の中身が変わるので、system.dict と一緒に作り直す（いつもの辞書の更新と同じ）。学習とユーザー辞書が左 ID を保存していないことは、実装で確かめる（§10-1）。

## 8. 検討した案

- **案 A（採用）: 件に専用の左 ID を足し、格助詞 の → その ID だけを下げる**: §1、§2。効く範囲が 1 マスで、実行時のコードを変えない。左文脈の最初の辺にも効く。辞書の更新に強くするために、語を表記・読み・品詞で探し、ビルドで確かめる（§6）。
- **案 B: 既存の 802 → 5154 を直接下げる**: 助数詞可能の名詞 277 行（か、かい、か月、か所、じかん など）のすべてが「の」の直後で δ（約 8000）安くなる。「〜のか」が の + か（助数詞）に、「〜のかい」が の + 回 に崩れる形が出る。影響を見積もるだけで、277 語 × 自然な入力の評価が要り、守る手段がない。**採らない**。
- **案 C: ラティスの辺の補正（ADR 0008 の `Lattice::edge_extra`）で「の → 件」に加点**: 文脈の解析と変換の分離を保てる利点はある。しかし、(1) 語を見分けるために core に「件」という語彙を持ち込むか、system.dict に印のビットを足す必要がある、(2) ADR 0008 の枠では BOS からの辺に効かず、「きのうの」を確定してから「けん」を打つ場合に直らない（こまめに確定するコンセプトに反する）、(3) 実行時の判定が 1 つ増える。**採らない**。
- **案 D: Ranker で「の + 件」を特別扱い**: Ranker は最初のプール（30 件）の並べ替えしかできない。基準では件が 31 位、34 位、圏外で、プールに入っていない（ADR 0008 §8 の案 D、ADR 0048 と同じ理由）。プールを広げる案は ADR 0048 で採らなかった。**採らない**。
- **案 E: 件の単語コストだけを下げる（`fix/ken-cost` の `matter_ken` 述語）**: §0.2 の計算で、両方を満たす値がない。**採らない**（ユーザーの決定 2026-11-06）。
- **案 F: 単語コストと連接を両方少しずつ下げる**: 「の」の直後で効くのは合計だけなので、得はない。単語コストを下げた分、けん単独で件が上がり、つまみが 2 つになって掃引が増える。**採らない**。
- **案 G: 件の右 ID も分ける**: 件の後ろの連接を変える必要がない（§2.2）。**採らない**。
- **案 H: 前の語と後ろの語の組を書いた汎用の補正表（TSV）を辞書のポリシーに足す**: ほかの語（〜の方、〜の点 など）にも使えるが、今は 1 件しかない。規則はコードに、値はデータに置く今のポリシーの分け方を崩す。2 件目が出てから、この ADR の `connection.rs` を広げる形で考える。**今は採らない**。

---

## 9. 結果

- 得るもの: 「〜の件」が、LM なしでも 1 位になる（目標）。確定してから「けん」を打つ場合にも効く。実行時のコードと速さは変わらない。
- 失うもの: 「〜の県」が既定で 2 位になる（§7-1）。辞書の連接表が Sudachi の値そのままではなくなる（`--policy-report` と BUILD_INFO に記録する）。辞書の更新のたびに §6 の手順が増える。
- 波及: grammar.bin の左 ID の数が 1 増える（形式は同じ）。連接表を補正する仕組みが dict-builder に入る。同じ型の誤り（〜の方、〜の点 など）が出たら、案 H を考える入口になる。

## 10. 実装の進め方（決めること (5)）

`dict-builder` と評価だけで、契約（言語やレーンをまたぐ型）がないので、**1 レーン（code-editor、Sonnet）**で行う。`fix/ken-cost` の `matter_ken` 述語（policy.rs と chive.tsv の変更）は捨て、`eval/sets/issue210.tsv` だけを引き継ぐ。ブランチは `fix/ken-cost` を origin/main から作り直す。

| 持つファイル | 中身 |
| --- | --- |
| `dict-builder/src/connection.rs`（新規） | 件の行と P を探す、新しい左 ID の割り当て、列の追加と補正、§6.1 の確かめ、レポートの行 |
| `dict-builder/src/matrix.rs` | 左 ID の列を 1 つ写して足す関数 |
| `dict-builder/src/lib.rs` | 組み立ての順: matrix と lex を読む → 品詞表の代表を決める（**件の ID を変える前**） → `connection.rs` を適用 → grammar.bin と system.dict を作る |
| `dict-builder/src/policy.rs`、`policy/default.tsv` | 値の 2 つのキー（`matter_ken_after_no`、`matter_ken_after_rentai`）を受け付ける。既定は掃引までは 0 |
| `dict-builder` のテスト | 小さい合成の辞書で: δ = 0 で grammar.bin がバイト単位で同じ、列の写しが元と同じ、P の 1 マスだけが変わる、件の行が 0 行・2 行・P の共有・δ ≤ T で失敗 |
| `eval/sets/issue210.tsv` | §4.1 の見張りを足す |

順:
1. 評価セットを足し、基準（main、LM なし・あり）を取る。学習とユーザー辞書が左 ID を保存していないかを確かめる（§7-5。保存していたら止めてリードに返す）。
2. 実装とテスト（δ = 0 の既定で `scripts/check.sh`）。
3. §5 の掃引。結果を `eval/reports/` に置く。
4. 既定の値を PR に表で示し、ユーザーに確かめてから入れる。§5.3-5 に当たったら、実装を止めてリードに返す。

## 12. ユーザーに聞くこと

1. **「〜の県」が既定で 2 位になってよいか**（§7-1）: 連接表では の の前の語を見分けられないので、「昨日の件」を 1 位にすると「隣の県」も LM なしでは件が 1 位になる。県 は 2 位に残り、LM・学習・話題で選べる。**推奨: よい**（「〜の件」は日常の文で毎回出る。「〜の県」は少なく、学習で戻せる）。掃引で「隣の県」型の悪化の件数と、LM ありで戻る件数を示してから最終の値を決める。
2. **連体詞（この件、その件、あの件）も対象にするか**（§3）: 連体詞の右 ID は 大きな、いわゆる、ある なども共有するので、「大きなけん」「あるけん」も件に寄る。**推奨: 同じ仕組みの 2 つ目の値として掃引だけ行い、既定は 0 で入れる**。「この券」「大きな剣」の見張りの結果を見て、別に決める。
3. **目標の順位**: 「〜の件」を LM なしで 1 位にする（δ > 8252）か、1 ページ目（9 位以内）でよいか。後者なら δ を小さくでき、隣の県 の代償が減る。**推奨: 1 位**（報告は「毎回『県』が 1 位」で、1 ページ目では毎回選び直すことになる）。
