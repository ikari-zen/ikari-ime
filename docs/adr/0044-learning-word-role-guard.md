# ADR 0044: 学習の word の加点を、記録できない語と競う読みでは弱める（観察しよう → 観察使用）

- 状態: 提案
- 日付: 2026-11-02
- 対象: `core/src/ranker/learning.rs`（word の加点の条件と設定の 1 項目）、`eval/scenarios/`（シナリオを 1 本足す）、`eval/tests/scenario_lm.rs`、`eval/scripts/snapshot.sh`。記録側（`core/src/user/learning.rs`）、`core/src/pos.rs`、学習の形式（`learning.tsv`）、Swift は変えない
- 前提: main = 9773895。ADR 0002 §8（文脈付きの学習）、ADR 0013（記録のない文脈の back-off、上限を phrase と word に分ける）
- タスク: #2（追加の例「観察しよう」。2026-10-31 のコメント）。ユーザーが案A（役割が違う候補の間で word の加点を弱める）を選んだ

---

## 0. 現状の把握（#2 の調査と、このブランチで流した CLI）
- word の加点は、候補のセグメントごとに `share × word_factor(0.5) × base_bonus(3000)`、上限 `max_total`（6000）を phrase と別にかける（`core/src/ranker/learning.rs:322-366`）。加点を受けるのは、(a) 内容語（`core/src/pos.rs` の `is_content_word`）で、(b) 候補の間で同じ読みの表記が 2 通り以上ある（`variants`）セグメント。
- 記録側は、複数文節の確定から、内容語のセグメントだけを word として記録する（`core/src/user/learning.rs:208`、`:400-405` の `is_recordable_word`）。
- 「しよう」（`動詞,非自立可能,*,*,サ行変格,意志推量形`）は内容語でない。「使用」（`名詞,普通名詞,サ変可能`）は内容語。読み しよう の `variants` は {しよう, 使用, …} で 2 通り以上なので、使用 だけが加点を受ける。しよう は記録も加点もされない。
- 別の語の確定（「ツールを使用」）1 回で word の加点が 750、上限 1500。辞書コストの差（約 375）を覆し、LM なしで 観察使用 が 1 位になる。LM が最後まで走ると逆転しない（#2）。実機で LM が間に合わない約 14%（#159）で起きる。
- このブランチで確かめたこと（`ikari-eval --ranker full`、LM なし、学習は空から）:
  - 学習なしの かんさつしよう は 観察しよう が 1 位。「ツールを使用」を 1 回確定すると 観察使用 が 1 位。けんしょうしよう も 検証使用 が 1 位になる。
  - いこう は学習なしで 行こう が 1 位。「これ以降」を 1 回確定すると 以降 が 1 位になる（同じ型。意志形 行こう は `動詞,非自立可能`）。
  - かんさつしよう → 観察使用 を確定すると、次の かんさつしよう は 観察使用 が 1 位（phrase の学習。正しい）。同時に word の 使用 が記録され、けんしょうしよう が 検証使用 になる。
  - 左文脈「もう少し」では、学習が空でも 観察使用 が 1 位（§9。この ADR の対象外）。

## 1. 問題の定義
word の加点は「同じ読みの表記のうち、ユーザーがどれをよく選ぶか」の比を使う。ところが、比べる相手の一方（しよう、行こう）は、記録側が決して記録しない語なので、比は常に「記録できる側の 1 / (1 + prior)」に片寄る。別の文の別の役割（名詞の 使用）を選んだ記録が、「この読みではこの表記を好む」という証拠として使われ、辞書コストの 1 位を覆している。spec「基本原則」（学習は支援であって決定ではない）に反する。

直したいのは「比べられない相手との比べ合い」であって、word の学習そのものではない（案B の `word_factor` 0 や `base_bonus` の低下は、word の学習を失うか、既存のシナリオが落ちる。#2 の掃引）。

## 2. 決定の要約（提案）
1. **「役割が違う」の定義は、案 R1（記録できない語と競う読み）にする**。候補の間で、ある読みに **内容語でない（`is_content_word` が偽の）セグメント** の表記が 1 つでもあれば、その読みの内容語のセグメントの word の加点に係数をかける。判定には記録側と同じ述語（`is_content_word`）を使う。
2. **弱め方は係数** `learning.word_rival_function_factor`（0.0〜1.0。1.0 で今と同じ）。word の share 全体（context と unconditional の両方）にかける。phrase の加点は変えない。値は掃引で決める（§5。**未決**。候補 0、0.1、0.25、0.5）。
3. 判断の置き場所: Rust の core（ranker の学習）。OS に依存せず、Swift は触らない。

## 3. 「役割が違う」の定義の候補
| 案 | 定義 | 観察使用 | 既存の学習への影響 | 評価 |
|---|---|---|---|---|
| **R1（推奨）** | 同じ読みの表記のなかに、内容語でないセグメント（記録側が記録しないもの）がある | 止まる（しよう が非内容語） | 内容語どうしの競り合い（直った／治った、下記／書き、帰る／蛙）は変わらない | 問題の原因（比べられない相手）そのものを条件にする。記録側と同じ述語で、定義が 1 つで済む |
| R2 | 同じ読みの表記の間で品詞1 が違う（名詞と動詞など） | 止まる | 名詞と動詞の同音語（下記／書き、帰る／蛙）も弱まる。下記／書き は「学習と LM に任せる」と決めている（user-feedback 10-14、ADR 0010） | 広すぎる。両方とも記録できる競り合いでは、比は正しい |
| R3 | 候補の末尾の部分の品詞が違う（意志形・活用語尾と名詞） | 止まる | 末尾以外の位置（いこう が先頭のとき、中ほどの しよう）を拾うには、位置の規則が増える | 現象に寄せすぎ。R1 の部分集合で、規則が増える |

R1 の補足:
- 非内容語には、補助・非自立可能の用言、助詞、助動詞、接尾辞、代名詞、数詞などが入る。どれも記録されないので、同じ理由で比が片寄る。数詞（いち：一／位置）も弱まるが、理由は同じなので例外にしない。
- 内容語どうしの競り合い（使用／仕様／試用）も、同じ入力に しよう の候補があれば一緒に弱まる。係数を 0 にしない場合は一部が残る。これは §5 の掃引で見る（§8-2）。

## 4. 弱め方: 0 か係数か
- **係数にする**（0 も値の 1 つとして掃引に入れる）。0 に固定すると、R1 に当たるすべての読みで word の学習が消え、R1 の取りこぼし（§8-2）を調整できない。係数なら 1.0 で今の動きに戻せる（比較と切り戻しが設定だけでできる）。
- かける先は word の share 全体。context の部分だけ残す案は、context の share もやはり記録できない相手との比なので、理由が立たない。LearningGuard は unconditional しか制限しないので、ガードに任せる案も取らない。
- phrase の加点はかけない。読み全体（かんさつしよう → 観察使用）をユーザーが選んだ記録は、比べる相手（観察しよう）も phrase として記録できるので、比は正しい（入力を正とする）。

## 5. 掃引の計画（数値は未決）
- 値: `word_rival_function_factor` ∈ {1.0（今）, 0.5, 0.25, 0.1, 0}。ほかの値（`base_bonus` 3000、`word_factor` 0.5、`max_total` 6000）は変えない。
- 条件: (1) LM なし（`--ranker full`。実機で LM が間に合わないときの代わり）、(2) LM あり・締め切り 3000ms（LM が最後まで走るとき）。(3) LM あり・締め切り 300ms は揺れるので参考だけ（3 回流して幅を書く）。
- 測るもの:
  1. 新しいシナリオ（§7）の probe の合否。加えて、使用 の記録を 1 回、3 回、10 回にしたときに、観察しよう／検証しよう／行こう が 1 位を保てるか（逆転までの回数）。
  2. 既存のシナリオ 8 本（a-02、a-03、a-04、b23-naoru、b23-susumeru、b23-same-context、b28-borrowed、it-pack）の probe の落ち。
  3. 全評価セット（`eval/scripts/snapshot.sh`）の 1 位の数。学習が空なので変わらないはず。変わったら実装の誤り。
  4. `sahen-shiyou.tsv` の guard の行（使用・仕様 が正しい入力）を、学習ありの形でシナリオに写した数行（§7 の G 行）の合否。
- 選び方: 1・2・3 をすべて満たす値のうち、**いちばん 1.0 に近い値**（word の学習をできるだけ残す）。満たす値がなければ、ユーザーに聞く。結果は `eval/reports/` に書き、索引に足す。値は PR でユーザーに確認する（値は計測で決める方針）。

## 6. 契約
- `core/src/ranker/learning.rs`
  - `LearningConfig` に `pub word_rival_function_factor: f32` を足す。既定は掃引までは 1.0（今と同じ動き）。掃引で決めた値に変える PR で既定を替える。`from_kv` のキーは `word_rival_function_factor`（`learning.word_rival_function_factor`）。0.0〜1.0 の外は `RankerConfigError`。
  - `bonuses` の中の `variants: HashMap<String, HashSet<String>>` を、読みごとに「表記の集合」と「内容語でない表記があるか」を持つ非公開の型に替える。word の加点の係数は、その型から決める非公開の純関数（例 `fn word_role_factor(v: &ReadingVariants, cfg: &LearningConfig) -> f32`）にし、単体テストを付ける。
  - 公開の関数のシグネチャ（`Ranker::rank`、`context_free_bonus`、`LearningRanker::new`）は変えない。`Bonuses` の形も変えない。
- 変えないもの: `core/src/pos.rs`（`is_content_word` をそのまま使う）、`core/src/user/learning.rs`（記録の規則）、`learning.tsv` の形式、`ranker/guard/learning.rs`、Swift。
- `eval/scenarios/issue2-shiyou.tsv` を足し、`eval/tests/scenario_lm.rs` と `eval/scripts/snapshot.sh` のシナリオの一覧に載せる。
- 判断の置き場所: Rust（core の ranker）。OS の API も UI も関わらない。

## 8. 懸念点
1. `variants` は読みの文字列で束ねていて、読みの位置（どこからどこまでか）を見ない。同じ読みが入力の別の場所に出るとき、無関係な候補の非内容語で弱まることがある。今の `contested` も同じ前提なので、この ADR では変えない。
2. R1 は、同じ入力に非内容語の候補があると、内容語どうしの学習（使用／仕様）も弱める。係数 0 では消える。§7 の G 行と §5 の掃引で大きさを見る。
3. 効くのは LM が間に合わないとき。LM が間に合えば今も逆転しない。根本の頻度は #159。
4. 実機の学習の中身は見ていない（評価に実機の学習を含めない方針）。人工のシナリオで再現した型に限って直す。

## 9. 対象外（別の課題）
- 左文脈「もう少し」「#3はもう少し」のあとの かんさつしよう で 観察使用 が 1 位（または 2 位）になる。学習が空でも起き、LM なしの順位（左文脈の連接）の問題。この ADR では扱わない。#2 に別の項目として残すか、新しい issue にする（リードが task-keeper に任せる）。

## 10. 実装の進め方（レーン 1 つ。core の学習と eval だけ）
1. シナリオ `issue2-shiyou.tsv` を足す（今の main で 3・5・6・7・10 が落ちることを確かめる。G 行は CLI で期待を確かめてから）。
2. `LearningConfig` の項目と `from_kv`、`ReadingVariants` と係数の純関数、単体テスト（非内容語の表記があるとき係数、ないとき 1.0、Rewriter は対象外のまま、係数 1.0 で今と同じ加点）。既定は 1.0。
3. §5 の掃引を流し、`eval/reports/` に書く。値を決めて既定を替える（PR でユーザーに確認）。
4. `scripts/check.sh` のフルと `eval/scripts/snapshot.sh` を通す。

## 11. 受け入れ条件
- 学習ありの人工シナリオ `issue2-shiyou.tsv` で、観察しよう と 検証しよう が（使用 の記録 3 回のあとも）1 位。行こう も 1 位。観察使用 を読み全体で選んだあとは 観察使用 が 1 位。LM なしと LM あり（3000ms）の両方。
- 既存のシナリオ 8 本が、LM なし・LM あり（3000ms）とも落ちない。
- 全評価セットで 1 位が悪化しない（`eval/scripts/snapshot.sh`）。
- `scripts/check.sh` が通る。

## 12. ユーザーの判断が要る点
1. 係数の値（§5 の掃引の結果を PR で確認する。満たす値がないときは、R1 の取りこぼしをどこまで許すか）。
2. R1 で、内容語どうしの学習（使用／仕様）が、同じ入力に しよう の候補があるときに弱まることを許すか（§8-2。推奨: 許す。比べられない相手が混ざる読みでは、word の比を信じない方が基本原則に沿う。読み全体で選んだものは phrase で残る）。
