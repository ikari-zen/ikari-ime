### 0.2 原因の構造
1. **Sudachi の語のコストは頻度をほとんど表さない。** 2文字以上の漢字の普通名詞（表記 = lemma）で、chiVe の順位の帯ごとのコストの中央値は、1000〜3000 位 6515、1 万〜3 万位 7402、3 万〜10 万位 7404、chiVe にない語 7404。10 万位より下の語の 42〜49% は既定の値（一般 7404、サ変可能 6518）を持つ。頻度の手がかりは `lemma_rank`（1 桁あたり 2000）だけ。
2. **解析用に安い語がある。** 複合語の部品（四半 2754 ← 四半期、管弦 3788 ← 管弦楽、右中 3144 ← 右中間）、新聞に多い語（製鋼 5268、訪朝 4479、部隊 2534）は、既定の値より 1000〜4000 安い。これが、よく使う同音語（市販、還元、宇宙、包丁）に勝つ。katakana_analysis（メイ／名）と同じ型で、漢字の語にもある。
3. **文脈で決まる同音語は、まれでも既定の値を持つ。** 介抱（62248 位）、照会（11438 位）、考証（49009 位）、対照（16846 位）、硬貨（16146 位）は、どれもコスト 6518 か 7403。頻度だけで下げると、文脈（怪我人を、残高の、原文と訳文を）があっても戻らない（§6 案 A、B）。
4. **分野の偏りは、頻度では切り分けられない。** 製鋼（48327 位）は 介抱（62248 位）より頻度が高い。「特定の文脈でしか使わない」を表す値は辞書にない。
5. **サ変でない名詞＋する**: 連接表は区別しているが（一般 → する -610、サ変可能 → する -3931）、頻度の差（女性 219 位 vs 助成 4265 位）や `frequent_compound` で覆る。文語の する（`文語サ行変格` の連体形）を通る逃げ道もある（公園する は 文語サ行変格 の する で1位）。

### 0.3 広さ（辞書から機械的に探した。試作のスクリプトは scratchpad）
- **R（まれな同音語が1位）**: 2文字以上の漢字の普通名詞（表記 = lemma）が2語以上ある読みは 13374。そのうち、最もよく使う語が次の語より 3 倍以上よく使われる 5035 読みを、読みだけで変換した。1位が最もよく使う語でないのは 1085 件。内訳は、**漢字の名詞で 10 倍以上まれな語が1位 62 件、3〜10 倍 197 件**（`frequent_compound` が効いたもの 3 件）、同じ名詞どうしで頻度が近いもの 18 件、かな・分割・別の品詞 808 件（期待そのものが文脈なしでは決まらないものを多く含む）。
  - 例: うちゅう → 右中（宇宙）、らいしゅう → 来襲（来週は4位）、しゅうまつ → 終末（週末）、がくぶ → 楽舞、ようび → 妖美、ほうちょう → 訪朝、きけん → 棄権、じょうじ → 情事、かいちょう → 開帳、しはん → 四半、かんげん → 管弦、さとう → 差等（差＋等）、きじ → 生地、ぶたい → 部隊、かいだん → 会談、じゅよう → 受容
- **S（サ変でない名詞＋する）**: サ変可能の名詞（5 万位以内）とサ変でない名詞が同じ読みにある 2201 読みに する を付けて変換した。誤りは 87 件。**サ変でない名詞＋する が 30 件**、別のサ変の名詞 24 件、その他 33 件（数詞＋する（九名する、五機する）、副詞＋する（一向する、一層する）、分割）。
  - 例: じょうきょうする → 状況する（上京する）、じょせいする → 女性する、せんせいする → 先生する、しきする → 式する、きかんする → 期間する、こうえんする → 公園する、じたくする → 自宅する、しじょうする → 市場する
- **D（分野の偏り）**: 機械的には探せない（§0.2-4）。製鋼 の型は、R の「まれな語が2位」の中に混ざる。

## 2. 規則 S: サ変でない名詞＋する の辺

### 2.1 定義
変換のラティスの辺 `prev → next`（BOS からの辺と EOS への辺を除く）で、
- `prev` が辞書のノードで、品詞1 = 名詞、品詞3 が `サ変可能` でも `サ変形状詞可能` でもない（一般、副詞可能、形状詞可能、助数詞可能、数詞、固有名詞など）
- `next` が辞書のノードで、品詞1 = 動詞 かつ活用型が `サ行変格` か `文語サ行変格`、または品詞1 = 助動詞 かつ活用型が `文語下二段-サ行`

のとき、連接コストに **3000** を足す。文脈の解析（`ContextAnalyzer`）には使わない（ADR 0008 と同じ。解析は Sudachi の値のまま）。

### 2.2 なぜこの形か
- **問題は並び**（名詞 も する も本物で、並びが不自然）なので、ADR 0008 と同じく辺で扱う。語のコストを変えると、同じ名詞の ゲームの・状況を など、する 以外の並びまで動く。
- **連接表はすでに区別している**（-610 と -3931）が、差 3321 は頻度の差（女性 219 位 vs 助成 4265 位）や `frequent_compound`（-8000）に負ける。足すのは「連接表の区別を、ほかの加点に負けない大きさにする」分。
- **文語の する と す を含める**: サ行変格だけにかけると、文語サ行変格 の する（連体形）を通る経路に逃げて 公園する が1位のままだった（試作の1回目）。
- **値 3000**: 2000 では S 2139（3000 は 2143）、5000 では ゲームする → ゲーム擦る、テニスする → テニス擦る、ランチする → ランチ擦る が崩れる（rare-homophones の否定）。3000 は崩れが出ない範囲で、効果がほぼ頭打ちになるところ。
- **候補を消さない**: 最下位する、ゲームする は残る（ほかに候補がなければ1位のまま）。

### 2.3 効かないもの
- 副詞＋する（一向する、一層する）、数詞の一部は品詞が違うので対象外（数詞は名詞なので 九名する、五機する は直る）。
- サ変の名詞どうし（再会する／再開する、施行する／施工する、製作する／制作する）。頻度と文脈の問題で、この規則は区別しない。

## 3. 規則 R: 解析用に安い語のコストの下限

### 3.1 定義
辞書の行 W に当てるのは、次のすべてを満たすとき。
- (a) 品詞1 = 名詞、品詞2 = 普通名詞、表記 = lemma、表記が漢字だけで2文字以上
- (b) Sudachi のコスト < 6518
- (c) lemma の chiVe の順位 ≥ 2 万（chiVe にない語は語彙の大きさ）
- (d) 同じ読みの、(a) を満たす行の lemma の chiVe の順位の最小を p とすると、`log10(W の順位 + 1) − log10(p + 1) ≥ 0.5`

当たった行には `6518 − コスト` を足す（コストを 6518 にそろえる）。`lemma_rank` などほかの述語はそのまま足す。

### 3.2 なぜこの形か
- **ずれているのは「頻度」ではなく「解析用の安さ」**: 文脈で決まるまれな同音語（介抱、照会、考証、硬貨）は既定の値（6518、7403）を持ち、規則に当たらない。当たるのは、Sudachi が解析のために既定の値より安くした語（右中 3144、四半 2754、管弦 3788、訪朝 4479、製鋼 5268）で、これは「頻度が高い」という意味ではない。
- **6518 にそろえるだけで、消さない**: 当たった語は、辞書の中のふつうのまれな語（既定の値）と同じ重さになる。文脈（鉄鋼業の＋せいこう → 製鋼、画面の＋せんい → 遷移、軍の＋ぶたい → 部隊）があれば今どおり1位になる（rare-homophones の否定は 21 / 21 のまま）。
- **2 万位以下**: 1 万位以下にすると、rare-homophones は 46（しはん → 市販、かんげん → 還元 が直る）だが、世界の＋しゅうまつ → 終末（12343 位）が 週末 に負け、S の探索の いっぽうする → 一報する が 一方する（5位）に崩れる。1.5 万位では 47 で 終末 は守れるが、一報する の崩れは残る。2 万位は 45 で、崩れがない。四半（15969 位）、管弦（18364 位）は 2 万位より上なので当たらない（§5.2、§6.3。どちらを採るかは §8-3）。
- **同じ読みに 3 倍以上よく使う語があるとき**: 同音語がない語、頻度の近い同音語しかない語は、安くても困らない。1 桁（10 倍）にすると 視察、臓器、言動 が漏れる（R 3954、rare-homophones 42）。
- **下限を 7000、7404 に上げない**: 既定の値 6518 を持つ サ変可能 の語まで上がり、ext dev が 778 → 774（7000）、758（7404）に下がった（照会、対照、介抱 など、文脈の語が負ける）。
- **辞書を作るときに決める**: 頻度は chiVe でしか分からず、ラティスや Ranker からは見えない（ADR 0011 §2.2 と同じ理由）。

## 4. 規則にしないもの・残る誤り

### 4.1 分野の偏った語（製鋼）
- せいこうする の 製鋼する は、規則 R で 2位 → 4位 に下がる（製鋼 のコスト 5268 が 6518 になる）。ただしこれは「解析用に安い」から当たったのであって、「分野が偏っている」から当たったのではない。
- 分野の偏りそのものは規則にしない。理由:
  1. **辞書に手がかりがない**（§0.2-4）。製鋼（48327 位）は 介抱（62248 位）より頻度が高く、頻度で切ると、文脈で決まる語（介抱、照会、考証）を先に落とす（§6.1、§6.2 で実測）。
  2. **分野の語の表を手で作ると、保守がユーザー1人に乗る**。どの語を「分野の語」とするかは使う人によって違い（ユーザーには IT の語がふつう）、表の誤りは評価セットでしか見つからない。
  3. **分野を扱う仕組みはすでにある**: 属性プロファイル（it で いとだけ → 意図だけ。§0.1）、文脈（鉄鋼業の＋せいこう → 製鋼）、学習（ADR 0013 の back-off。1回選べば上がる）、LM。分野の偏りは「その人の分野」の問題なので、ユーザーごとの仕組みで扱うのが筋。

### 4.2 頻度の高い同音語（糸／意図）
- いとだけ は変わらない。糸（3104 位、コスト 4739）は chiVe でも 意図（5145 位、コスト 6506）より上で、どちらの規則にも当たらない。辞書の値は「誤り」ではないので、規則で 意図 を上げる根拠がない。
- 「実装はしないで。」の文脈でも、話題の加点（-1677）が差（2403）に届かない（§0.1）。文脈の効き方の問題で、この ADR の範囲外（§8-5）。

### 4.3 サ変の名詞どうし（再会する／再開する）
- さいかいする の1位は 再会する のまま（2位 再開する）。どちらもサ変可能の名詞で、規則 S は区別しない。差は頻度（2.6 倍）と語のコストの差（2121）で、規則にする根拠がない。LM（300ms・2000ms）では 作業を＋さいかいする が 再開する になる（§5.3）。文脈なしは学習で直る。
- 最下位する は 3位 → 5位。実機で1位になった件（§0.1）は、文書内キャッシュか学習の効きと考えられ、CLI では再現していない。再現しないものは直したと言えないので、実機で再び出たときのログ（候補とコストの内訳）を取る（§8-6）。

### 4.4 さいかい（1語）→ 最下位
- 最下位 はコスト 12389 で規則 R に当たらず、`frequent_compound`（-8000）が効いたまま1位に残る。`frequent_compound` を同じ読みの短い名詞（再会、再開）があるときに外す案（§6.5）は、リーグで＋さいかい、さいかいになる など 最下位 が正しい入力を崩した。**この ADR では扱わない**（§8-4）。

### 4.5 既定の値を持つまれな語
- 新しいセットの「頻度」24 件のうち、規則 R で直るのは 6 件（宇宙、包丁、戦後、視察、臓器、言動）。残る 18 件（来襲、楽舞、妖美、各字、移封、棄権、情事、開帳、四半、管弦、受容、会談、部隊、生地、差等、想起、自給、終末）は、まれな語の側が既定の値を持つ（§0.2-3）、コストの下限の条件（2 万位、6518 未満）に当たらない、かなや分割が1位（ようび、さとう）のどれか。
- この 18 件のうち 15 件は、LM あり（2000ms）なら規則なしでも直っている（直らないのは じゅよう → 受容、ぶたい → 部隊、さとう → サトウ）。
- これらを頻度で下げると、文脈で決まる語が崩れる（§6.1）。**規則を広げず、学習、プロファイル、LM に任せる**。

### 4.6 その他
- ぶんかする: 規則 S だけなら 分化する が1位になる（S のみの試作。§5.2）が、規則 R で 分化（コスト 4620、26950 位）も下限に当たり、文化する に戻る。S を 5000 にすると直るが、ゲーム擦る が出る（§6.4）。
- さいかいしよう → 再会使用（名詞＋名詞 の分割）は B17 の型で、この ADR の範囲外。LM 2000ms では 再会しよう になる。
- 副詞＋する（一向する、一層する）は品詞が違い、規則 S の対象外（§2.3）。

### 6.1 案 A: 同じ読みに、よりよく使う語があるとき、頻度の差に比例して加算する（`rare_homophone`）

| 変種 | rare-homophones | ext dev | ext test | 探索 R | 探索 S | new-words |
| --- | --- | --- | --- | --- | --- | --- |

- 探索 R は採用案より上がるが、**文脈で決まるまれな語が崩れる**: 原稿を＋こうせい → 構成（校正）、原文と訳文を＋たいしょう → 対象（対照）、学問を＋ついきゅう → 追求（追究）、怪我人を＋かいほう → 解放（介抱）、残高の＋しょうかい → 紹介（照会）、鉄鋼業の＋せいこう → 成功（製鋼）。

### 6.6 案 D: 分野の偏りを規則にする（分野の語の表、または分野の印を辞書に足す）
- §4.1。辞書に手がかりがなく、表は手で作るしかない。表の保守がユーザーに乗り、使う人の分野で正解が変わる。分野はプロファイル・文脈・学習で扱う。**採らない**。

- LM あり（2000ms）でも サ変の 5 件（助成する、先制する、分化する、開戦する、知覚する）は基準では直っていない（§5.3）。LM の締め切りに間に合わないとき（先行計算のない変換、区切り直し）は効かない。Ranker で見る案は、ADR 0008 §8 案 D と同じ理由（プールに入らない、N-best の順と食い違う）で採らない。規則で直る形は規則で直す（ADR 0008 と同じ方針）。

## 7. 影響範囲とリスク

### 7.1 変わるもの
- **規則 S**: `core/src/lattice.rs` の `EdgeRules` と `Lattice::edge_extra`（ADR 0008 と同じ関数）。品詞の表に「サ変でない名詞」「サ行変格の動詞と文語の す」の分類を足す。値は `ConvertOptions` に持ち、`--ranker-config` の `lattice.<名前>.penalty` で上書きできる（0 で止まる）。名前は本実装で決める。
- **規則 R**: `dict-builder/src/policy.rs` に述語を1つ、`policy/chive.tsv` に値（下限、順位、差）。辞書の形式は変えない。**辞書を作り直す必要がある**（ユーザーの手元は `install-data.sh` で入れ替え）。
- Ranker、LM、学習、文脈の解析（`ContextAnalyzer`）は変えない。

### 7.2 リスク
1. **N-best のコストの意味**: ADR 0008 と同じく、経路のコストが Sudachi の値だけでは決まらなくなる。2 つ目の辺の規則なので、`edge_extra` の中で規則の順と重なり（副詞 → 名詞 と 名詞 → する は同じ辺にならない）を本実装のテストで固定する。
2. **規則 R は chiVe の順位と辞書の版に依存する**: B20（Core → Full の置き換え。ADR 0012）で辞書の行が増えると、当たる行と「同じ読みの よく使う語」が変わる。B20 が先に main に入れば、その上で測り直す。逆なら、B20 の統合で測り直す。どちらでも §5 の数字は Core のもので、Full の数字ではない。
3. **規則 R が当てる行の一部は、正しい語を後ろに下げる**: 時季（じき）、調製、火口、管制、分化 など、実際に使う語も 6518 まで上がる。消しはしないので、文脈・学習・LM で戻る（否定のケース 21 / 21 は保たれた）。ただし、否定のケースは 21 件で、383 行のすべてを確かめたわけではない。
4. **規則 S と R が打ち消すケース**（ぶんかする）がある。2 つの規則を別々に止められるように、値を別に持つ（S は `ConvertOptions`、R は `policy/chive.tsv`）。
5. **学習との関係**: 規則は学習の加点を止めない。最下位 を学習で選んでいれば、さいかいする の 最下位する が上がりうる（実機の報告の原因の候補。§4.3）。この ADR はそれを防がない。
6. **評価セットの期待が下書き**: rare-homophones.tsv の期待は Claude が chiVe の頻度と日常の用法から書いた。期待が誤っていれば、値の選び方が誤る（§8-7）。セットの先頭のコメントにある `eval/sets/REVIEW.md` の ADR 0016 の節は、まだない。
7. **探索のセット（scan-R、scan-S）は scratchpad にしかない**。期待が chiVe から機械的に決まるので、リポジトリには入れない（数字の再現には試作の手順が要る）。入れるかは §8-8。

### 7.3 実装の進め方（承認のあと）
- 規模が小さいので、レーンを分けず 1 つの code-editor で行う（ADR 0008 §10 と同じ）。
  1. 契約: `ConvertOptions` の規則 S の値、`policy/chive.tsv` の規則 R のキー（述語名 `cheap_rare_homophone`）。
  2. 実装とテスト: 規則 S の品詞の分類の単体テスト（文語サ行変格、文語下二段-サ行 の す を含む）、規則 R の述語の単体テスト（条件の境界）、実辞書のテスト（せいこうする、じょうきょうする、げーむする）。
  3. 統合: `scripts/check.sh`、`scripts/check.sh --real --perf`、snapshot（基準 main）で、差分が §5.2 のケースだけであること。rare-homophones を snapshot.sh のセットに足す。

## 11. 追記（2026-10-22。B63 / issue #110）: 助詞＋しよう（意志形）の規則 V

### 11.1 問題と原因

「としよう」が 文脈なしで 都市用、issue のあとで と使用 になる。「にしよう」「でしよう」「そうしよう」も 使用 になる。CLI で確かめた原因は、助詞＋名詞「使用」（単語コスト 3597）のほうが、助詞＋動詞「しよう」（サ行変格・意志推量形）より安いこと。

### 11.2 規則 V

- 辺 (助詞・副詞・接続詞) → (読みが しよう の、サ行変格の意志推量形の動詞) から **5000 を引く**。
- 辺 (その しよう) → (動詞・名詞・接尾辞) に **5000 を足す**。前の辺だけだと「でしようする」（で＋しよう＋する）が 使用する に勝つ。意志形のあとに動詞・名詞は来ないので、足してよい。
- 値は `ConvertOptions::volitional`（`VolitionalRule`、既定 5000、`--ranker-config` の `lattice.volitional.bonus`、0 で止まる）。
- 負の値の辺の補正は、これが初めて。前向き Viterbi と後ろ向き A* が同じ `edge_extra` を使うので、ヒューリスティックは正確なまま。

### 11.3 値と範囲の根拠（評価セット `eval/sets/toshiyou.tsv` の 20 件、dev / test まとめて）

- 値の幅は狭い。4500 では直したい側が 2 件残り（13 件中 11）、5500 では に使用する が にしようする になって守る側が 1 件壊れる。5000 で 20 / 20。
- prev に 副詞 を含めるのは そうしよう、どうしよう のため。接続詞は、文脈なしの で が接続詞になるため（でしよう）。
- next の読みを しよう に限るのは、限らない試作で ext の こうしょう（考証・公称）が 12 件悪化したため（こう＋しょう の意志形）。この版は使わない。
- prev を助詞だけにすると、他のセットは変わらないが でしよう（文脈なし）と そうしよう が残る。

### 11.4 実測（LM なし、`snapshot.sh --compare`）

- toshiyou: 1位 7 / 20（直したい側 0 / 13）→ 20 / 20。
- ほかの全セットの1位: 悪化 0。adverbs の どうしよう が改善（+1）。辞書、segments、シナリオ、CLI golden は変化なし。
- 限界: 「ひとにしよう」のように、名詞の 使用 が自然な文脈でも、かなで しよう と打てば 意志形が1位になる（入力を正とする原則どおり。使用 は 2 位以下に残る）。

## 12. 追記（2026-10-23。#230）: サ変可能の名詞＋しよう（てすとしよう → テストしよう）

### 12.1 問題と原因

「てすとしよう」の 1 位が「テスト使用」、「けいかくしよう」が「計画使用」（LM なし）。規則 V（§11）は前の品詞が助詞・副詞・接続詞のときだけ効くので、前がサ変可能の名詞だと効かない。名詞＋名詞「使用」のほうが、名詞＋動詞「しよう」（サ変の意志推量形）より安い。LM ありでは、評価セット（下記）の 44 件中 42 件が元から しよう で、LM なしだけの問題。実機のユーザーの報告は、LM が間に合わなかった場合と考えられる（推測。未確認）。

### 12.2 変更（`core/src/lattice.rs` の規則 V、`VolitionalRule`）

1. 辺 (`名詞,普通名詞,サ変可能`) → (読み しよう のサ変の意志形) から **`sahen_bonus`（既定 1500）を引く**。`--ranker-config` は `lattice.volitional.sahen_bonus`（0 でこの辺は補正しない）。助詞などの辺の 5000 は変えない。
2. 「しよう → ○○」の +5000 の対象に、**接頭辞と、助動詞（助動詞-ダ の じゃ を除く）**を足す。1 だけだと、「かくにんしようちゅう（確認使用中）」「れんらくしようしょ（連絡仕様書）」が、しよう＋ちゅう（助動詞）、しよう＋しょ（助動詞）、しよう＋中（接頭辞）の無意味な分割に負ける。じゃ を除くのは「しようじゃないか」のため。サ変可能の名詞も「しよう → 名詞」の +5000 の対象のまま。

### 12.3 値の掃引（評価セット `eval/sets/sahen-shiyou.tsv` の 177 件。1 位正解の数。`sahen_bonus` 以外は 12.2 の 2 を入れた状態。期待はユーザー確認済み 2026-10-23: 作業しよう、設計しよう など 16 件は「サ変＋しよう」）

- 下限は約 1150（「使用」とのコスト差）。上限側の 3000 は仕様書が壊れる。LM ありの害が最小で、LM なしの改善が飽和するのは 1200〜1500。**1500 を選ぶ**（幅は 1200〜1500）。ユーザーの期待の訂正（作業使用・設計仕様 を期待にしない）で、LM なしの悪化は 1 → 0 になったが、選ぶ値と幅は変わらない。
