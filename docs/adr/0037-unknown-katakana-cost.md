## 0. 現状の把握（researcher の調査。確認済み）

- 「バージョニング」は辞書にない。候補は origin=katakana の 1 語で、読みのひらがなから作る。作るのは `build_first_pool`（conversion.rs:134-160）。
- そのコストは **「辞書の候補の最大 base_cost + 1」**。辞書の候補は `DEFAULT_POOL_SIZE` = 30 件（options.rs:11）なので、カタカナの候補は必ず 30 件の後ろ（ひらがなの候補と並んで 31〜32 位）に置かれる。
- `katakana_like` の補正は既定で有効だが、効く手がかりは強いもの（ゔぁぃぅぇぉ）だけ。ー・ぐ などの弱い手がかりは `weak_bonus` = 0 で効かない（katakana_like.rs:22-23。ADR 0020 §14 の掃引で、和語を壊さない幅では利益がなかった）。
- ばーじょにんぐ（LM なし / `--ranker full` の LM あり）: 1 位 バー叙任具 と 2 位 バー𥝱人具 は合計コスト 24228（22221）で同じ。バージョニング は 31403（30163）。𥝱 は「じょ」の数詞で、辞書に 1 字の語としてある。
- 同じ型（調査用の人工例。実在の自然な語ではないので評価セットには入れない。§6.4）: ろーかるじょにんぐ、でぃれくとりーぐ（末尾が「ぐ」だと崩れる）。辞書にある語（ぷろびじょにんぐ、すけじゅーりんぐ、ばーじょん）は 1 位。
- でぃれくとりーぐ（調査用の人工例）は強い手がかり（ぃ）を 1 つ持つのに崩れる。下げ幅 5000 は「最大 + 1」からの値なので、辞書の候補のコストの幅が 5000 より広いと、補正があっても 1 位に届かない（ADR 0020 §14 の「5000 未満は動かない」も同じ理由と読める。**推測**。§6 S0 で確かめる）。

## 1. 問題の定義

- 本質は、**未知語のカタカナの候補のコストが、ラティスの経路のコストと同じ物差しで決まっていない**こと。「辞書の最大 + 1」は「辞書の候補より必ず後ろ」という意味しか持たず、分割の経路がどれほど不自然（まれな 1 字の語の連なり）でも、カタカナの候補はそれに勝てない。
- 経路のコストは読みが長いほど増える。不自然な分割は 1 字あたりのコストが高く、自然な和語の解析は低い。カタカナの候補に「読みの長さに応じたコスト」を与えれば、不自然な分割にだけ勝ち、自然な解析には負ける形にできる見込みがある（**推測**。§6 の掃引で確かめる）。
- 制約: 候補は辞書から作り、読みに対応しない文字は足さない（守る決定）。カタカナの候補は読みそのものなので、この制約の内側にある。変換に手を入れたら、全セットで 1 位が悪化しないこと（CLAUDE.md）。値は計測で決める。

## 2. 決定（K1 の採用は 2026-10-29 のユーザー決定。§10）

**案 K1 を採る。** 辞書にない語のカタカナの候補（辞書に同じ表記の 1 語の候補がないとき）の base_cost を、

```
katakana_cost = min( 辞書の最大 base_cost + 1,  base + per_char × 読みの文字数 )
```

にする。その上に、今の `katakana_like` の下げ幅（下限 = 辞書の最小 − `below_best`）をそのまま掛ける。

- 「最大 + 1」より高くはしない（今より後ろに下がる読みは出ない）。
- ひらがなの候補（origin=hiragana）は今のまま「最大 + 1」。
- 辞書に同じ表記の 1 語があるカタカナ（ばーじょん → バージョン）は今のまま（辞書のコスト + `katakana_like`）。
- `base` と `per_char` は `--ranker-config` で上書きできる設定にし（接頭辞は `katakana_like` に足すか別にするかは実装で決める。契約は §5）、**既定値は §6 の掃引で決める**。掃引で採用の条件を満たす値がなければ、K1 を採らず、既定は今と同じ（K1 を無効にする値）にする。
- 文字数は読みのひらがなの文字数（拗音・長音も 1 文字）。モーラで数えるかは S0 で両方を測って決める。

### 3.1 案 K6 の詳細（ユーザーの問い「辞書に入れるのではなく、別の方法で外来語っぽいと判定できないか」への答え）

- **作り方**: 辞書のビルド時に、(1) 表記がカタカナだけの語の読み（外来語の側）と、(2) 表記が漢字・かなの語の読み（和語の側）について、読みの 2〜3 文字の並び（モーラの n-gram。語の頭と末尾の印を含める）の出る回数を数える。並びごとに、2 つの側での出方の比（対数の比など）を表にする。**手書きの表は持たない**（今の `strong_chars` / `weak_chars` のような文字の表を足さない）。
- **実行時**: 読みの並びの値を足し合わせ、読みの長さで割った値を「外来語らしさ」の連続値にする。表を引くだけなので軽い（推測。時間は S0 で測る）。
- **K1 との組み合わせ**: 次のどちらか（または両方）を掃引の軸にする。値は決めない。
  - K1+K6a: 外来語らしさが閾値を超えた読みだけ K1 を効かせる。
  - K1+K6b: `per_char`（または `base`）を外来語らしさの関数にする（らしいほど安い）。
- **`katakana_like` との関係**: K6 は `katakana_like` の手がかりの文字（強い・弱い）を、データから数えた値で置き換える形になる。両方を残すと二重に下げるので、掃引では「K6 だけ」と「K6 + `strong_bonus`」を比べ、K6 を採るなら `katakana_like` を外すか残すかもそこで決める。
- **副作用**:
  - ぐ で終わる和語（およぐ、いそぐ、つなぐ）: 末尾の ぐ は和語の側にも多いので値は小さく出るはずだが、〜にんぐ の「んぐ」と分けられるかは測るまで分からない。
  - 擬音語・擬態語（ぴかぴか、ふんわり）: 辞書にカタカナの表記で入っている擬音語が外来語の側に入り、らしさが高く出る恐れ。外来語の側から、反復の読み（`is_reduplication`）や品詞が副詞の語を除く処理が要るかもしれない（S0 で決める）。
  - 口語の長音（すげー、やばー）: ー を含む並びは外来語の側にほぼ限られるので、らしさが高く出る恐れ。守る群で測る。
- **表のサイズ**: 3 文字までの並びの種類の数で決まる。かなの種類の 3 乗が上限だが、実際に出る並びだけを持つ。大きさは S0 で数える（未計測）。
- **辞書のビルドへの影響**: 辞書の語を 1 回なめて数える段が 1 つ増え、出力に表のファイルが 1 つ増える。表は辞書の版に結びつくので、辞書の一式（ADR 0033 の配布を含む）と一緒に作り直す。
- **K4 との違い**: K4 は人が選んだ文字や語尾の型を足す。K6 はデータから数えるので、型の表を人が手入れしなくてよい。

## 4. 結果（採ったときに変わること）

- 得るもの: 辞書にない外来語（IT の語の 〜にんぐ など）が、不自然な分割に勝って 1 位、または上位に出る。語彙集（ADR 0012）に足さなくても効くので、語彙集の手入れが減る。`katakana_like` の強い手がかりも、最大 + 1 ではなく K1 の値から引くので届きやすくなる（推測。S0 で確かめる）。
- 失う恐れ: 短い読みや、辞書の語の組み合わせが少し高いだけの和語で、カタカナが 1 位や最初の 3 件に入る（ノイズ）。LM ありでは、カタカナの候補が上がることで LM の並べ替えの相手が変わる。これらは §6 の基準で測って止める。
- 変えないこと: 辞書、ラティス、ひらがなの候補、ADR 0020 の英字 → カタカナの規則、学習。

## 5. 契約（実装に入るときに先に入れるもの）

- `KatakanaLikeRule`（または新しい小さな構造体）に、`base: i32` と `per_char: i32` を足す。**両方 0 なら K1 は働かず、今と同じ**（`is_enabled` と同じ扱い）。
- `lowered_cost(reading, cost, best)` の前に、未知語のカタカナにだけ `min(cost, base + per_char × n)` を掛ける関数を置く。辞書に同じ表記があるカタカナ（conversion.rs:149-155 の分岐）には掛けない。
- 掃引のために、既定は 0（無効）のままで入れ、値は掃引の後の別のコミットで既定にする。
- **K6 の表を作る語から、leave-one-out の除外語（§6.1.1）と eval/sets の期待の語を除く**。除いた語で表を作らないと、外した語の並びが表に残り、評価が実際より楽になる。表を作るコマンドは除外表を引数で受け取り、除いた件数を出す。
- leave-one-out のためのコードは足さない（2026-10-29 ユーザー決定。§6.1.1、§7）。

## 6. 掃引の設計

### 6.1 S0（測るだけ。値を決める前の分布）

- 目的: `base` と `per_char` の格子の範囲を、勘ではなく分布から決める。あわせて、LM ありの並べ替えが塊の全件（31〜32 位を含む）に掛かっているかをログか CLI で確かめる（掛かっていなければ、K1 で上がった位置で初めて LM が見る、という差が出る）。
- 方法: 次の 2 群の読みを単独で変換し（`ikari-eval --ranker full`、LM なし、`--out-cases`）、読みごとに「辞書の最小 base_cost」「最大 base_cost」「文字数」「モーラ数」を出す（出力の列が足りなければ、捨てるコードで出す）。
  - 守る群: eval/sets のうち期待がカタカナでないケース全部（homophones-ext、hiragana、verbs、adverbs、katakana-like の 擬音語・和語 など）と、Sudachi Core の表記が漢字・かなの語の読みから乱数の種を固定して選んだ読み（件数は S0 で、変換の時間に合わせて決める）。
  - 狙う群: katakana-like の カタカナ語(弱い) と、§6.4 で足すケース。
- 出すもの: 2 群の「最小コスト ÷ 文字数」の分布（分位点）。2 群が重なる幅が大きければ、K1 だけでは分けられないので、K4・K5・K6 を軸に足すか、K1 を止める判断に使う。
- K6 の分離（捨てるコードで表を作って測る）: 辞書のカタカナ語と和語の読みから §3.1 の表を作り、狙う群と守る群の読みの「外来語らしさ」の分布を出す。分離の度合いは、2 群の分布の重なりと、閾値を動かしたときの「狙う群を拾う割合」と「守る群を誤って拾う割合」の曲線（ROC と AUC）で見る。守る群は、ぐ で終わる和語、擬音語、口語の長音を別に数える。あわせて表のサイズと、判定 1 回の時間を測る。表を作る語は eval/sets の読みと重ならないようにする（重なった語は除いて数え直し、差を記録する）。値と閾値はここでは決めない。
- **K6 を掃引の軸に足す条件**: K6 の分離が「最小コスト ÷ 文字数」より狙う群と守る群をよく分けるとき（同じ誤り率で拾う割合が高いとき）。分けられなければ K6 は採らず、K1 だけで掃引する。

#### 6.1.1 leave-one-out の狙う群（2026-10-29 ユーザー承認）

本物の未知語（バージョニング、シャーディング）は数本しかないので、辞書にあるカタカナ語を辞書から外して「疑似の未知語」にし、狙う群を増やす。`build_first_pool`（conversion.rs:133-160）のカタカナの候補の作り方は、疑似と本物で同じ経路を通る（外した語は `seen` に入らない。researcher が確認済み）。

- **抽出の条件**（ユーザー決定）: Sudachi（small・core・notcore）の行のうち、表記も読みもカタカナで、読みが 6 字以上、末尾が 〜ング・〜ション・〜ジョン の語。researcher の数え: 〜ング 5,168（Sudachi の A・B 分割の印なし 1,264）、〜ション 3,050（同 874）、3 つの型の計 8,698（同 2,243）。
- **2 つの群で測る**（ユーザー決定）: 「分割の印なし」と「全体」の両方。印は Sudachi の単位の印で、ラティスで実際に分割できるかではないので、片方だけにしない。tags 列に `loo`、型（`ng` / `shon` / `jon`）、`unsplit` または `split` を入れ、集計は tags で分ける。
- **同音の別表記は辞書に残す**（ユーザー決定）。外すのは対象の (表記, 読み) の行だけで、品詞の違う同じ (表記, 読み) の行はすべて外す。同じ読みの英字の表記（Versioning など）が残る語は、ADR 0020 の規則でカタカナが出るので K1 を測っていない。tags に `homophone-left` を付けて、別に数える。
- **TSV**: 列は `id kind tags profile context reading expected note split source`（eval/sets/katakana-suffix.tsv と同じ）。除外表から機械的に作り、scratchpad に置く（リポジトリに入れない。数千行で、辞書の版に結びつくため）。id は `loo-<読み>-<表記>` のように (表記, 読み) から決まる形にし、**split は既存の規則 FNV-1a64(id) % 5 == 0 なら test、それ以外は dev**。調整は dev だけで行い、test は採る値を決めた後に 1 回だけ流す。
- **件数の上限**: 掃引の 1 点あたりの時間（LM ありを含む）で決める。上限を超える群は、FNV-1a64(id + 固定の種の文字列) の小さい順に上限まで取る（種は eval/reports に書く。乱数のライブラリは使わず、同じ入力から同じ選び方になるようにする）。値は S0 で時間を測ってから決める。
- **辞書**: 除外表で絞った辞書を scratchpad に作り、`ikari-eval --dict <scratchpad の辞書> --set <TSV> --ranker full`（LM なしと LM あり）で流す。作り方は §7。**守る群は絞った辞書ではなく、ふつうの辞書で測る**（絞った辞書ではほかの読みの経路も変わるため）。
- **疑似と本物の差**: 疑似の未知語は、部分の語（バージョン など）が辞書に残るので、本物より分割の経路が見つかりやすい恐れがある（逆に、本物の方が難しい恐れ）。そこで、
  - 本物の数本（ばーじょにんぐ、しゃーでぃんぐ と、今後確認されたもの）について、今の main での「正解の順位」「1 位の経路のコスト ÷ 文字数」「1 位の経路の文節の数」「K6 の値」を、疑似の分布の分位点で表す。本物が疑似の分布の端に入るなら（どこからを端とするかは、ここでは決めない）、疑似は本物と似ていないとみなす。
  - 掃引でも、疑似の群の改善と、本物の数本の改善を並べて書く。**疑似が改善しても本物が改善しない点は採らない**。疑似の結果は、本物だけでは数が少なすぎるところを補うものとして使い、単独では決めない。

### 6.2 掃引の軸

- `per_char` と `base` の格子（範囲と刻みは S0 の分位点から決める）。0 / 0（今と同じ）を必ず含める。
- `katakana_like.strong_bonus` は 0 と今の既定（5000）の 2 通り。`weak_bonus` は 0 と、S0 で狙う群にだけ効きそうな値の 2〜3 通り（K1 の上なら弱い手がかりが効くかもしれないので、ADR 0020 §14 の結論を K1 の下で測り直す）。
- K6 を足すとき（§6.1 の条件を満たしたとき）: K1+K6a の閾値、または K1+K6b の関数の傾きを軸に足し、`katakana_like` を残すか外すかの 2 通りと組む。
- 構成: **LM なし**（`--ranker full`）と **LM あり**（`--ranker full --lm <zenz-v3.2 small の gguf> --lm-budget-ms 2000 --lm-deadline-ms 2000`。時間切れ 0 になるまで流し直す。snapshot と同じ）の両方。値は `--ranker-config <ファイル>` で渡す。

### 6.3 セットとコマンド

- 調整は dev だけで行い、test は採る値を決めたあとに 1 回だけ流す。
- 狙う群: `eval/sets/katakana-like.tsv`（`--split dev`）と、leave-one-out の TSV（§6.1.1。`--dict` に絞った辞書、`--split dev`。群は tags で分けて数える）。
- 守る群: `eval/sets/*.tsv` の全セット（snapshot が流すもの）と AJIMEE（`--set-format ajimee`）。各セットを、基準（今の main の `--out-cases`）と比べる。
  ```sh
  cargo run --release -p ikari-eval -- --ranker full --set eval/sets/<セット>.tsv --split dev \
    --ranker-config <格子の点>.kv --out-cases out/<点>/<セット>.tsv \
    --baseline base/<セット>.tsv --fail-on-regression
  # LM ありは --lm <gguf> --lm-budget-ms 2000 --lm-deadline-ms 2000 を足す
  cargo run --release -p ikari-eval -- compare base/<セット>.tsv out/<点>/<セット>.tsv   # 順位の差分
  ```
  採る候補が決まったら `eval/scripts/snapshot.sh --compare <基準>`（LM あり・なし、`--ajimee`）で全体を確かめる。
- ノイズの量: S0 の守る群の読み（Core の乱数抽出）で、「1 位がカタカナに変わった読み」と「最初の 3 件にカタカナが新しく入った読み」を数え、変わった読みから抜き出して目で見る。

### 6.4 評価セットに足すケース（2026-10-29 ユーザー承認）

`eval/sets/katakana-like.tsv` に kind `カタカナ語(分割負け)` を足す（split は既存の規則 FNV-1a64(id) % 5）。

- **狙う群（確定）**: しゃーでぃんぐ → シャーディング（sharding。2026-10-29 ユーザー確認: 自然な語で、期待はこのとおり）と、#100 の ばーじょにんぐ → バージョニング の 2 本（文脈なし、と文脈つき。文脈は公開の一般的な文にする。例「APIの」。ユーザーの実際の文は使わない。2026-10-29 ユーザー承認）。
- ろーかるじょにんぐ、でぃれくとりーぐ は**外した**（不自然な語なので。2026-10-29 ユーザー指摘）。
- 同じ型の候補を CLI で確かめた（2026-10-29。インストール済みの辞書、空のユーザーディレクトリ、`ikari --ranker cost --format tsv` と `ikari-eval --ranker cost / full`。full は LM なし）:

  | 読み | 期待 | 辞書の 1 語 | cost の順位（1 位） | full の順位 | 扱い |
  | --- | --- | --- | --- | --- | --- |
  | しゃーでぃんぐ | シャーディング | なし | 14（シャーDING = シャー + DING） | 1 | 狙う群（確定。2026-10-29 ユーザー確認: 自然な語、期待どおり） |
  | てざりんぐ | テザリング | あり（固有名詞、18608） | 5（てザリング = て + ザ + リング、14674） | 5 | K1 の対象外（辞書にある語が分割に負ける型。ADR 0035 の型に近い）。参考例としてセットに入れる（確定。2026-10-29 ユーザー承認。K1 では直らない型の見張り。改善の数には数えない） |

- **守る群に足す外来語**（kind `カタカナ語(辞書)`。辞書にある外来語が K1 で分割の経路に負けず 1 位のままかを見張る）: ろーからいず → ローカライズ、でぃれくとり → ディレクトリ（でぃれくとりー → ディレクトリー も同じく 1 位）、ふぁじんぐ → ファジング、ぱーてぃしょにんぐ → パーティショニング、ちゃんきんぐ → チャンキング。いずれも今 1 位（確認済み）。

### 6.5 採る・採らないの基準

- **不採用**: 既存のどのセット（LM あり・なし、dev・test、AJIMEE）でも、1 位が基準より悪化したケースが 1 件でも出た点（ADR 0020 §14 と同じ基準。2026-10-29 ユーザー決定。§10）。LM ありで時間切れが 0 にならない点は無効。
- **採る点の選び方**: 不採用でない点のうち、(1) 狙う群の dev の 1 位が最も多い、(2) 同じなら、ノイズ（§6.3 の 2 つの数）が最も少ない、(3) それも同じなら、`per_char` が大きい（効きが弱い）方。
- **K1 をやめる条件**: 不採用でない点で、狙う群の dev の 1 位が今より増えない（ばーじょにんぐ の 2 本がどちらも 1 位にならない）とき。そのときは K1 の効きと残る型を記録して、Q3（最初のページへの補助）、K5、K6 を次に考える。
- 結果は eval/reports に 1 本書き、索引（eval/reports/README.md）に足す。

1. S0（捨てるコードで分布を出す。researcher + code-editor）。結果をこの ADR に追記して、格子の範囲を決める。leave-one-out の準備は次のとおり（コードは足さない。2026-10-29 ユーザー決定）。

## 8. 懸念点

- K1 は「経路のコストがおおむね読みの長さに比例する」という見込みに立つ。S0 で 2 群の分布が重なれば、K1 だけでは分けられない。
- LM ありでは、カタカナが上がることで zenz が和語の候補よりカタカナを好む読み（ADR 0020 §14 の ぴかぴか → ピカピカ）が増える恐れ。擬音語の守る側で測る。
- 1 位の経路に 𥝱 のようなまれな字が出ること自体は直らない（(a) を採らないため）。K1 でカタカナが勝てば見えなくなるが、カタカナの読みでない語（和語の分割）で 𥝱 が出る型は残る。

## 9. ユーザーに聞くこと

- **Q1. 案 K1（読みの長さに比例するコストで、カタカナを分割の経路と競わせる）でよいか。** 推奨: はい。K2・K3（位置だけ上げる）は 1 位を取れず、どの読みでも最初の 3 件を 1 つ使う。
- **Q2. 不採用の基準を「既存の全セットで 1 位の悪化 0 件」（ADR 0020 §14 と同じ）にしてよいか。** 推奨: はい。0 件で採れる点がなければ、悪化したケースを並べてもう一度聞く。
- **Q3. 掃引で 1 位に届かない読みのために、カタカナを「最初のページ（9 件）の中」に入れる補助（K3 の弱い形）を足すか。** 推奨: 今は足さない。K1 の結果を見てから決める（どの読みでも 1 枠を取るので）。
- あわせて、§6.4 の評価セットの 3 点（2026-10-29 に提案どおりで承認。§10）: (1) ばーじょにんぐ の文脈つきのケースの文脈は公開の一般的な文（例「APIの」）にする、(2) てざりんぐ → テザリング を K1 では直らない参考例としてセットに入れる、(3) 守る側の「ぐ」で終わる動詞は 5 語（およぐ、いそぐ、つなぐ、ふせぐ、かつぐ）。しゃーでぃんぐ（狙う群）と ちゃんきんぐ（守る群）も確認済み。
- 残る問い: K6（§3.1）を K1 の上に足すかと、掃引の格子の範囲は、S0 の結果を見てから聞く。

## 10. 決定（2026-10-29 ユーザー承認）

- Q1: **K1 を採る**。
- Q2: 不採用の基準は「**既存の全セットで 1 位の悪化 0 件**」（LM あり・なし、dev・test、AJIMEE）。
- Q3: 最初のページ（9 件）への補助は**今は足さない**。K1 の掃引の結果を見てから決める。
- 追加: ユーザーの問い（辞書に入れずに外来語らしさを判定できないか）を受けて、K6（§3.1）を足した。S0 で分離を測り、分けられるときだけ掃引の軸に足す。LM に判定させる案（K7）は、LM は並べ替えにだけ使う決定に反するので採らない。
- leave-one-out（§6.1.1）を承認。辞書から外すのは CSV を絞るだけでコードは足さない。狙う群は読み 6 字以上、末尾 〜ング・〜ション・〜ジョン、分割の印なしと全体の両方で測り、同音の別表記は残す。
- §6.4 の評価セットの 3 点（ばーじょにんぐ の文脈つきは公開の一般的な文、てざりんぐ は K1 では直らない参考例として入れる、守る側の「ぐ」の動詞 5 語）を提案どおり承認。
- ADR 全体を承認（「それで良い。進めて」）。K6 の採否と掃引の格子の範囲は S0 の後に決める。

## 11. S0 の結果による訂正と、その後の決定（2026-10-29。測定は [katakana-s0](../../eval/reports/katakana-s0.md)）

**訂正**（上の §0〜§10 は決定の時点の記録として残し、ここで正す）

1. §0・§3 の K7 の行にある「LM はカタカナを 32 位のままにしている」は事実と違う。LM ありではカタカナの候補も並べ替えに掛かり、ばーじょにんぐ は 32 位 → 3 位、ぺねとれーしょん は 32 位 → 7 位に上がる。K1 の利益は、LM なし（または LM が時間切れ）では「32 位 → 1 位」、LM ありでは「3 位 → 1 位」で違う。
2. §6.4: しゃーでぃんぐ は今の main（`--ranker full`）で 1 位。K1 で直る本物の例は ばーじょにんぐ（文脈なしと文脈つき）の側に数える。
3. §6.1.1: 疑似の未知語 8698 件のうち、約半分（4434 件）は期待が辞書の語の連なりで出るので、K1 の対象外。K1 の対象は、主の群（同音の別表記が残る語を除く）で今 1 位でない **900 件**。homophone-left（2165 組）と、部分に英字の語がある型（今 1 位のうち 333 件）は本物より易しい。掃引の集計はこの 900 件を中心にする。「分割の印なし」は 2240 組（2243 ではない）。
4. §6.1: 「辞書の最小コスト ÷ 文字数」だけでは守る群と狙う群が重なる（AUC 0.775）。`base + per_char × 文字数` の K1 の形が要る（`per_char` だけでは 7.9%）。
5. 本物の未知語（ばーじょにんぐ）は、疑似の分布の端ではなく中央にある。K1 だけでは、疑似の約 900 件のうち、守る側を壊さずに直せる数に限りがある。辞書の語彙を増やす #113 とは補い合う関係にする。

**決定**（2026-10-29 ユーザー承認）

- 掃引は、**まず K1 だけ**で行う。K6 は S0 で条件（§6.1）を満たしたが、擬音語の誤りが残るので、K1 の結果を見てから軸に足すかを決める。
- LM ありの掃引は、疑似の未知語を FNV-1a64 の小さい順に **1000 件**に絞る（約 1.3 分）。LM なしは全件。絞った点だけ、LM ありでも全件で確かめる。
- 格子の範囲は S0 報告 §8 を出発点にする。既定値は、掃引の結果を示してユーザーに確認してから決める（計測していない値は入れない）。
- 辞書の語彙を増やす方針は、別の issue #113 で進める。
