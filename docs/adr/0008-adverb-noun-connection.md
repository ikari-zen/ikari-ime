# ADR 0008: 副詞の直後の名詞を、同じ読みを1語で覆う名詞があるときだけ重くする（変換のラティスの辺の補正）

- 状態: 承認（2026-10-13。§11.1 を参照）
- 日付: 2026-10-13
- 対象: core のラティス（前向き Viterbi）と N-best（後ろ向き A*）。変換だけで、文脈の解析と取り込みのアライメントは変えない
- 前提: main = f9ebf3a。ADR 0001 §4.6（ラティス、Viterbi、A*）、ADR 0002 §4（辞書のポリシー）・§22.2（`frequent_compound`）、ADR 0006 §2〜§4・§9（文節、区切り直し、再変換）。
  原因の測定は `eval/reports/phase3-suffix.md` §2.2・§3.2（`fix/suffix-ka` のブランチ。この時点で main には未マージ）。
  ユーザーの承認「副詞の直後の名詞を、変換のときの規則で扱う（案 C）で設計する」。スパイクの数値は [phase3-adverb-noun.md](../../eval/reports/phase3-adverb-noun.md)

## 0. 現状の把握

### 0.1 現象と原因（測った値）

| 入力 | 1位（経路のコスト） | 期待（コスト） | 原因の経路 |
| --- | --- | --- | --- |
| そうじき | そう時期（3254） | 掃除機（5952） | そう（副詞 4066）+ 時期（名詞,副詞可能。語のコスト **-372**） |
| こうはん | こう班（6903） | 後半（7907） | こう（副詞 4167）+ 班 |
| そうおん | そうオン（6654） | 騒音（9145） | そう + オン |
| もうふ | もう府（5765） | 毛布（9244） | もう（副詞 3194）+ 府 |
| こうかそくてい | こうか測定（13407） | 効果測定（14203） | こう + か（副助詞）+ 測定。区切りの評価 seg-stretch-16 も こうか／そくてい に分かれる |
| こうぞうか | こう増加（9331） | 構造化 | こう + 増加（BOS → 副詞 -1304、副詞 → 名詞 +695） |

- 指示副詞 こう・そう・どう（4066〜4200）と もう（3194）は、ひらがな2文字の副詞の中で飛び抜けて安い。副詞から名詞への連接も +263〜+695 と小さい（「もっと前」「ちょっと時間」のような正しい並びがあるため）。
  その結果、漢語の読みの頭（こう、そう、どう、もう）を副詞で切る経路が、1語の漢語より安くなる。
- Sudachi の副詞（品詞1 = 副詞、7483 行）は、7038 行が左右ID 5 で、残りもほとんどが 4、6、7、8 を共有している。**連接表の上では、副詞はほぼ1つの品詞**で、連接表の値を変えることは「すべての副詞 → 名詞」に一律に足すことと同じになる（§8 の案 B5）。

### 0.2 辞書のポリシーでは直せない
- ポリシー（ADR 0002 §4）は語ごとの加算だけで、並びは表せない。`fix/suffix-ka` のレーンが試した `short_kana_adverb`（ひらがな2文字以下の副詞 374 件に加算）は、セットでは +6000 まで悪化がなかったが、セットにない自然な入力で崩れた:
  +1000 で すぐ → す‐ぐ、+2000 で つい → 付い、どうも → 道も、こうかな → 高価な、+3000 で どう → 道、+5000 で そうですね → 層ですね。
- 副詞そのものは正しく安い語で、悪いのは「副詞の直後に名詞」という並びの方。
- 掃除機 には `frequent_compound`（-8000）がすでに当たっている。それでも 時期 の語のコストが負（-372）なので、そう時期 に 2698 負ける。`frequent_compound` をさらに下げると区切りの F1 が崖を越える（phase3-compound で -12000 から F1 が下がった）。

### 0.3 コードの現状（設計に効く事実）
- 変換の連接コストを足しているのは `core/src/lattice.rs` の `build_inner`（前向き Viterbi。BOS からの辺と、ノードの間の辺）と、`core/src/nbest.rs` の `NBest::next`（後ろ向き A*。ノードの間の辺）と `NBest::with_end`（EOS への辺）だけ。どちらも `grammar.connection_cost(prev.right_id, next.left_id)` を直接呼ぶ。
- ラティスを作るのは、読み全体の変換（`Converter::convert_until`）、文節ごとの候補と区切り直し（`converter/segment.rs`。`build_with_starts` と `build_constrained`）、再変換の読みの分割（`converter/reconvert.rs`）の3か所で、すべて `lattice.rs` の同じ関数を通る。
- `Node` は `pos_id`、`cost`（`cost + penalty`）、開始と終了の位置を持つ。品詞名は `grammar.pos_name(pos_id)` で引ける。
- 文脈の解析（`analysis/lattice_analyzer.rs`）と取り込みのアライメント（`import/src/align.rs`）は、別のラティスで `connection_cost` を呼ぶ。どちらも書かれた表記を解析するもので、この問題は起きない。

| 項目 | 決定 |
| --- | --- |

## 2. 規則

### 2.1 定義
変換のラティスの、ノードの間の辺 `prev → next` に、次をすべて満たすとき `P`（既定 6000）を足す。

1. `prev` の品詞1 が **副詞**。表記（ひらがな、漢字、カタカナ）も読みの長さも問わない。
2. `next` の品詞1 が **名詞**。普通名詞（一般、サ変可能、副詞可能、形状詞可能、助数詞可能）、固有名詞、数詞、代名詞ではない名詞をすべて含む。
3. ラティスに、**`prev` の開始位置から `next` の終了位置までをちょうど覆う、辞書の名詞のノード `W`** がある。`W` の品詞1 は名詞で、変換用のコスト（`cost + penalty`。ポリシーの `lemma_rank` や `frequent_compound` を含む）が `C`（既定 10000）以下。

- 未知語のノードは、`prev` にも `next` にも `W` にもならない。ユーザー辞書の語は、品詞が合えば `prev`、`next`、`W` のどれにもなる。
- BOS からの辺（左文脈の最後の語 → 最初の語）と EOS への辺には足さない。覆う名詞が、ラティスの外（左文脈や右の文節）にまたがることはないため。
- 1回の変換（1つのラティス）の中だけで働く。こまめに確定して「そう」を確定したあとに「じき」を打てば、時期 のまま（左文脈の そう は BOS で、条件 3 が成り立たない）。

### 2.2 なぜこの形か
- **並びを重くし、語は重くしない**: 副詞だけの入力（すぐ、どうも、どう）、副詞 + 用言（そうですね、こうなる、そう思う）、副詞 + 助詞（どうも）は、条件 2 に当たらないので変わらない。語ごとのペナルティ（§0.2）で崩れたものは、すべてここで守られる。
- **副詞を表記で絞らない**: ひらがなの表記の副詞にだけ足すと、同じ副詞の漢字の表記（可成、丁度、一寸、先ず、随分、取り敢えず）が加算を受けずに1位に上がった（スパイクの案 B1。かなり前 → 可成前、ちょうど今 → 丁度今）。公用文の表記（ADR 0002 §22.1）を崩すので、副詞は品詞だけで決める。
- **1語で覆う名詞があるときだけにする**: 並びに一律に足すと（スパイクの案 B2〜B4）、掃除機 を1位にするのに要る値（そう時期 との差 2698 を超える値）で、正しい 副詞 + 名詞 が別の不自然な分割に負けた。正しい並びとその次点の差は、是非今度 1958（→ 是非込んど）、もう深夜 2435（→ もう死んや）、もう午後 1168（→ もう御語）しかない。
  副詞 + サ変名詞 + する（どう対処する、こう表現する）も +2500〜+3000 で 道対処する、高表現する に崩れた。**一律の加算には、直したい入力だけを動かす値の幅がない**（スパイクの §3）。
  条件 3 は「その2語を、ふつうに使う1語の名詞として読める」ことで、誤りの形（そう＋時期 と 掃除機、こう＋班 と 後半、もう＋府 と 毛布）をそのまま表している。もう一度、是非今度、もう深夜、どう対処する のように1語で覆う名詞がない並びには、何もしない。
- **覆う名詞のコストに上限を置く**: 上限がないと、まれな名詞（光周性 11854、公衆性 11815、地名の 蒙疆）が「覆う名詞」になり、こう修正する → 高修正する が崩れた。上限 `C` は「ふつうに使う名詞か」の代わりで、変換用のコストには chiVe の頻度による加算（`lemma_rank`）と `frequent_compound` が入っている。
- **加算は大きめの一定値**: 覆う名詞があるときだけ働くので、+4000〜+20000 で結果が同じだった（スパイクの §4.1）。+3000 では 毛布 が直らない（もう府 との差が足りない）。平坦な範囲の手前寄りの +6000 にする。
- **名詞の品詞2 で絞らない**: サ変可能を外すと、こう＋増加、どう＋使用 のような同じ型の誤りが対象から漏れる。条件 3 がある形では、サ変可能を含めても どう対処する は崩れなかった（覆う名詞がない）。

### 2.3 副助詞 か を挟む形（こうかそくてい）は含めない
- こう（副詞）+ か（副助詞）+ 測定 は、2語の辺（副詞 → 名詞）にならない。同じ条件で「副詞 → 副助詞 か」の辺にも足す形を測った。区切り（seg-stretch-16）は直る（segments 143 → 144、F1 0.989 → 0.994）が、**1位は 硬化測定**（13865）で、効果測定（14203）ではない。
- 覆う名詞のコストの上限の幅が 9500〜10000 しかなく、10500 で そうかもしれない → 層かもしれない に崩れた（そう＋か を 層化 などが覆う）。名詞の辺だけなら 9500〜12000 で同じ結果になる。
- 効果 と 硬化 の区別は話題か LM の仕事で、区切りだけのために幅の狭い規則を足す利点は小さい。**推奨: 入れない**（§11-3）。

## 3. 置き場所: ラティスの辺のコスト

### 3.1 形
- `core/src/lattice.rs` に、辺の追加コストを返す関数を1つ置く: `Lattice::edge_extra(&self, prev: &Node, next: &Node) -> i32`。
  `build_inner` の前向きの辺（`prev.best + connection_cost + edge_extra`）と、`NBest::next` の後ろ向きの辺（`g + node_cost + connection_cost + edge_extra`）の**両方が同じ関数を呼ぶ**。
  - 前向きの `best` と後ろ向きの `g` に同じ値が入るので、A* のヒューリスティック（前向きの `best`）は今と同じく正確で、パスはコストの昇順に出る（ADR 0001 §4.6-5 の性質を保つ）。
  - BOS からの辺と EOS への辺（`NBest::with_end`）は変えない。
- **品詞の分類の表**: 品詞IDごとに「副詞か」「名詞か」を1バイトで持つ表を、`Converter` の組み立てのときに1度だけ `grammar.pos_name` から作り、`Arc` で共有する（ラティスを作るたびに品詞名の文字列を比べない）。`Grammar` トレイトは変えない。
- **覆う名詞の表**: `build_inner` が、開始位置ごとに「品詞1 = 名詞で、コストが `C` 以下の辞書のノードの終了位置」を記録する（開始位置ごとの小さな `Vec<u32>`）。前向きでは、位置 `i` のノードへの辺を計算するときに、`prev.start < i` の表はできあがっている。
  `edge_extra` は、`prev` が副詞で `next` が名詞のときだけ、`cover_ends[prev.start]` に `next.end` があるかを調べる。ほとんどの辺は品詞の表を1回引くだけで終わる。
- `build_constrained`（区切り直し）は境界をまたぐノードを作らないので、境界をまたぐ覆う名詞は表に入らない（§4.3）。

### 3.2 値の持ち方
- `ConvertOptions` に `adverb_noun: AdverbNounRule { penalty: i32, cover_max_cost: i32 }` を足す（既定 6000 と 10000。`penalty == 0` なら止める）。`Converter` の組み立てで品詞の表と一緒に保持し、`lattice::build_*` に渡す。
- `stack`（`build_stack`）は、`--ranker-config` と同じ key=value のファイルから `lattice.adverb_noun.penalty` と `lattice.adverb_noun.cover_max_cost` を読んで上書きする（評価で値を振るため）。設定アプリには出さない。
- `ConvertOptions` を構造体リテラルで作っているテスト（`converter/tests.rs`）は `..Default::default()` に直す。

### 3.3 Ranker との関係
- 候補の `base_cost`（パスのコスト）に加算が入るので、CostRanker と、`base_cost` を使うすべての Ranker が同じ値を見る。`--ranker cost` の評価にも効く。
- LeftContextRanker（BOS の連接）、KanaStyleRanker、学習、話題、LM の採点は変えない。

## 4. N-best と文節モード（ADR 0006）との整合

### 4.1 N-best
- 加算した経路は消えない。N-best の後ろに下がるだけで、ユーザーは候補から そう時期 を選べる（基本原則「選択肢を制限しない」）。読みに対応しない文字は足さない（基本原則 1.1）。
- 学習（LearningRanker）が過去の選択（そう時期）を上げることは止めない（基本原則 1.2。学習は score で働く）。

### 4.2 最初の区切りと不変条件
- 区切りは今どおり、Ranker が1位にした候補の語の並びから作る（ADR 0006 §2.1）。この規則は1位の候補を変えるだけなので、「文節をつないだもの = 1位」の不変条件はそのまま保たれる。
- スパイクで、規則を入れた状態で実辞書のテスト（`core/tests/segment_real.rs` の 5 件。1位の表示の保持、区切り直しで読みと左の文節が変わらない、助詞のあとの用言、再変換の表示の保持）を流し、すべて通った。複数文節になったケースは 1565 件中 115 → 114（そう時期 のような2文節が、1語の名詞になった）。

### 4.3 文節ごとの候補と区切り直し
- 文節ごとの候補（ADR 0006 §3.1）は、その文節の読みだけのラティスを同じ関数で作るので、文節の中では同じ規則が働く。文節の境界をまたぐ 副詞 → 名詞 には働かない（BOS と EOS の辺は対象外。覆う名詞もその文節のラティスの外になる）。
- 区切り直し（`build_constrained`）は、ユーザーが決めた境界をまたぐノードを作らない。ユーザーが そう｜じき に区切れば、掃除機 は覆う名詞として表に入らず、そう＋時期 に加算しない。**ユーザーの区切りが規則より優先される**。

### 4.4 再変換
- 再変換の読みの分割（`converter/reconvert.rs`）は、N-best から表記が一致するパスを探す。規則で順位が下がっても、`max_astar_pops` の範囲で見つかる。スパイクで、再変換の読みの推定の一致率は 1565 件中 1499 件（95.8%）で変わらなかった。

## 5. 速さ

スパイク（品詞名の文字列をノードごとに比べる、本実装より重い作り）で、同じバイナリで規則を切り替えて直列に測った。コンテナの計測の揺れは ±0.3ms ある。

| 計測 | 規則なし | 規則あり |
| --- | --- | --- |
| ikari-eval の warm（ext、katakana、hiragana を 3 回ずつ。平均） | p50 0.108ms / p99 0.424ms | p50 0.118ms / p99 0.432ms |
| 文節の1ページ目（2文節以上の先頭） | p99 0.207ms | p99 0.214ms |
| 区切り直し | p99 0.689ms | p99 0.784ms |
| 再変換のあとのページ | p99 0.389ms | p99 0.406ms |

- 本実装は品詞の表を引くだけなので、これより軽い。目標（エンジン内 p99 2ms。ADR 0006 §10.1）を大きく下回る。
- メモリ: ラティスごとに、開始位置ごとの小さな配列（読みの文字数 + 1 個）が増える。

- 実辞書: snapshot で、基準との差が §6.1 のケースだけであること。`segment_real` の不変条件と性能。
- **自然な入力のセット**: スパイクの 174 件のうち、副詞だけ、副詞 + 用言、正しい 副詞 + 名詞、こう／そう／どう／もう で始まる漢語を、評価セット `eval/sets/adverbs.tsv`（仮）にする。今のセットには副詞だけの入力や 副詞 + 用言 の入力がなく、語ごとのペナルティの崩れ（すぐ → す‐ぐ）をセットで見つけられなかった（phase3-suffix §6）。正解はユーザーの確認が要る（§11-5）。

## 7. 失敗のしかた（既知の限界）

1. **1語で覆う名詞がよく使う語でも、2語の並びが意図のことがある**: どうし は どう市 が消えたが、1位は どうし（副詞 + サ変の し）で、同士 と 同市 は 2〜3位。意図した 副詞 + 名詞 を、覆う名詞が上回る例は、スパイクの 174 件では見つかっていない（もう一度、もう時間、まだ時間、ほぼ全部、是非今度 などは覆う名詞がない）。見つかったときは、学習（選び直し）で直る。
2. **上限 `C` は辞書のコストの代わりで、辞書を作り直すと誰が「覆う名詞」かが動く**: たとえば `fix/suffix-ka` の `frequent_compound` の上限の変更（3 万 → 4 万位）で 構造化 のコストが下がり、覆う名詞になる（こうぞうか はそのレーンの変更で直る）。ポリシーを変えたら、評価セットと自然な入力のセット（§6.2）で取り直す。
3. **副助詞 か を挟む形（こうかそくてい）は直らない**（§2.3）。
4. **副詞 + 用言の誤った分割は対象外**: 基準から誤っている もう行っ海、ただ行っ海、なお行っそう、ずっと行っしょ、とても来れい、どう来、もう仕分けない、同省もない、まだ見てい、また来襲 は、読みの短い動詞の連用形（行っ、来）が安いのが原因で、別の課題（§11-6）。（原因は ADR 0010 で訂正: 本動詞の漢字の加点が区切りの選択に効いていた。）
5. **名詞でない語への逃げ道**: もうふ の2位に もう府 11038 が残るのは、府 を 接尾辞 として読む経路（副詞 → 接尾辞）で、加算を受けない。同じく 副詞 → 接頭辞 → 名詞（ほぼ＋全＋イン）も対象外。一律の加算（スパイクの B 系）では、こうした逃げ道が1位に上がった。条件 3 の形では、覆う名詞が安いので、逃げ道は1位にならなかった。
6. **LM の効き方は測っていない**（このコンテナにモデルがない）。LM は並べ替えだけなので、プールに入る候補は規則で決まる。LM ありの評価は本実装のあとに取る。

## 8. 検討した案

- **案 A: 語ごとのペナルティ（`short_kana_adverb`、レーンの案）**: §0.2。副詞だけの入力と 副詞 + 用言 が崩れる。**採らない**。
- **案 B1〜B4: 「副詞 → 名詞」の辺に一律に加算（ラティス）**: スパイクの §3。副詞をひらがなの表記で絞る（B1）、すべての副詞（B2）、読み2文字以下（B3）、サ変可能の名詞を外して接頭辞を足す（B4）を測った。どれも、掃除機 を直す値で正しい並びが崩れる（是非今度、もう深夜、どう対処する、ちょうど今 など）。**採らない**。
- **案 B5: 辞書を作るときに連接表（matrix.def）の副詞の行を書き換える**: 副詞は右ID 4〜8 をほぼ全員で共有しているので、B2 と同じ一律の加算になり、同じ理由で崩れる。条件 3（覆う名詞）は連接表では表せない。**採らない**。
- **案 D: 同じ条件を Ranker で見る（候補の語の並びに 副詞 + 名詞 があり、2語の読みを `lookup_exact` で引いて安い名詞があれば score に加算）**: 実装はラティスに触れずに済み、`--ranker-config` で切り替えやすい。しかし、
  1. Ranker は最初のプール（30 件）の並べ替えしかできない。副詞の表記ゆれ（そう、然う、ソウ）と名詞の表記ゆれの組み合わせでプールが埋まると、覆う名詞の候補がプールに入らない。
  2. N-best の順（2ページ目以降、文節ごとの候補、再変換の探索）と、1ページ目の順が食い違う。ラティスで扱えば、どの経路でも同じコストになる。
  3. `--ranker cost` の評価や、Ranker を通らない処理（再変換の読みの分割）には効かない。

  **採らない**。ラティスの方が、Sudachi の連接コスト（解析用に作られた値）を変換のために補正する、という性質に合う。
- **案 E: 覆う名詞の側に加点する（掃除機、後半、毛布 を安くする）**: 語ごとの加点で、単独の入力（そうじき の前後に何もない場合）以外にも効いてしまう。`frequent_compound` の強化は区切りの F1 の崖に近い（§0.2）。**採らない**。
- **案 F: LM（zenz）に任せる**: LM は並べ替えだけで、プールに入った候補にしか効かない（ADR 0003）。LM の待ち時間に間に合わないとき（先行計算のない Convert、区切り直し）は効かない。規則で直る形は規則で直す。
- **案 G: 副助詞 か を挟む形も同じ規則に入れる**: §2.3。値の幅が狭く、1位は 硬化測定 にしかならない。**採らない**（§11-3）。

## 11. ユーザーの判断が要る点

1. **規則の形**: 「副詞の直後の名詞に加算する。ただし、同じ読みの範囲を1語で覆う、よく使う名詞があるときだけ」（§2.1）でよいか。一律の加算（案 B）には値の幅がなかった。**推奨: この形で入れる**。
2. **値**: 加算 +6000、覆う名詞のコストの上限 10000。加算は +4000〜+20000、上限は 9500〜12000 で同じ結果だった。**推奨: この値**（加算は平坦な範囲の手前寄り、上限は範囲の中で か の辺を後から足す余地がある値）。
3. **こうかそくてい（副詞 + か + 名詞）を含めるか**（§2.3）: 含めると区切りの評価は 1 件直るが、1位は 硬化測定 で、上限の幅が 9500〜10000 と狭い。**推奨: 含めない**。効果 と 硬化 は話題か LM で扱う。
4. **値を変えられる範囲**: `ConvertOptions` と、評価用の `--ranker-config` のキーだけにし、設定アプリには出さない。**推奨: この案**。
5. **自然な入力の評価セット**（§6.2）: スパイクの 174 件から `eval/sets/adverbs.tsv` を作り、正解をユーザーが確認する（docs/tasks.md の A2 に足す）。**推奨: 作る**（同じ型の規則の副作用を、セットで早く見つけるため）。
6. **副詞 + 用言の誤った分割**（§7-4。もう行っ海、とても来れい など）を、別のタスクとして docs/tasks.md の B に積むか。**推奨: 積む**（この ADR の範囲外。原因は動詞の連用形の安さ）。

### 11.1 決定（2026-10-13 ユーザー）
上の 1〜6 は、すべて推奨のとおりに承認された。
1. 規則は §2.1 の形（覆う名詞があるときだけ）で入れる
2. 値は加算 +6000、覆う名詞のコストの上限 10000
3. 副詞 + か + 名詞（こうかそくてい）は含めない
4. 値は `ConvertOptions` と評価用の `--ranker-config` のキーだけで変える。設定アプリには出さない
5. `eval/sets/adverbs.tsv` を作り、正解をユーザーが確認する（docs/tasks.md の A2）
6. 副詞 + 用言の誤った分割は、別のタスクとして docs/tasks.md の B に積む

実装は §10 のとおり、1 つのレーンで行う。`fix/suffix-ka`（`frequent_compound` の順位の上限）が main に入ったあとで測り直す。

## 13. 名詞 → 接尾辞 の辺への拡張（2026-10-15。B25、ブランチ `feat/b25-noun-suffix-edge`）

ADR 0011 §4.2 の副産物（案 B を上限 10000 で 名詞 → 接尾辞 の辺に広げると、低数名 → 定数名、層等 → 相当、会等 → 回答 が直る）を、別のタスク B25 として入れた。

### 13.1 広げた条件
- 辞書のノード N（品詞1 = 名詞）→ 辞書のノード S（品詞1 = 接尾辞）の辺に、N の開始位置から S の終了位置までをちょうど1語で覆う名詞（品詞1 = 名詞、変換用のコスト `cost + penalty` が上限以下）があるときだけ、`penalty` を足す。BOS と EOS の辺、未知語、接頭辞 → 名詞、副詞 → 接尾辞 には足さない。
- 値は §2.1 と同じ（加算 +6000、上限 10000）。別の規則 `NounSuffixRule`（`ConvertOptions::noun_suffix`）にして、`--ranker-config` の `lattice.noun_suffix.penalty` と `lattice.noun_suffix.cover_max_cost` で変える（0 で止まる。設定アプリには出さない）。副詞の規則の値とは独立。

- テスト: `lattice.rs`（接尾辞の分類、覆う名詞があるときだけ、名詞 → 接尾辞 だけが対象で 名詞 → 名詞・接頭辞 → 名詞・動詞 → 接尾辞 は対象外、上限ちょうどと +1 の境界、名詞でない覆う語、設定での変更と停止、規則ごとに別の上限、表の有無）、`options.rs`（既定値とキー）、`stack/src/tests.rs`（設定の読み込み）。

### 13.3 B25 で直らなかったもの
- **ていすうめい の 低数名 → 定数名（B17）は直らない**。今の Full では 低数名 は 低（接頭辞）＋ 数 ＋ 名（名詞 助数詞可能）の 3 語で、名詞 → 接尾辞 の辺がない。スパイク（Core）の分割とは違う。接頭辞 → 名詞 の辺まで広げるのは、ADR 0011 の測定で逃げ道に流れる（接頭辞の側）と分かっているので、ここではやっていない。
- **そうとう（文脈なし）は そう等 のまま**。分割は 副詞 そう ＋ 接尾辞 等 で、前が名詞でないので当たらない。adverbs.tsv の adv-kango-48（文脈あり）は、文脈の側の候補が変わって 相当 が1位になった。副詞 → 接尾辞 の辺に広げる案は、悪化の有無を測っていないので、入れていない。
- B19 の熟語には、ADR 0011 §4.2 のとおり、ほとんど効かない。
