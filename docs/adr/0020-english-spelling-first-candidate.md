## 0. ユーザーの決定（2026-10-15〜16。変えない）
1. 原因は Sudachi の辞書のコスト（同じ語で、英字 5000、カタカナ 15000）。
2. **辞書のコストの入れ替えではなく、規則にする。英字（ASCII の英字）が1位に来る場合のみ、カタカナ（読みをそのままカタカナにした表記）を繰り上げて1位に強制する。英字は消さず、2位以下に残す。**
3. 単語として読む略語・社名（NASDAQ → ナスダック、JICA → ジャイカ、JAL → ジャル）も対象。
4. 「全てのケースでカタカナを優先」。混ざった表記、直前に英字を確定した場合の LM による英字の1位戻し、正規化表記で結ばれない組（ようこ → YOKO、Gmail、ChatGPT）も含める。
5. 未決（実測してから聞く）: (i) 英字を1回選んだあとも強制するか、(ii) 文字の名前の読み（URL、ABC）と数詞・単位を対象にするか、(iii) 規則を置く場所と、LM が英字を1位にしたときの扱い、(iv) 英字が正しい語が2位以下に下がる数。§10 で聞く。

## 1. 現状の把握（測った値。断りがなければ LM なし、`--ranker full`、ユーザーディレクトリは空）

### 1.1 再現と原因（初版の調査。今の main でも同じ）
- はるしねーしょん: 1 Hallucination（経路 14170）、2 春市ネーション、…、7 ハルシネーション（21170）。
- 学習・語彙集・LM が原因ではない（空のユーザーディレクトリ、`--no-packs`、`--ranker cost` でも Hallucination が1位）。Core の2行（Hallucination 5000、ハルシネーション 15000。正規化表記はどちらも ハルシネーション）の差 10000 を、ポリシー `ascii_other`（+3000）が埋めない。
- 文の中でも同じ: 文脈「LLMの」+ はるしねーしょんがおきる → 1 Hallucinationが起きる。

### 1.2 同じ型の広さ（今回、範囲を広げて測り直した）
- 方法: Sudachi（small、core、notcore）の行のうち、表記に ASCII の英字を含み、読みがカタカナだけの行の読み（30 字以下）をすべて集めた（**108,796 読み**。初版は「同じ読みに読みのカタカナの行もあるもの」に絞って 78,243 読み）。それぞれを単独で変換し、1位を数えた。
- 今の main: **1位が英字を含む 35,963 読み**、1位が読みのカタカナ 55,539 読み。

  | 英字の行の出どころ / 表記 | 読み | 1位が英字を含む |
  | --- | ---: | ---: |
  | small / 英字だけ | 4,887 | 2,405 |
  | small / 混ざった表記 | 110 | 19 |
  | Core / 英字だけ | 32,184 | 1,549 |
  | Core / 混ざった表記 | 1,218 | 837 |
  | notcore / 英字だけ | 61,047 | 26,268 |
  | notcore / 混ざった表記 | 9,350 | 4,885 |

- 1位が英字のうち、表記の各文字を名前で読む読み（ゆーあーるえる → URL、えーびーしー → ABC）は small と Core の英字だけの表記で約 2,700 読み、全体で約 8,600 読み（§4.2。初版の「約 1,100」は 78,243 読みの中の数）。

### 1.3 LM による英字の1位戻し（ADR 0021 §2.3 の件）
- new-words（71 件）の1位は LM なし 61、**LM あり 50**。下がった 17 件は、IT の語彙集の語（カタカナ1位・英字2位）で LM が英字を1位にしたもの（くばねてぃす → Kubernetes、りなっくすのかーねる → Linuxのカーネル など）。**左の文脈が空でも起きる**（読みだけで LM が英字を推す）。
- 語彙集のシナリオ it-pack を LM ありで流すと、main で失敗 4（ADR 0021、初版 §5.4）。同じ原因。
- ADR 0021（B36）で LM が付く変換を増やすと、この害も同じだけ増える。

### 1.4 ユーザーの実機の学習（読むだけ。件数と型だけ数えた）
- `learning.tsv` の文脈なしの記録（Unconditional）は、句の確定 1,257 回（889 種）。そのうち表記に英字を含むものは **Hallucination の 2 回**だけ（ほかは打ちかけの b が 2 回）。カタカナを含む句は 199 回。
- 同じ読み はるしねーしょん に ハルシネーション 3 回もある。ユーザーは日本語の入力で英字の表記をほとんど確定していない（英語は ABC で打つ。ADR 0005 §15.2）。
- 今の main では、同じ回数（Hallucination 2、ハルシネーション 3）を確定しても ハルシネーション は**5位のまま**（シナリオで再現。§4.5）。

### 1.5 今の候補の流れ（規則を置く場所の判断に使う）
- `Conversion::build_first_pool` が辞書の候補（`pool_size` 件）、Rewriter、読みのひらがな・カタカナを1つの塊にし、`CompositeRanker` で順位を付けて並べる。1位はこの最初の塊で決まり、後のページは足すだけ（表示済みのページは変えない。NFR-05）。
- `CompositeRanker` の並びは 左文脈 → かなの表記 → 文書内キャッシュ → 学習 → プロファイル → 話題 → LM。GrammarGuard と LearningGuard は話題・学習の直後に働き、**LM は Guard の後で、制限されない**（ADR 0013 §0.1）。
- 文節のモード（ADR 0006）の各文節の先頭は、読み全体の1位の分割から作る。再変換も同じ `Conversion` を使う。
- 読み全体のカタカナの候補は、いつも最初の塊にある（`CandidateOrigin::Katakana`）。文の中の1語（ハルシネーションが起きる）は、辞書の経路にしかなく、最初の塊に入るとは限らない。

## 2. 問題の定義
- 大方針は「ユーザーの書いた言葉を尊重する」（user-feedback.md §1.1）。カタカナで読みを打ったら、まずそのカタカナを出す。英字は2位に置き、選べるようにする。
- 英字が1位に来る経路は3つあり、**どれか1つを直しても残る**:
  1. **辞書のコスト**（Sudachi の英字の行が安い）。単独の読みでも文の中でも起きる（§1.1、§1.2）。
  2. **LM**（zenz が英字を推す）。辞書でカタカナが1位でも、LM が付くと英字に戻る（§1.3。new-words で 17 件）。LM は Guard の後に働くので、今の仕組みでは止まらない。
  3. **学習**（英字を確定した記録）。これはユーザーの選択なので、扱いはユーザーが決める（Q1）。
- 初版の案 S-P（辞書のコストの入れ替え）は経路1しか直さない。LM ありの it-pack の失敗 4 も、new-words の 61 → 50 も残る（初版 §5.4）。ユーザーが規則にしたのはこのため。
- 制約: 読みに対応しない文字を足さない（読みのカタカナは読みそのもの。§3.2 の混ざった表記の置き換え先も同じ読みの辞書の語）。候補を消さない（英字は2位に残す）。表示済みのページは変えない（NFR-05）。既存の評価を崩さない。

## 3. 規則（案 F。提案）

### 3.1 一言で
**候補の最初の塊を、LM まで含めて全部の Ranker で並べた後、1位の候補が「英字の語」を含んでいれば、その英字の語を置き換えた候補を1位にする。英字の候補は2位になる。** ほかの候補の順は変えない。

### 3.2 条件
- **英字の語**（規則の対象）: 1位の候補の分割の中の1語で、次をすべて満たすもの。
  1. 辞書の語（未知語、Rewriter の候補、かなの候補は対象外）。
  2. 表記に ASCII の英字を1文字以上含み、読みに英字を含まない。
  3. 表記が ASCII の文字だけ（Hallucination、Google、NASDAQ、Mark Zuckerberg、COVID-19）か、日本語との混ざった表記（X線、Tシャツ。ユーザーの決定 4）。
  4. 例外（§3.3）に当たらない。
- **置き換え先**:
  - 英字だけの表記 → **読みをそのままカタカナにした表記**（Hallucination → ハルシネーション、TAKO → タコ、YOKO → ヨウコ、Gmail → ジーメール）。同じ読み・同じ表記の語が辞書にあれば、その語として扱う（品詞と語ID。学習と文脈の解析がその語を引ける）。なければ英字の語の品詞のまま、辞書にない語として扱う。
  - 混ざった表記 → **同じ読みで、Sudachi の正規化表記が同じ（同じ語）、表記に英字を含まない辞書の語のうち、コストの最も安いもの**（X線 → エックス線、Tシャツ → ティーシャツ。ティーシャツ の正規化表記は Tシャツ なので、正規化表記そのものではなく「同じ正規化表記を持つ語」で結ぶ）。読みのカタカナ（エックスセン）にはしない。そういう語が辞書になければ対象にしない（BMI値、JR高島屋、交通系ICカード は英字のまま。Q5）。
  - 置き換え先は、どれも同じ読みの表記なので、読みに対応しない文字を足さない（user-feedback.md §1.1）。
- **1位の判定**: LM を含む全部の Ranker と Guard の後のスコアで1位の候補。
- **繰り上げ方**: 置き換えた候補（同じ表記の候補が塊にあればそれ、なければ §3.4 で足したもの）のスコアを、1位のスコア − 1 にする。英字の候補は2位になる。

### 3.3 例外（英字のまま1位に残すもの）
| 例外 | 例 | 理由 | 決めること |
| --- | --- | --- | --- |
| E1 文字の名前の読み | ゆーあーるえる → URL、えーびーしー → ABC、ぴーしー → PC、えーあい → AI | ユーアールエル と書く人はいない。語彙集の形 `latin` と同じ考え（ADR 0012 §4.2） | Q2 |
| E2 品詞が 数詞・助数詞可能 | きろめーとるまいじ → km/h、めーとるまいびょう → m/s、IV | キロメートルマイジ にはしない | Q2 |
| E3 英字だけを出すと決めた語 | 語彙集の形 `latin`（まいえすきゅーえる → MySQL、えーだぶりゅーえす → AWS、えんじんえっくす → nginx）、ユーザー辞書に英字だけで登録した語 | ユーザーが確認・登録した表の決定（ADR 0012 §4.2）。判定は「その語の辞書（語彙集、ユーザー辞書）に、同じ読みのカタカナの項目がない」 | なし（決定済みの表に従う） |
| E4 学習（Q1 で決める） | 1回 Kubernetes を選んだ後の くばねてぃす | §3.5 | Q1 |
- E1 の判定は、表記の英字・数字を1文字ずつ名前（えー／えい、びー、しー、…、ぜっと、数字は わん／いち など）で読んだ読みと一致するか（表はコードに固定。初版と同じ考え）。一部だけ文字の名前の語（ChatGPT = ちゃっと + じーぴーてぃー、CD-ROM、SDGs）は E1 に入らない（Q2）。

### 3.4 置き換えた候補を最初の塊に足す
- 1位が文の候補（Hallucinationが起きる）のとき、置き換えた候補（ハルシネーションが起きる）が最初の塊にあるとは限らない。そこで `build_first_pool` で、塊の中の英字の語を含む候補ごとに、置き換えた候補を（表記が未出なら）足す。コストは元の英字の候補と同じにする（ほかの Ranker の比べ合いに入る）。
- 読み全体のカタカナの候補は今も塊にあるので、単独の読みでは足すものはない。

### 3.5 学習との関係（Q1）
- 推奨（E4 あり）: **学習の加点が、英字の候補にカタカナの候補より多く付いているときは、繰り上げない**。「その読み（とその文脈）で、この人はカタカナより英字を多く選んでいる」ときだけ英字を1位に残す。1回英字を選べば、英字が1位に戻る（ADR 0012 §4.3 の体験のまま）。
- 判定は学習の Ranker の加点（文脈に依らない分と文脈の分の両方）を、英字の候補と置き換えた候補で比べる。数え方は今の学習の式のまま（新しい重みや閾値は足さない）。
- ユーザーの今の学習（Hallucination 2 回、ハルシネーション 3 回）では、カタカナの加点が多いので繰り上げる（§4.5）。

### 3.6 置く場所（Q3）
- 規則は `CompositeRanker` の最後の段（LM の後）。GrammarGuard・LearningGuard と同じく、Ranker の差分の足し算ではなく「並びの規則」なので、Ranker を1つ足すのではなく、Composite の中に置く。学習の加点（E4）も Composite の中で取れる。
- 置き換えた候補の追加（§3.4）は `Conversion::build_first_pool`（core の変換）に置く。
- LM が英字を1位にしても、規則が後に働くので、カタカナが1位になる（ユーザーの決定 4）。
- 文節のモード（各文節の候補）と再変換も `Conversion` と同じ Ranker を通るので、同じ規則が効く。文節の先頭は読み全体の1位から作るので、読み全体で直れば文節も直る。表示中の表記を0番に固定する処理（`pin_first`）は今のまま優先する。
- secure の入力欄では学習を使わないので、E4 は働かない（いつも繰り上げる）。

## 4. 測定

### 4.1 方法
- 試作（捨てるコード）: core に、規則を環境変数で切り替えて入れた。比べた形は次のとおり。
  - **基準**: 今の main。
  - **F**: 最初の塊を並べた後に、1位の英字をカタカナに入れ替える（LM の後。学習を見ない。E1〜E3 あり、英字だけの表記のみ）。
  - **F+学習**（推奨の形）: F を `CompositeRanker` の最後に置き、§3.5 の E4 を足したもの。混ざった表記も §3.2 の置き換え先で対象にした。
  - **R**: 同じ規則を LM の**前**に置いたもの（LM がその後に並べ替える）。
  - F に、E1 を外したもの（文字の名前も繰り上げる）、E2 を外したもの、混ざった表記を読みのカタカナで置き換えたもの、も測った。
- 108,796 読み（§1.2）は `ikari-eval --ranker full`、単独の読み、LM なし。
- 既存の評価は snapshot と同じ 19 構成（LM なし、AJIMEE を含む）と、LM ありの 9 構成（homophones、homophones-ext の dev・test、hiragana、verbs、katakana-suffix、rare-homophones、new-words、AJIMEE。締め切り 2000ms、時間切れ 0）。ケースごとの1位を基準と比べた。
- 学習はシナリオ（一時的なユーザーディレクトリ）。既存の a-02〜a-04、b23-*、b28-borrowed、it-pack と、測定用の2つ（1回英字を選ぶ、ユーザーの今の学習と同じ回数を選ぶ）。LM ありのシナリオは締め切りも 2000ms に固定した（snapshot の LM ありのシナリオは締め切りを固定していないので、時間切れの多さで失敗の数が 2〜6 に揺れる。§11）。

## 10. ユーザーに聞くこと

### Q1. 英字を選んだ後も、カタカナを1位に強制するか（未決の (i)）
- 背景: 今の語彙集（ADR 0012 §4.3）は「カタカナ1位・英字2位、1回英字を選べば英字が1位」。規則を学習より後に置くと、何もしなければ英字は二度と1位に戻らない。基本原則「学習は支援であって決定ではない」は、過去の選択で今の文脈の判断を覆さない、という意味で使ってきた（LearningGuard）。この規則は文脈の判断ではなく表記の既定なので、どちらを選んでも原則には反しない。
- 実測: ユーザーの実機の学習で、日本語の入力で英字の表記を確定したのは Hallucination の 2 回だけ（同じ読みで ハルシネーション 3 回）。どちらの案でも、入れた後は ハルシネーション が1位になる。
- 例: くばねてぃす で Kubernetes を1回選ぶ → 次の くばねてぃす は？
- 選択肢:
  - (a) いつも強制する: 次も クバネティス が1位、Kubernetes は2位。英字を使うたびに2位を選ぶ。it-pack の4行（ADR 0012 §4.3 の体験）を書き換える。
  - **(b) その読みで英字の方を多く選んでいれば、強制しない（推奨）**: 次は Kubernetes が1位。カタカナを選び直せば、カタカナに戻る。it-pack は今のまま通る（LM なし・ありとも失敗 0）。
  - (c) 同じ文脈で選んだときだけ強制しない: 単独の くばねてぃす は クバネティス のまま。
- 推奨: **(b)**。理由: 語彙集の体験（1回選べば英字）とそろい、英字を使う語がある人の手間が増えない。誤って英字を確定する経路（英字が1位に出ること）は規則がふさぐので、学習が英字に傾くのはユーザーが選んだときだけになる。注意: 単独で選んだ学習は、文の中の同じ語（はるしねーしょんがおきる）には効かない（今の学習の性質。§7-3）。

### Q2. 文字の名前の読み、単位、一部だけ文字の名前の語、数字を含む語を対象にするか（未決の (ii)）
- 背景と例:

  | 型 | 例（今の1位 → 対象にしたときの1位） | Core と small の読み |
  | --- | --- | ---: |
  | 文字の名前 | ゆーあーるえる URL → ユーアールエル、えーびーしー ABC → エービーシー、ぴーしー PC → ピーシー | 2,719 |
  | 単位（品詞 助数詞可能）と数詞 | きろめーとるまいじ km/h → キロメートルマイジ、めーとるまいびょう m/s → メートルマイビョウ | 32 |
  | 一部だけ文字の名前 | ちゃっとじーぴーてぃー ChatGPT → チャットジーピーティー、しーでぃーろむ CD-ROM → シーディーロム、えすでぃーじーず SDGs → エスディージーズ、あいぴーせっく IPsec → アイピーセック | 41 |
  | 数字を含む | こびっどじゅうきゅう COVID-19 → コビッドジュウキュウ、じーぴーてぃーふぉーおーみに GPT-4o mini → ジーピーティーフォーオーミニ | 6 |
- 選択肢:
  - (a) 文字の名前と単位だけ外す（E1、E2）。ChatGPT、CD-ROM、SDGs、COVID-19 はカタカナが1位（ユーザーの決定 4 の文言どおり）。
  - **(b) 文字の名前と単位に加えて、一部だけ文字の名前の語と数字を含む語も外す（推奨）**: ChatGPT、CD-ROM、SDGs、COVID-19 は英字のまま1位。
  - (c) 何も外さない: URL → ユーアールエル。
- 推奨: **(b)**。理由: どれも、カタカナにすると誰も書かない表記（チャットジーピーティー、コビッドジュウキュウ）になり、文字の名前（E1）と同じ理由が当てはまる。ただし決定 4 で ChatGPT を対象と言われているので、実際の結果（チャットジーピーティー）を見て決めてほしい。判定は「大文字が2文字以上続く部分を文字の名前で読んでいる」「表記に数字がある」の2つで、表は E1 と同じものを使う。

### Q3. 規則を置く場所と、LM が英字を1位にしたときの扱い（未決の (iii)）
- 背景: 英字が1位に来る経路は、辞書のコスト、LM、学習の3つ。LM は今の仕組みで最後に働き、Guard でも止まらない。LM ありでは、語彙集の語（カタカナ1位のはずの りなっくす、どっかー、えくせる、ぱいそん）まで英字が1位になる（new-words 61 → 50、下書きのセットの守りの語）。ADR 0021（B36）で LM が付く変換を増やすと、この害も増える。
- 選択肢:
  - **(a) LM の後（最後の段）に置く（推奨）**: new-words 50 → 67、it-pack（LM あり）失敗 6 → 0。既存のセットは AJIMEE の1〜2件の順位だけが変わる。
  - (b) LM の前に置く: new-words 50 のまま（LM が英字に戻す）。
  - (c) 辞書で直す（初版の S-P）: LM の経路が残る。
- 推奨: **(a)**。理由: 決定 4（LM の英字戻しも含めてカタカナ）を満たすのは (a) だけ。ADR 0021 の Q4（B32 を先に入れる）とも合う。

### Q4. 英字で書く方が普通の語も2位に下がる（未決の (iv)）
- 背景: Core と small で 1,154 読みの1位が英字から変わる。そのうち英字の表記が chiVe の語彙の上位 5 万語（日本語のウェブの文章で英字のまま多く書かれる）に入るものは 59 読み:
  Twitter、Google、iPhone、Instagram、WWW、TOEIC、SDGs、JAL、NISA、YouTuber、CAD、Netflix、iDeCo、COVID-19、GOTO、Glamping、VTuber、Adobe、Gmail、TikTok、UFO、EPOS、TOTO、LIXIL、SQL（しーくえる）、SaaS、JAS、HUAWEI、POS、MIXI、UNESCO、EVA、EOS、WOWOW、ROM、NASDAQ、TOEFL、FIFA、ASEAN、NATO、ZOZO、pixiv、Retty、JPEG、JICA、SIer、HACCP、RAID、RIZAP、BIOS、UEFA、CD-ROM、Judy、SRC、CMOS、YAG、JETRO、ALSOK、OPEC。
  評価では AJIMEE の1件（当初は + わうわうが… の正解 WOWOW）が 2位 → 3位に下がった。語彙集の IT の語（Kubernetes、GitHub、Docker）は、もともとカタカナ1位の決定（B20-3）。
- 選択肢:
  - **(a) 受け入れる（推奨）**: 英字で書く語は、1回英字を選べば戻る（Q1 の (b) のとき）。ずっと英字にしたい語は、ユーザー辞書に英字だけで登録すれば、E3 で英字が1位のまま（今ある仕組みで足りる）。
  - (b) 英字のまま残す語の表を作る（語彙集の `latin` と同じ形。最初は上の 59 語の下書きをユーザーが確認）。
  - (c) 英字の表記が chiVe の上位 5 万語に入る語は自動で外す。
- 推奨: **(a)**。理由: 決定 2・4（英字が1位なら必ずカタカナ）の例外を増やさない。どの語を英字にしたいかは人によって違い、学習とユーザー辞書で個別に直せる。(c) は Google、iPhone が英字のまま残り、決定の例（Google）と食い違う。

### Q5. 置き換え先の細部（はい／いいえ）
- たこ: 今 1 TAKO 2 蛸 3 タコ → 規則では 1 タコ 2 TAKO 3 蛸（決定どおり読みのカタカナ）。初版の S-P では 蛸 だった。**このままでよいか**（推奨: はい。TAKO を選ぶ人はまれで、蛸 は Space 2回）。
- 外国の人名: かーとこばーん → カートコバーン（中黒なし。辞書にある カート・コバーン は3位）。**中黒つきの同じ語が辞書にあれば、そちらを置き換え先にするか**（推奨: いいえ、まずは読みのカタカナ。中黒は読みにない文字で、notcore の人名は日常の入力で出る機会が少ない。気になったら足す）。
- 混ざった表記: えっくすせん → エックス線、てぃーしゃつ → ティーシャツ（読みのカタカナ エックスセン ではなく、同じ語の英字を含まない表記）。**この置き換え方でよいか**（推奨: はい）。

## 11. ついでに気づいたこと（B32 とは別）
- **snapshot の LM ありのシナリオは、締め切りを固定していない**（`run_scenario` は `--lm-budget-ms` だけを渡す）。既定の締め切り（読み1文字 6ms）で LM の時間切れが起きるかどうかで、it-pack-lm の失敗が 2〜6 に揺れる（締め切りを 2000ms に固定すると main で失敗 6）。基準のレポートとの一致で比べるので、揺れが差分に出ることがある。`--lm-deadline-ms 2000` を足す小さなタスクの候補。
- そのまま（単独・文の中）で そのママ が1位になる件（初版 §10）は、今の main でも LM なしで残る（下書きのセットの守りの1件）。B32 の規則とは関係しない。
- LM ありでは、きろめーとるまいじ → キロメートル毎時、たこ → たこ（ひらがな）が1位になる。規則とは別の LM の判断。

## 12. 決定（2026-10-16 ユーザー承認）
| Q | 決定 |
| --- | --- |
| Q1 | **強制しない**（E4 あり）。その読み（とその文脈）で、カタカナより英字を多く選んでいるときは、繰り上げない。1回英字を選べば英字が1位に戻る（ADR 0012 §4.3 のまま） |
| Q2 | **例外は置かない**。文字の名前の読み（E1。URL、ABC）、単位（E2）、一部だけ文字の名前の語・数字を含む語（ChatGPT、CD-ROM、SDGs、COVID-19）も、カタカナを1位にする。理由: ユーザーがカタカナで書き始めた以上、それを尊重する |
| Q3 | 推奨のとおり。規則は `CompositeRanker` の最後の段（LM の後） |
| Q4 | 英字で書くほうが普通の語も、カタカナを1位にする。理由: ユーザーがカタカナで書きたいという意図があると見て、ユーザーを尊重する。ずっと英字にしたい語は、学習（E4。1回選べば戻る）かユーザー辞書（E3）で残す |
| Q5 | 推奨のとおり（たこ → タコ、かーとこばーん → カートコバーン（中黒なし）、混ざった表記は §3.2 の置き換え先） |
| Q6 | 評価セットの期待の確認（A2-17）は**やらない**。`eval/sets/english-first.tsv` は下書きのまま、期待の確認はしない（snapshot にも足さない） |

実装時の注意:
- **語彙集の形 `latin` の扱い（2026-10-16 ユーザー決定）**: `latin` の語（えすきゅーえる → SQL、まいえすきゅーえる → MySQL、しーぷらすぷらす → C++ など）も、カタカナを1位にする（Q2 の「例外なし」を文字どおり適用）。ADR 0012 §4.2 の「latin はカタカナを作らない」を、この点で改める。置き換え先は読みのカタカナ（エスキューエル）。E4（学習で英字を多く選んでいれば繰り上げない）は残るので、1回英字を選べば英字が1位に戻る。ユーザー辞書に英字だけで登録した語は、ユーザー自身の登録なので、E3 のまま英字を1位に残す（この点は未確認。実装後の報告で触れる）。
- E1・E2 を置かないので、§4.2 の測定のうち「E1 を外したもの」「E2 を外したもの」の数字が実装後の見込みに近い。実装前に、英字が1位から外れる読みの数と、it-pack のシナリオの期待（英字を1位にしている行）への影響を、その構成で測り直す。
- 実装は ADR 0021（B36）より先（ADR 0021 Q4）。

## 13. 実装の結果（2026-10-16。ブランチ `feat/b32-english-first`）
- 置き換えた候補を作る部品は `core/src/ranker/english_first.rs`（純粋な関数 `variant`）。最後の段は `CompositeRanker::english_first`（LM の後。E4 は学習の Ranker に2つの候補だけを渡して加点を比べる）。候補の追加は `Conversion::build_first_pool`。
- E3 の判定のため、`Dictionary::is_user_authored(WordId)` を足した（既定は false。`UserDictionary::build` が作る辞書だけ true。語彙集とシステム辞書は false）。語彙集の形 `latin` は語彙集なので対象（カタカナの項目がなければ、語IDなしの語として置き換える）。
- 測定（E1・E2 なし、LM なし、`--ranker full`、108,796 読み）: 1位が英字を含む 35,963 → **2,922**、1位が読みのカタカナ 55,539 → **86,318**（§4.2 の「E1 を外す」3,314 / 85,998 と同程度。差は混ざった表記の置き換え先と、語彙集の `latin`）。残り 2,922 のうち 2,854 は混ざった表記で、同じ語の英字を含まない表記が辞書にないもの。68 は記号つきの複数語（U・S・… など）。
- 既存の評価（snapshot。LM なし 19 構成と LM あり。基準は同じ版の規則なし）: 1位が変わったのは new-words の 3 件（it-mysql-01 MySQL、it-nginx-01 nginx、nw-seiseiai-01 生成AI。期待が英字なので 61 → 58。LM ありは 50 → 64）と AJIMEE（ajimee-1774、ajimee-2111。LM ありは ajimee-2111 だけ）。ほかは一致。
- 学習のシナリオ: it-pack の 15 行（まいえすきゅーえる）の期待を MySQL → マイエスキューエル に直した。it-pack-lm の失敗は 6 → 0。

## 14. カタカナ語らしさの補正（`katakana_like.*`。2026-10-24。#271）

辞書にない語（未知語）の読みから作るカタカナの候補は、`build_first_pool` で辞書の最大 base_cost + 1（最後）に置かれる。読みに外来語に特有の文字があるときだけ、この base_cost を下げる。azooKey の文字別の補正の考え方だけを参考にした（表や値は写していない）。

- **強い手がかり**: ゔ と小書きの母音（ぁぃぅぇぉ。てぃ・ふぁ・しぇ などを含む）。1 文字につき `strong_bonus` を下げる。
- **弱い手がかり**: ぱぴぷぺぽふぐむー。**既定では使わない**（`weak_bonus` 0）。擬音語・和語（ふんわり、ぐっすり、ふぐ）を壊さない幅では利益がなかった。同じ塊の繰り返し（ぷんぷん、ふふふ）は対象外。
- **下限**: 辞書の候補の最小 base_cost − `below_best`。0 だと同値で後に回るので上がらない。
- **既定**（ユーザー決定 2026-10-24: 採用）: `strong_bonus` 5000、`weak_bonus` 0、`below_best` 500。`--ranker-config` の `katakana_like.*` で上書きできる（0 で止まる）。
- **掃引**（PR #273。評価セット eval/sets/katakana-like.tsv 87 行 + 既存 25 セット、LM あり・なし、時間切れ 0）: 強い手がかり 5000 未満は動かず、5000 以上は同じ結果。全セット・全 split で 1 位の悪化 0 件。改善は小さい（dev の弱い外来語は LM なしで 1 → 3、LM ありは 6 のまま。test は LM ありで 11/16 → 12/16）。複数の語に分かれる辞書の経路まで下げる版は、dev の弱い外来語が 1 → 7 に増えたが、ファイル名 など 4 件が悪化したので外した。
- **残る問題**: LM ありだと ぴかぴか → ピカピカ のように擬音語がカタカナに寄る（既存）。ふかふか、ふくろう、ふじさん、むくむく、ぐふふ は補正なしでも失敗する（既存）。
