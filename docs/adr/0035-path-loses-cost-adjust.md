ここから分かった構造は 2 つ。

1. **1 語の熟語が辞書にあるのに、頻度の手がかりがなくて負ける**（異常気象、仕様変更、推し活）。異常気象 と 仕様変更 は chiVe にないので `frequent_compound`（ADR 0011）が当たらない。ただし**部品（異常 2516、気象 7340、仕様 1182、変更 350）はどれもよく使う語**。推し活 は chiVe の順位では ADR 0011 の (e) の範囲（4 万〜20 万）にあり、仮名を含むことだけで外れている。
2. **Sudachi の既定のコストが品詞3で違う**（ADR 0016 §0.2-1: サ変可能 約 6518、一般 約 7404）。看取 6519 と 看守 7401、起床 6516 と 気象 7379 は、どちらの組も「両方とも既定の値」で、Sudachi のコストに頻度の情報はない。差の約 880 は品詞の違いだけから来る。頻度の手がかりは `lemma_rank`（1 桁あたり 2000）だけで、看守／看取 は 0.41 桁（約 820）、気象／起床 は 0.19 桁（約 380）しか戻さない。さらに連接もサ変可能に有利（以上 → 起床 と 以上 → 気象 の経路の差が約 1500、看取 → 薬 と 看守 → 薬 で約 1200。上の合計から逆算した値で、内訳は測っていない）。

### 0.3 既存の仕組みとの関係
- `lemma_rank`: すべての行に、頻度の桁数で加算する。上の 2 の型では、品詞の既定の差と連接の差に負ける。
- `frequent_compound`（ADR 0011）: 漢字だけ 3 文字以上の熟語に -8000。chiVe の順位が要る（4 万位未満、または 20 万位未満で同音の守り）。chiVe にない熟語には当てない（ADR 0011 §7-1。広げると 高修正する、公家領 が崩れた。どちらも 1 文字の部品を含む）。
- 規則 R（ADR 0016 `cheap_rare_homophone`）: Sudachi のコストが 6518 **未満**のまれな語を 6518 まで上げる。看取（6519）、起床（6516 だが 11400 位で 2 万位より上）には当たらない。R は「既定より安い」語を扱い、この ADR の 2 は「既定どうしの品詞の差」を扱う。
- 規則 S（ADR 0016、辺）: 名詞（サ変でない）→ する に +3000。起床する のような サ変の名詞 + する は、この ADR のあとも S と連接で守られる。

## 2. 決定 1: どの語のコストをどう下げるか

### 2.1 規則 F（主）の定義
辞書の行 W に `frequent_compound` を当てる条件（ADR 0011 §2.1 の (a)〜(e)）に、次の (f) を足す。

- (a)(b) は今のまま（名詞,普通名詞、表記 = lemma）
- (f) 表記が漢字だけで **4 文字以上**、lemma が chiVe にない、または chiVe の順位が `COMPOUND_GUARDED_MAX_RANK`（20 万）以上で、かつ
  - (f1) 表記を 2 つに切ったとき、前と後がそれぞれ辞書の行（品詞1 = 名詞、品詞2 = 普通名詞、表記 = lemma、漢字だけ 2 文字以上）で、その読みをつなぐと W の読みになる組が少なくとも 1 つあり
  - (f2) その組の両方の lemma の chiVe の順位が Y（中心 1 万。掃引）未満で
  - (f3) 同音の守り: W の読みの `noun_peer_rank`（同じ読みの漢字を含む名詞の最小の順位）が W の順位以上（W が chiVe にないときは語彙の大きさ。つまり、同じ読みに chiVe にある漢字の名詞があれば当てない）

値は `frequent_compound` の -8000 をそのまま使う（新しい値を足さない）。述語の名前も同じにし、ポリシーの報告では (f) で当たった行数を別に数える。

### 2.2 規則 F の理由
- **原因に合っている**: 異常気象、仕様変更 は「辞書に 1 語である」のに「頻度の手がかりがない」ことで負けている。chiVe は複合語の頻度を持たないことが多い。代わりに、**部品がよく使う語であること**を、熟語がふつうに使われることの手がかりにする。
- **ADR 0011 §7-1 の崩れを避ける形**: chiVe にない語へ広げたときの崩れ（高修正する、公家領）は、どちらも 1 文字の部品（高、領）を含む。部品を「漢字だけ 2 文字以上の普通名詞」に限り、4 文字以上にする。
- **同音の守りは ADR 0011 と同じ物差し**: chiVe にない熟語は、同じ読みに chiVe にある漢字の名詞が 1 つでもあれば当てない（ADR 0011 §2.2 の「その読みでいちばん使われる表記」）。
- **値を足さない**: -8000 は ADR 0011 で区切りの崖の手前と確かめた値。ここで動かすのは条件だけにして、掃引の軸を減らす。

### 2.3 規則 H（従）の定義
読みごとに、`is_homophone_peer`（ADR 0016。漢字だけ 2 文字以上の普通名詞、表記 = lemma）の行を集める。

- W: その中で lemma の chiVe の順位がいちばん高い行。W の順位が X（中心 10 万。掃引）未満で、W の Sudachi のコストが既定の帯 [B_lo, B_hi]（中心 6500〜7410。掃引の前に分布で決める。§4.1）にある
- V: ほかの peer で、(1) W より d 桁（中心 0.15。掃引）以上まれ、(2) Sudachi のコストが既定の帯にある、(3) 規則 R に当たっていない
- 総コスト T = Sudachi のコスト + この述語を除くポリシーの加算の合計（`lemma_rank`、`frequent_compound`、規則 R などを含む）
- T(W) > min T(V) − M のとき、W に `min T(V) − M − T(W)`（負の値）を足す。それ以外は何もしない

これは `katakana_place_peer`（#223）と同じ「固定の加算ではなく、そろえる」形で、`chive.tsv` の値（M）は余白。

### 2.4 規則 H の理由と限界
- **既定のコストどうしに限る**: 既定の値は「Sudachi が頻度の情報を持たない」印で、その差は品詞3の違いだけ。ここを頻度（chiVe）でそろえるのは、ずれの原因そのものの補正になる。帯の外（再開 8691 のように Sudachi が既定より高くした語、規則 R の対象の安い語）には当てない。これで、ADR 0016 が「規則では扱わない」とした 再会／再開（再開 は 8691 で帯の外）に入り込まない。
- **そろえるだけで、固定の加点にしない**: 頻度の順とコストの順がずれているときだけ、ずれの分だけ動く。W がすでに安い読み（以上／異常 の 以上）では何もしない。
- **限界（推測）**: 連接の差（サ変可能に有利な約 1200〜1500）は語のコストでは消せない。M をそこまで上げると、学習（1 回の選択の加点 1500。#223 の議論）で戻せなくなる。だから**規則 H の目標は「頻度の高い語の経路を pool の上の方に上げ、LM と文脈と学習が選べるようにする」**ことで、LM なしの 1 位をすべて直すことではない。看守役 は 看守 + 役（接尾辞）で、役（904）と 薬（1141）は頻度がほぼ同じなので、看守薬 と 看守役 の差は辞書では決められない。LM に届けるのが限界。いじょうきしょう の 1 位は規則 F（異常気象 の 1 語）で直し、規則 H は 以上起床 → 以上気象 の差を縮めるだけ。

### 2.5 既存の述語との関係（重ならない、二重に効かない）

| 述語 | この ADR との関係 |
| --- | --- |
| `lemma_rank` | 規則 H は `lemma_rank` を含む総コストでそろえるので、`lemma_rank` が戻した分は差し引かれる（二重に効かない）。規則 F の対象（chiVe にない熟語）には今どおり最大の `lemma_rank` が乗り、-8000 がそれを打ち消す（ADR 0011 と同じ関係） |
| `frequent_compound` (d)(e) | 規則 F は (d)(e) に当たらない行（chiVe にない、または 20 万位以下）だけが対象。同じ行に -8000 が 2 回乗ることはない。(d)(e) の対象はコストが高く、規則 H の帯に入らない見込み（入れば総コストで比べるので二重には効かない） |
| 規則 R `cheap_rare_homophone` | R は Sudachi のコストが 6518 未満の行。帯の下限 6500 と少し重なるので、**帯の判定は Sudachi の元のコストで行い、R の当たった行は V から除く**。R を先に当て、H は R のあとの総コストを見る |
| 規則 S（辺） | 辺の補正で、語のコストとは独立。起床する は S と連接で守られる |
| `katakana_place_peer` | 対象（カタカナの固有名詞）が重ならない |

実装の順: ポリシーの加算（H 以外）→ 総コスト T → 規則 H。T を読みごとに求めるには 2 回目の走査が要る（`place_peer_totals` と同じ形）。規則 F は (f1) のために「(表記, 読み) → 行」の索引が要る（ビルド時だけ）。

## 3. 決定 2: 副作用の見積もりと守り

### 3.1 悪化しやすいケース（推測。新しいセットの否定に入れる）
- **規則 H、サ変の名詞の方が意図**: きしょうじかん（起床時間 → 気象時間）、あさろくじにきしょう（朝6時に起床）、かんしゅ を 看取 の意味で使う文。する が続く形（起床する）は S と連接で守られる見込み。名詞が続く形が危ない。
- **規則 H、頻度の高い語が別の経路にも入り込む**: 下げた W（気象、看守）が、長い読みの中の別の切れ目に勝つ（ADR 0011 §13 の 会東洋史 と同じ型）。全セットで測る。
- **規則 F、2 語の分割の方が意図**: 熟語と同じ読みで、よく使う 2 語の別の分割が意図の入力（ADR 0011 の否定 139 件の型）。researcher に「規則 F の対象のうち、今の 1 位が 2 語の分割で、その 2 語がどちらも Y 位未満のもの」を洗い出してもらい、否定のセットにする。
- **以上／異常、看取／看守 の使い分け**: 規則 H は 以上 を動かさない（すでに安い）。異常 が単独で 以上 に勝つことはない。異常気象 は規則 F（1 語の熟語）でだけ直す。単独の語の勝ち負けは頻度、文の中の使い分けは文脈と LM と学習。

### 3.2 守りの方針
- **候補は消さない**。起床、看取、お死活、以上起床 は N-best に残る（基本原則「選択肢を制限しない」）。
- **規則 H は学習で戻せる大きさにする**: M は「V を 1 回選んだあと、次の変換で V が 1 位になる」範囲で決める（#223 と同じ確かめ方。学習の 1 回の加点 1500）。
- **規則 F は -8000 で、1 回の学習では戻らない**（今の `frequent_compound` と同じ）。そのため対象を狭く（4 文字以上、部品 2 文字以上、部品が Y 位未満、同音の守り）する。
- **LM に戻させる範囲**: LM なしの悪化は、正解が 30 位以内に残るものに限り、LM ありで 1 位に戻ることを確かめる。30 位より下に落ちる悪化は 0 にする。

## 4. 決定 3: 値の決め方（掃引の設計）

### 4.1 掃引の前に測るもの（researcher か code-editor）
1. **既定の帯**: 漢字だけ 2 文字以上の普通名詞（表記 = lemma）の Sudachi のコストの分布（品詞3ごと）。サ変可能 と 一般 の山（見えている値: 6512〜6519、7379〜7404）の幅から B_lo、B_hi を決める。中心は 6500〜7410。
2. **対象の行数**: 規則 F（Y ごと）、F2、H（X、d ごと）で当たる行数と、例を 30 件ずつ。

### 4.2 辞書の作り方
- scratch に `data/` を作り、`data/raw/` の下の各ディレクトリ（sudachi、chive、abr など）を symlink する。`scripts/build-dict.sh --data <scratch>/data --policy <scratch の chive.tsv>` で作る（ABR の町字マスターは今 `data/raw/abr/` にあるので地名の行を含む）。
- **基準も同じ手順で作り直す**（main の dict-builder、同じ raw）。比べるのは同じ入力の辞書どうし（ADR 0011 §13.2 と同じ）。
- 閾値（Y、X、d、帯、F2 の有無）はコードの定数なので、掃引のためだけに環境変数で上書きできるスパイクの dict-builder を作る（捨てる。コミットしない）。M と規則の有無（値 0）は `--policy` のファイルで変える。
- 実機の辞書（`~/Library/Application Support/ikari-ime/dict`）は読むだけ。`data/build/`、`data/raw/`、ユーザーデータは書き換えない。

### 4.4 見る指標
1. 全 30 セットのケースごとの 1 位（改善 / 悪化 / 変化なし）。LM なし（`--ranker full`）と LM あり（締め切り 2000ms）。参考に LM あり（既定の締め切り。snapshot の ref）
2. §0.1 の 22 件: LM なしで 30 位以内に入った数、LM ありで 1 位の数
3. 新しいセット（§6）の正と否定

## 8. 結果（提案どおりに入れた場合）
- 得るもの: 部品がよく使う語の 4 文字以上の熟語（異常気象、仕様変更 など）が、同音の 2 語の分割に負けなくなる。品詞の既定のコストの差だけで、頻度の低い同音語が上に来ることが減る。変更は `dict-builder` だけで、辞書を作り直すだけで効く。
- 失うもの: `frequent_compound` の条件が 1 つ増え、ビルド時に「(表記, 読み) → 行」の索引が要る。規則 H のために総コストを読みごとに求める 2 回目の走査が要る。
- 波及: 熟語のコストが下がるので、ADR 0008 の「覆う名詞」が増える（adverbs を流す）。Sudachi や chiVe の版を変えたら、規則 F の対象と帯を取り直す。

## 10. ユーザーの決定（2026-10-25。3 点とも推奨どおり）
1. **規則の組み合わせ**: 主を規則 F（部品がよく使う語の熟語に `frequent_compound`。異常気象、設計仕様変更）、従を規則 H（既定のコストどうしの同音語のそろえ。看守、気象）にする。規則 H は LM なしで 看守役 を直すものではなく、正解を LM の pool に入れるためのもの、という期待の置き方でよいか。**推奨: この形で掃引に進む**（規則 H は平坦な範囲がなければ入れない）。
2. **推し活（規則 F2）**: 仮名を含む熟語を ADR 0011 の (e)（4 万〜20 万位、同音の守りつき）に限って対象にするのを、掃引に入れるか。送り仮名を含む熟語まで対象が広がり、セットの外の効き方が読みにくい。**推奨: 掃引には入れ、悪化 0 で当たる行数が少ないときだけ入れる**。
3. **悪化の条件**: 「既存の全セットで 1 位が悪化しない」を、LM あり（2000ms）で 0、LM なしは 0 を目指し、出たら件数と内訳を出して聞く（ADR 0011 §13 の 公用文 と同じ扱い）、でよいか。**推奨: この扱い**。

## 12. 拡張の掃引（#2。2026-10-28）
経路のコスト型（看守役、見た目）に規則 F を広げられるかを、変換時の補正で測った。**既定は補正なし（今の挙動のまま）。値はユーザーが掃引の表（PR の説明）を見て決める**。

- 規則 F は辞書の作成時（`dict-builder/src/policy.rs`）に語のコストを下げる。仮名まじりの熟語に広げる F2 は §11 で採らなかった（悪化あり）。辞書の作り直しには `data/raw` が要るので、この掃引は変換時の補正で行った。
- 設定のキー: `--ranker-config` の `lattice.compound_word.bonus`（0 以上の整数。既定 0 = 補正なし）。辞書のノードのうち、品詞1 が名詞で、表記の先頭と末尾が漢字・途中に平仮名があり（見た目、結び目）、表記と読みがどちらも 3 文字以上のものから、この値を引く（`core/src/lattice.rs` の `is_kana_mixed_compound`）。末尾が仮名の表記ゆれ（想ぞう、家てい）は除く。
- 看守役 は辞書にない複合語（看守 + 役 と 看取 + 役 の競り）なので、この補正は効かない。頻度の手がかり（chiVe）は変換時に持っていないので、直すなら辞書の作成時の規則 H（§2.3。M）の側。
