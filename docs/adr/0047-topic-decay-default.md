# ADR 0047: 話題の減衰 `topic.decay` の既定を 0.97 から 0.8 にする

- 状態: 採用（2026-11-04 にユーザーが 0.8 に決定）
- 日付: 2026-11-04
- 対象: `core/src/ranker/topic.rs`（既定値の 1 行）。学習側の `core/src/user/features.rs` の `TOPIC_DECAY`（0.97）は変えない（別の部品。この掃引の対象外）
- タスク: #178（遠い話題が直前の話題に勝つ）
- 判断の置き場所: Rust の core（ranker の設定の既定値。OS の API も UI も関わらない）

## 1. 問題
左文脈の話題の重みは `decay ^ 距離` で減る。既定の 0.97 は緩く（50 個目で約 0.22）、直前の話題より同じ話題の分量が多いほうが勝つ。例: 技術文を 3 回書いたあとに直前だけゲームの文だと、「ひんし」の 1 位は「品詞」になる。

## 2. 調べたこと
全文は `eval/reports/topic-decay-sweep-2026-11-04.md`。学習なし、LM なし、43 セットと AJIMEE の 1 位の総数。

| decay | 1 位の総数 | 基準からの悪化 | #178 の 4 例 |
|---|---|---|---|
| 0.97（基準） | 7171 | 0 | 直らない |
| 0.9 | 7194 | 25 | 1 例 |
| **0.8** | 7225 | 54 | 3 例（「ゲーム×3→技術」だけ残る） |
| 0.7 | 7235 | 88 | 4 例 |
| 0.5 | 7249 | 147 | 4 例 |

LM あり（3000ms）: 0.97 が 7987、0.8 が 8009（悪化 29、改善 51）、0.7 が 8020（悪化 36、改善 69）。ajimee は 0.8 で 111 のまま。
- 総数の増加は、ほぼ carry-unrelated（履歴が無関係な話題）による。
- 悪化は carry-* の派生セットと、本物のセット（ajimee、place、homophones-ext）にもある。「悪化ゼロ」の値はない。

## 3. 決定
`topic.decay` の既定を **0.8** にする。設定（`--ranker-config`、設定ファイル）で上書きできるのは今のとおり。
- 理由: LM なしで悪化が 54 件と小さく、LM ありでは ajimee が落ちない。0.7 は残る 1 例も直るが、悪化が 88 件に増える。
- 悪化を許す判断はユーザーによる（2026-11-04）。

## 4. 検討した案
- 0.9: 悪化は 25 件だが、直る例が 1 つだけ。
- 0.7、0.5: 直る例は増えるが、悪化が 88、147 件に増える。
- 距離でなく文境界で切る案: 未検討。残る「ゲーム×3→技術」はこの案の動機になる。必要なら別の issue にする。

## 5. 結果と残ること
- 「ゲーム×3→技術」の例は直らない。
- 500 文字を超える長い文脈でも傾向は同じで、長さで悪くはならない。
- 0.8 は掃引の 2 例と評価セットで決めた値で、実機の使用感は未確認。
