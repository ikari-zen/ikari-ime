# ADR 0029: 形状詞のあとの複合語と、名詞的な接尾辞の増幅をやめること（#137 最適 + かい → 解）

- 状態: 承認（2026-10-22。Q1〜Q3 すべてユーザーが推奨どおりに承認。§8）
- 日付: 2026-10-22
- 対象: core の `LeftContextRanker`（`core/src/ranker/left_context.rs`）。issue #137（B62）
- 前提: main = d1c27ca。ADR 0002 §22（連接の増幅）、ADR 0007 §3.1（複合語の条件）・§9（案 B-1 を不採用にした経緯）
- 測定: LM なしの CLI（`ikari --format tsv`、空の `--user-dir`、`--profile none`）。§5 の表は、コードを変える前に 3 通りの出力（既定、`left_context.weight=0`、`left_context.compound_bonus=0`）の差分を組み合わせて A / B を**模した値**。§7 は、実装したあとの**実測**
- ADR 0007 §3.1 と §6.1、ADR 0002 §22 の該当部分を本 ADR で改める（本文は書き換えず、注記だけ足した）

## 0. 現状の把握

### 0.1 起きていたこと（LM なし、学習ゼロ）
| 文脈 + 読み | 1位 | 期待（順位） |
| --- | --- | --- |
| 最適 + かい | 海 | 解（14位） |
| 無理 + かい | 海 | 解（3位） |
| 唯一 + かい | 海 | 解（10位。唯一解 は辞書にない。本 ADR の対象外、別 issue） |

### 0.2 原因（測った値。列は 最終スコア / 経路のコスト）
- 海・界・塊・カイ は `接尾辞,名詞的,一般`、解 は `名詞,普通名詞,一般`。
- **原因 1（接尾辞の増幅）**: 最適 + かい で 海 は 3669 → -2331（増幅の上限 -6000 が付く）。解 は名詞なので増幅されず 10263 → 8963。`weight=0` でも経路のコストだけで 海 3669 が 解 10263 より安い。
- **原因 2（複合語の条件 1）**: 最適 は `形状詞,一般` で、ADR 0007 §3.1 の条件 1（左が名詞）に当たらず、最適解（普通名詞）があっても加点されない。無理（`名詞,普通名詞,形状詞可能`）は当たり、解 は 10193 → 569（-9000 ほか）だが、海 の -1065 に負ける。
- つまり、複合語の加点（上限 -6000 + 3000）は「当たらない接尾辞も上限 -6000 を受ける」ため、実質 3000 の差しか作らない。経路のコストの差（解 − 海 = 6000〜6600）を越えられない。

## 1. 決定の要約
| 項目 | 決定 |
| --- | --- |
| 案 A | 複合語の条件 1 を「左の語の品詞1が `名詞`、または品詞が `形状詞,一般` か `形状詞,タリ`」に広げる。`形状詞,助動詞語幹`（そう、よう、みたい）は含めない |
| 案 B | 連接の増幅（ADR 0002 §22）から、`接尾辞,名詞的,*` のうち **助数詞（`接尾辞,名詞的,助数詞`）以外**（一般、サ変可能、副詞可能）を外す。複合語が当たった候補は今までどおり「上限まで引き上げ + `compound_bonus`」 |
| 変えないもの | `接尾辞,形状詞的`（的）・`動詞的`・`形容詞的` の増幅、助数詞の増幅と規則 C、`max_total` 6000、`compound_bonus` 3000、複合語の条件 2〜5 |
| 設定 | 新しいつまみは足さない（品詞の規則はコードに固定。ADR 0007 §2 と同じ） |

## 2. 案 A の詳細
- 理由: 最適解、最適化、重要視、明確化、透明性、多様性 のように、形状詞の語幹に 1 字の名詞・接尾辞が付いた普通名詞が辞書に多い。品詞が 名詞,形状詞可能（無理、必要、安全）か 形状詞,一般（最適、簡単、重要）かは Sudachi の分け方の違いで、0007 §0.3 の「品詞の分け方によらない手がかり」に沿う。
- 助動詞語幹を除く理由: 機能語で、つないだ表記が複合語になる例が見込めない。誤爆の芽を残さない。
- 条件 3〜5（辞書の 1 語、普通名詞か地名、読みの一致）はそのまま。形状詞 + な / に / だ は、つないだ表記が普通名詞にならないので当たらない（§7.3 で確かめた）。

## 3. 案 B の詳細
- 増幅（ADR 0002 §22）の目的は「文法（左文脈）が品詞を決める」こと（と → しよう）。名詞的な接尾辞（海、界、家、化、間）は名詞と同じく内容を担う語で、同音の名詞（解、会、か）との比較は文法では決まらない。名詞の候補を増幅しない理由（希少な語が偶然有利になる）が、名詞的な接尾辞にもそのまま当てはまる。
- 名詞に付く接尾辞が正しいときの支えは、ADR 0007 の複合語の加点（辞書に 日本海、業界、政治家、美術館 がある）に移る。
- 助数詞を残す理由: 数詞のあとの 歳 が 菜 に負けた（§5.2。規則 C と同じ考えで、助数詞は文法的に決まる）。
- 0007 §9 の案 B-1（接尾辞をすべて増幅しない）を、複合語の加点がある今、名詞的に限って採り直す。B-1 の悪化（論理 + てき → 敵）は 接尾辞,形状詞的 なので、本案では起きない。

## 4. ほかの仕組みとの関係
- GrammarGuard / LearningGuard: 増幅を受けなくなった名詞的な接尾辞は「文法候補」「文脈の証拠」でなくなる（複合語が当たれば今までどおり）。話題・プロファイル・学習の文脈に依らない加点で追い越されうる、という懸念は §7.2 で実測した（悪化なし）。
- LM（zenz）: Guard のあと。LM ありは未測定（§9）。
- 学習の記録、ユーザー辞書: 変えない。

## 5. 測定（コードを変えずに模した値）
### 5.1 方法
候補ごとに、増幅の差分 = 既定 − `weight=0`、複合語が当たった候補 = 既定 ≠ `compound_bonus=0`。B は当たらない対象の接尾辞のスコアを `weight=0` の値に置き換え、A は左が形状詞の入力で複合語の候補に「`weight=0` の値 − 9000」を与えて並べ直した。CLI の既定の 1 位数は ikari-eval と一致した（context-compound 40、homophones-ext 993）。この方法では Guard の効き方の違いは模せない。

## 6. 壊しうる入力
- **型 1（B）: 名詞 + 名詞的な接尾辞で、つないだ語が辞書にない**。増幅を失い、同音の名詞・助詞・未知の分割に負けうる。測った範囲では 文字列 + か（家 → か）だけで、元から誤り。新語・専門語（〜性、〜化、〜界 の造語）で起きうる（推測）。
- **型 2（B）: 名詞 + か の終助詞化**。本当か、無理か、簡単か が か になるのは改善だが、辞書にない「〜化」を打つときは か が先に出る（文字列化）。Q3 で受け入れた。
- **型 3（A）: 形状詞 + 1 字で、つないだ普通名詞が辞書にあるが、別の語を意図する**。§7.3 の範囲では見つからなかった。
- **型 4（B と Guard）**: 増幅を失った接尾辞が話題・プロファイルの加点で入れ替わる。§7.2 の範囲では起きなかった。

## 7. 実装後の実測（2026-10-22。LM なし。main = d1c27ca との比較）
### 7.1 全評価セット（`eval/scripts/snapshot.sh --compare`。Guard を含む full）
- 1 位が正解でなくなった（悪化）ケースは **0**。順位が下がったケースも 0。
- 1 位が正解になった（改善）: context-compound 4（日本語 + ばん → 版、本当 / 無理 / 大丈夫 + か → か）、katakana-full 1、katakana-topic 1（どちらも 日本語 + ばん → 版）。順位だけ上がったもの: 本 + と（4 → 3 位）。
- adverbs、verbs、compound-affix、new-words、rare-homophones、formal-noun-split、counters、toshiyou、segments、シナリオ（a-02〜it-pack）、CLI golden は完全一致。warm p99 の警告が homophones-cost / homophones-full に出たが、これは測定のゆれと思われる（本変更は候補ごとに品詞名を引く処理を足しただけ。再測定はしていない）。
- context-compound に 7 件を足した（最適 / 無理 + かい、重要 + し、人口 + りつ、出発 + てん、最適 + か、簡単 + か）。足した 7 件はすべて 1 位。全 54 件で 51 件が 1 位（外れは ADR 0007 で受け入れた 2 件と 本 + と）。

### 7.2 Guard（話題・プロファイル・学習）との関係
名詞 + 名詞的な接尾辞で正解が接尾辞のもの（日本 + かい、業 + かい、政治 + か、美術 + かん、洗濯 + き、自動 + か、人口 + りつ、出発 + てん、最適 / 無理 + かい、重要 + し、簡単 + か など） 35 入力を、プロファイル 5 通り（なし、it、infra、novel、business）× 左文脈（語だけ / 話題の文 + 語）で、変更前後で比べた（350 組）。
- 悪化 0、改善 73、変わらず 277。話題やプロファイルの加点が、増幅を失った接尾辞を追い越した例は出なかった。
- 学習: 日本 + かい で 海 を 3 回確定したあとでも、最適 + かい は 解 が 1 位、業 + かい は 界 が 1 位（変更前は 海 が 1 位）。
- 限界: 専門語の語彙集（IT の pack）は既定で使われている。LM ありは測っていない。

### 7.3 案 A の効きと誤爆探し
形状詞,一般 / タリ や形状詞可能の名詞を手で選んだ 68 語（最適、簡単、重要、無理、必要 など）× 読み 22 通りの 1,496 入力で、A だけを入れたもの（B を切ったビルド）と変更前を比べた。
- A だけで 1 位が変わったのは 5 件: 重要 + ど → 度（重要度）、特別 + かい → 会（特別会）、特別 + てん → 展（特別展）、特別 + ほう → 法（特別法）、可能 + けい → 形（可能形）。辞書にある語で、どれも自然な読み。誤爆は見つからなかった。
- 形状詞 + な / に / だ は A で変わらなかった。
- A + B では 423 件で 1 位が変わる。多くは「名詞的な接尾辞（氏、史、御、店）が 1 位だったところが、終助詞の か・し、助詞の ご、同音の名詞（語、感、方、法）に替わる」型で、形状詞 + 1 字で辞書に複合語がない入力。期待の判定は付けていない（変更前も正解とは限らない）。最適 + ど で ℃ が 1 位になる（変更前は 奴）ような、元から誤りの入力もある。
