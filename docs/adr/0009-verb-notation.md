## 0. 現状の把握

### 0.1 報告された3件（CLI と eval で再現。空の学習、プロファイルなし）

| 入力（文脈） | 期待 | LM なしの1位（期待の順位） | LM ありの1位（期待の順位） | 後ろの語まで一度に打つと（LM あり） |
| --- | --- | --- | --- | --- |
| すすめられる（今から風呂に入ってくるけど） | 進められる | 薦められる（7） | 勧められる（2） | すすめられるたすくはあるか → 進められるタスクはあるか（1） |
| なおったけど（なし） | 直ったけど | 治ったけど（3） | 治ったけど（2） | ― |
| かこう（と） | 書こう | 囲う（4） | かこう（5） | かこうとしたら → 書こうとしたら（1） |

- LM ありは zenz-v3.2 small、締め切り 2000ms（時間切れ 0）。ユーザーが見た「勧められる」は LM ありの結果と一致する（LM なしなら 薦められる）。
- **LM があっても3件とも直らない。** LM は、後ろの語（タスク、としたら）まで一度に打ったときだけ直す。こまめに確定する書き方では、ちょうどこの3件のような短い入力になる。
- `zenz.alpha=20`（LM の判断だけで並べる）でも、すすめられる → 勧められる、なおった → 治った、と＋かこう → 加工。LM そのものが、この短さでは決められない。

### 0.2 原因（測った値。詳細はレポート §2）

1. **Sudachi の正規化表記が、異字同訓と表外の表記を1つの lemma にまとめている。** 勧める = 勧・薦・奨・奬・推、取る = 取・捕・執・採・獲・摂・録・盗・奪 など、会う = 会・逢・遇・遭・晤、利く = 利・効、聞く = 聞・聴・訊・尋、治る = 治・癒・愈。
   - chiVe の頻度（`lemma_rank`）も話題スコア（chiVe のベクトル）も lemma 単位なので、**同じ lemma の中の表記は区別できない**。
   - `variant_surface`（表記が lemma と違うものに +1500）は活用しない語だけが対象で、動詞には当たらない。
2. **同じ lemma の中の順は、Sudachi の解析用のコストだけで決まり、使われ方の順になっていない。** 未然形の すすめ は 薦 11242 < 勧 11385 < 奨 11636 < 奬・推 11671 < 進 11727。取る の中では 捕 5266 < 取 6871（最小のコスト）。
   解析では表記が与えられるので、同じ読みの表記どうしのコストの差は解析の結果に効かず、IME 用に揃えられていない。
3. **`lemma_rank` は頻度 1000 位まで無料なので、よく使う動詞どうしの差が消える。** 進める（988 位）は 0、勧める（1341 位）は +256。lemma の違う 直る（10719 位）+2060 と 治る（3719 位）+1141 は、頻度の差がそのまま 治る を押す（web の文章では 治る の方が多い）。なおった は 治った 8208、直った 10409（差 2201）。
4. **話題スコアは、文脈の内容語との近さで 勧める を押した。** 今から風呂に入ってくるけど のあとで、勧める の系統に -3359、進める に -2028。文脈なしで 3 位の 進められる が 7 位に下がる。動詞の話題スコアは全体では効いている（止めると verbs.tsv の LM なしの1位が 59 → 46）ので、この入力では雑音として扱う。
5. **と のあとの かこう は、連接表とその増幅で決まる。** 格助詞 と → 五段ワア行の終止形（囲う、言う、思う が同じ左ID 1450）が -3770（「という」「と思う」の分）、意志推量形（書こう）は -1397。LeftContextRanker が名詞以外の1語の候補について ×4 で足すので、囲う は上限の -6000、書こう は -1588。さらに と → 副助詞 か（「とか」）が安く、か＋こう（2899）も 書こう（8502）より安い。
6. **学習は、文脈がないとほとんど効かない。** 文脈なしで「直った」を3回確定しても、加点は +675（差 2201 に届かない）。ADR 0002 §8.4 の Unconditional の重み 0.2 による（文脈が違う場面で過去の選択を効かせすぎないための値）。文脈 と のあとで 書こう を1回確定しても +1800 で、囲う との差に届かない。
7. **治っタ（読みの一部がカタカナ）。** 助動詞 タ のコスト 6884 は た 8729 より安い。`katakana_variant`（+5000）で後ろには下がるが、候補の数が少ない読みでは 4 位に残る。機能語の装飾の表記を後ろに回す `function_word_notation` は、英字と波ダッシュ（YO、ね〜）にしか当たらない。

### 0.3 LM なしの順位が効く場面
- 1位以外の並び（奬められる、推められる が 5、6 位に出る）。
- LM が締め切りに間に合わないとき。eval の既定の締め切り（先行計算なし。読み1文字 6ms、30〜300ms）では、報告の入力を含む 12 件で時間切れが 16 / 48 回（33%）だった。エンジンは先行計算をするので実機ではもっと少ないが、0 ではない。
- LM が採点する候補は上位 32 件だけ。

## 2. 規則

### 2.1 表（`dict-builder/policy/kun.tsv`。同梱、Claude の下書き、ユーザーの確認待ち）
列は `lemma<TAB>漢字（常用漢字表の訓で、その読みに使えるもの）<TAB>lemma の中の既定<TAB>読みの組の既定なら組の名前`。抜粋:

| lemma | 漢字 | lemma の中の既定 | 読みの組の既定 |
| --- | --- | --- | --- |
| 勧める | 勧、薦 | 勧 | |
| 進める | 進 | 進 | すすめる |
| 取る | 取、捕、執、採 | 取 | とる |
| 撮る | 撮 | 撮 | |
| 会う | 会、遭 | 会 | |
| 治る、治す | 治 | 治 | |
| 直る、直す | 直 | 直 | なおる、なおす |
| 書く | 書 | 書 | かく |
| 聞く | 聞、聴 | 聞 | きく |
| 利く | 利、効 | （なし） | |
| 上る | 上、登、昇 | 上 | のぼる |
| 見る | 見、診 | 見 | みる |

全体（50 行）と、表外として当たる辞書形の一覧はレポート §3。

### 2.2 判定（行は辞書形でまとめる）
- 対象は品詞1が動詞で、lemma が表にある行。活用形の行は、Sudachi の辞書形 ID（列 14）の行の表記で判定する（未然形の 奬め は 奬める で判定）。
- **表外**: 辞書形の表記の漢字の部分が表の漢字にない、または送り仮名が lemma の送り仮名（と、その可能動詞の形）に合わない。かなだけの表記（すすめる、ススメる）は対象にしない（`katakana_variant` と KanaStyleRanker の扱いのまま）。
  可能動詞（書ける、打てる、送れる）は、Sudachi では lemma が元の動詞なので、送り仮名の判定で可能動詞の形を許す（スパイクの最初の版はこれを誤って罰していた。レポート §4.1）。
- **lemma の中の既定**: 同じ (lemma, 読み, 品詞) の中で、表外でない既定以外の行の最小のコストを m とする。既定の行のコスト + ペナルティが m 以上なら、m - 50 になるようにペナルティを足す（負の値になることがある）。
- **読みの組の既定**: 既定の lemma の、既定の表記の行に -500。

## 3. なぜ辞書のポリシーか（Ranker ではなく）
- 同じ lemma の中の順は、文脈によらない静的な性質で、ADR 0002 §4 のポリシー（`variant_surface`、`katakana_analysis`、`frequent_compound`）と同じ種類の補正。
- ラティスのコストを変えるので、後ろに語が続く候補（すすめられるたすくはあるか）にも効く。KanaStyleRanker のような Ranker は候補の最初の語しか見ず、N-best に出てこない表記を拾えない（スパイクで、verb-susumeru-12 は辞書のコストを変えたときに直った）。
- ペナルティは変換にだけ効き、文脈の解析（書かれた表記を読む側）には効かない。ユーザーが 奨める と書いた文章も、今どおり解析できる。

- dev は 95 件、test は 25 件（unreachable の 1 件を除く）。
- 既存のセット（LM なし）: homophones（full）、homophones-ext の dev / test（topic / full）、hiragana（topic / full）、katakana-suffix、context-compound、adverbs（いずれも1位の数とケースごとの1位）、segments（区切りの完全一致と F1）。LM あり: homophones（full）、homophones-ext の dev / test（topic）、hiragana（topic）。

- 速さ: 辞書のコストを変えるだけで、変換の処理は変わらない。辞書の作り直しは今と同じ（スパイクで 7 秒）。

## 5. 直らないもの（既知の限界）
提案の構成でも、報告の3件は1位にならない。

| 入力 | 提案の LM なし | 提案の LM あり | 何が要るか |
| --- | --- | --- | --- |
| すすめられる（今から風呂に…） | 勧められる（進 は 3 位） | 勧められる（2 位） | 話題スコアの雑音（風呂 → 勧める）と、受け身の「勧められる」を好む LM。後ろの語（タスク）があれば LM が直す。学習（案 E） |
| なおったけど | 治ったけど（2 位） | 治ったけど（2 位） | 治る の頻度の有利（差 2201）を覆す既定は、病気の文脈を壊す（§4 の -3000）。この人の使い方（IT の 直る）は学習で合わせるもの（案 E） |
| と＋かこう | 囲う（4 位） | かこう（5 位） | 連接表の「という／と思う」と「とか」。語のコストでは直らない。B15 とは別に、左文脈の増幅の扱いを見直す（案 F） |

提案で直るのは、同じ lemma の中の表記（捕 → 取、逢 → 会、薦 → 勧、奬・推・奨 の後退、現わす → 現す）と、文脈がないときや文脈の手がかりが弱いときの既定（すすめる → 進める、エラーが・このPRで ＋ なおす → 直す）。

## 7. 結果
- 得るもの: 異字同訓の動詞で、表外の表記が上位に出なくなる。文脈がないときに、広い意味の表記が出る。LM が間に合わないときの並びが良くなる。公用文の書き表し方（常用漢字表の訓、本則の送り仮名）を、辞書の作り方として持てる。
- 失うもの: 表の手入れ（同梱のデータ。ユーザーの確認が要る）。観る、現わす のような許容・表外の表記を好む人には、1 回目は後ろに出る（学習で戻る）。
- 変わらないもの: 候補の集合（消さない）。core、LM、学習。文脈の解析。

## 8. 実装の進め方（レーン 1 つ。実装は §11）
1. 契約: `dict-builder/policy/kun.tsv`（表の形式とヘッダ）、述語名 `kun_outside`・`kun_lemma_default`・`kun_reading_default`、`policy/chive.tsv` と `policy/default.tsv` の値。`function_word_notation` の判定の拡張（ヶ・ヵ を除く）。
2. dict-builder: 表を `include_str!` で読み、`PolicyRow` に辞書形の表記を足す（`InflectRow::dict_form` から引く）。lemma の中の最小のコストは、`kanji_peer_ranks` と同じく前処理で求める。表の内容をメタ情報（BUILD_INFO の policy の指紋）に含める。ポリシーのレポートに述語ごとの件数と例を出す。

## 9. 懸念点
- スパイクは Sudachi の CSV のコストを書き換えて測った。本実装のペナルティは変換にだけ効くので、文脈の解析の結果がスパイクとわずかに違いうる（左文脈に表外の表記が書かれている場合だけ）。**本実装で取り直した結果は、1位が変わったケースまでスパイクと同じだった（§11.3）。**
- 表は手で作る。漏れた lemma は今のまま（悪くはならない）。常用漢字表の訓の全体（約 1900）を機械で入れる案は、データの入手元を決めてから（§10 Q5）。
- verbs.tsv はこの ADR のために作ったセットで、値もこのセットの dev で決めた。test でも同じ向き（LM なし +3、LM あり +1）だったが、件数が少ない。ユーザーの確認（A2-6）のあとに、期待が変われば値を見直す。
- B15（ADR 0010）との関係: ADR 0010 は KanaStyleRanker の `aux_kanji_bonus` を同じ形の候補の中にだけ効かせる変更で、Ranker の段にある。本 ADR は辞書のコストだけを変え、KanaStyleRanker の語の表（`core/assets/kana_style.tsv`）にも触らない。動詞の表記の加点は、KanaStyleRanker の「本動詞は漢字」の加点の前段（ラティスと N-best）に効く。両方を入れたあとに、verbs.tsv と adverbs.tsv を合わせて流して確かめる。

## 10. ユーザーの判断が要る点
- **Q1（方針）**: 異字同訓の表を辞書のポリシーとして同梱し、表外の表記を後ろに回し、lemma の中の既定を決める（§1、案 A・B・K）。Claude の推奨: 採用。
- **Q2（文脈なしの既定）**: 読みだけのときの既定を、広い意味の表記にしてよいか。すすめる → 進める、なおす → 直す、なおる → 直る、かく → 書く、とる → 取る、きく → 聞く、かえる → 変える（下一段）・帰る（五段）、あける → 開ける、のぼる → 上る、おくる → 送る、うつ → 打つ、あらわす → 表す、みる → 見る。lemma の中では 勧める（薦める より先）、取る、会う。あう（会う・合う）、つとめる、はかる、うつる は既定を置かない。Claude の推奨: このとおり、値は -500。

- **Q5（表の範囲とデータ）**: 表を、報告と評価セットの動詞（50 lemma）から始めるか、文化審議会「異字同訓」の漢字の使い分け例（2014）の全体（形容詞の 早い・速い、暑い・熱い を含む）まで Claude が下書きするか。Claude の推奨: 使い分け例の全体を下書きして、A2 の確認に回す。
- **Q6（評価セット）**: `eval/sets/verbs.tsv` の期待（とくに 会話 と 文脈なし の行）が使い方に合っているか（A2-6）。

### 11.2 規則の細部（ADR の本文にない、実装で決めたこと）
- **分類は辞書形で行う**（§2.2 のとおり）。活用形の行は、辞書形 ID の行の表記と読みで判定する。漢字で始まらない表記（すすめる、ススメる、お勧める）は対象外。漢字が表にない、漢字が 2 字以上（還帰る）、または送り仮名が lemma に合わないもの（現わす、帰える、開ケる）は表外。
- **読みが標準の形と違う行は対象外にした**（§2.2 にない追加）。標準の形 = 表の漢字 + lemma の送り仮名の辞書形の行の読み（とその可能動詞の読み）。この読みでない行は別の語で、表記のゆれではない: 乗っかる（のっかる）、書くぅ、早え・暑し（古語・方言）、取る（どる。「〜どる」）は罰しない。入れないと、乗っかる のような実際に使う語を +3000 で後ろに回してしまう。
- **可能動詞**（書ける、取れる、見れる）は表外にしない。lemma の中の既定（`kun_lemma_default`）は可能動詞にも効くが、読みの組の既定（`kun_reading_default`）は効かない。
- **読みの組の既定は、読みが「組の読みの語幹」で始まる行だけ**（§2.2 にない追加）。語幹は組の読みの最後の 1 文字を除いたもの（すすめる → すすめ）。開ける の ひらける のように、組と違う読みの行に -500 が付かないため。
- **lemma の中の既定**は §2.2 のとおり（既定の行のコストが、ほかの表の表記の最小のコスト m 以上のときだけ、m - 50 にする）。比べるのは辞書のコストで、ペナルティは含めない。
- 値の意味: `kun_lemma_default` の値（-50）は、既定の表記をほかの表記より安くする差。既定の行に足す量は「-50 - (今の差)」になる（負の値。`frequent_compound` と同じく、`cost + penalty` が負にならない範囲）。
