# ADR 0068: プロセス間の口の規則。口ごとの役割、相手の確認、運んでよいもの、上限。設定と候補窓の相手の照合、エンジンを止める口

- 状態: 承認（2026-11-16 ユーザー決定。質問はすべて推奨どおり。実機などの確認が済んでいない決定は、確認が済むまで仮。末尾の「決定済み」を見る）
- 日付: 2026-11-16
- 対象: `pipe`（上限、締め切り、相手の PID）、`windows/tip/src/peer.rs`（照合の規則を 3 つの口で共有）、`windows/engine-host`（設定の口の相手の確認、止める口、接続の上限）、`windows/candidate`（受けた命令の扱い）、`lm/src/host/`（子に渡すハンドル）、設定画面、インストーラ。macOS は変えない（比べる相手として書く）。この ADR ではコードを変えない
- 前提: main = 94f65ae。[ADR 0066](0066-security-premises.md)（P1〜P3、R6）、[ADR 0067](0067-windows-install-layout-and-launch-chain.md)（インストール先が信頼の根。高い権限の TIP はつながない）、ADR 0040 §5、ADR 0062 §3・§5.4・§7、ADR 0064（接続ごとの状態、止めてよい者）、ADR 0060 Q4、`docs/architecture.md` §2.2（今の状態の表）
- 判断の置き場所: Rust。照合の規則は OS に依存しない純粋な関数（Mac でテストする）。OS から値を取るのは `cfg(windows)` の薄い層
- 既存の指摘は番号だけで参照する（S3 = #411、S4 = #412、S5 = #413）

## 1. 現状（分かったこと）

| 口 | 受け口の守り | つなぐ側が相手を確かめるか | 受ける側が相手を確かめるか |
| --- | --- | --- | --- |
| エンジン（TIP → engine-host） | 自分のユーザーと SYSTEM だけの DACL、リモート拒否、名前の先取りの防止（最初のインスタンス） | する（S1。実行ファイルのパス。`peer.rs`） | しない。管理の要求は受けない（設定の口だけが受ける。`windows/engine-host/src/lib.rs`） |
| 設定（設定画面 → engine-host） | 同じ | 画面がまだ無い | **しない（S3）**。最初の枠で版を照らすだけ。設定の読み書き、ユーザー辞書、学習の書き出し・取り込み・消去が届く |
| 候補窓（TIP → ikari-candidate） | 同じ（窓の本体はまだ無い） | **しない（S4）** | できない（どのアプリの TIP も正当な送り手） |
| LM の子（engine → ikari-lm-host） | 名前のない標準入出力 | 絶対パスで起動する | — 。**子に渡るハンドルを限定していない（S5）** |
| 止める（インストーラ → engine-host） | **口が無い**（ADR 0064 §6.2 で「エンジンのパイプとは別の口」とだけ決まっている） | — | — |

- つなぐ側は `SECURITY_IDENTIFICATION` で開く（受け口が、つないだ側になりすませない。`pipe/src/os/windows.rs`）。
- 枠の上限は、どの口も同じ 16MiB（`pipe/src/frame.rs`）。書き込みの締め切りは 200ms（#392）。接続は、接続ごとにスレッドを持つ。上限と締め切りの今の状態の細かい点は、ここには書かない（§7 で、何に上限を置くかを決める）。
- 設定の取り込みの上限は 64MiB で、パイプの枠（16MiB）より大きい（`settings_pipe.rs` の注記。未解決）。
- macOS: 殻とエンジンは XPC（署名要件で相互に確認）。設定アプリと殻は Unix ソケット（同じユーザー、署名要件、ad-hoc では cdhash とパス。#269）。候補ウィンドウは殻の中。

## 2. 決定 1: 共通の規則

1. **1 つの口に 1 つの役割（R6）。** 口ごとに、運んでよい要求を許可リストで持つ。許可リストの外は、中を解釈せずに断る。

| 口 | 役割 | 運んでよいもの | 運ばないもの |
| --- | --- | --- | --- |
| エンジン | 変換 | 変換、確定、文脈、セッション | 管理の要求（今のまま）、止める指示 |
| 設定 | 設定とデータの管理 | 設定の読み書き、ユーザー辞書、学習の状態と消去、書き出しと取り込みの**指示**（§4） | 変換と確定（学習を汚す道を作らない。今のまま）、止める指示 |
| 候補窓 | 描く | 候補と注釈の文字、位置 | それ以外のすべて |
| LM の子 | 採点 | 文字列を渡し、数値を受ける | それ以外のすべて |
| 止める | 止める | 合図 1 つ | データ |

2. **相手の確認は、実行ファイルのパスの照合を 1 か所の規則で行う。** 今の `peer.rs` の規則（インストール先は自分のモジュールの場所から決める、絶対パスどうしを文字列で比べる、リンクをたどらない、取れなければ拒む）を、設定と候補窓にも使う。前提は ADR 0067（インストール先は管理者だけが書ける）。署名が付いたら（NFR-42）、この 1 か所を署名の照合に替える。
3. **この確認が何を守り、何を守らないかを、口ごとに書く。** パスの照合は、正当な実行ファイルにコードを入れる相手には効かない（P3）。破られたときに残るものを、§3〜§6 に書く。
4. **受けた内容は、相手を確かめたあとでも信用しない。** 長さ、個数、数値の範囲、文字の種類を確かめる。壊れた枠は、返事をせずに切る（今のまま）。
5. **高い権限の相手を断る。** engine-host と候補窓は、つないできた相手の整合性が高以上なら、何も読まずに切る。高い権限の TIP はつながない決まり（ADR 0067 §5）なので、来るのは誤りか、ikari でない何か。P2 の二重の守り。
6. **上限と締め切りを、口ごとに持つ**（§7）。
7. **ログに出すのは、番号と固定の語だけ**（今のまま。NFR-19）。断った理由は種類だけを書く。

## 3. 決定 2: エンジンの口

- つなぐ側（TIP）の確認は今のまま（S1）。
- **受ける側は、相手のパスを確かめない。** TIP はどのアプリの中にもいるので、相手の実行ファイルは何でもありうる。この口は「同じ利用者のプログラムなら、だれでも変換を頼める」口と位置づける。
- そのうえで、この口から出せるものを小さく保つ: 管理の要求を受けない（今のまま）、接続ごとに状態を分ける（ADR 0064。ほかのアプリの文脈や変換が見えない）、返すのは変換の結果だけ。
- 残るもの（P3 の範囲。約束しない）: 同じ利用者のプログラムは、変換を頼める。確定を送って学習を汚せる（学習のファイルを直接書くこともできる相手）。
- **製品の engine-host は、データの場所を引数でも受けない**（R5 と同じ扱い。`--data-dir` は開発用のビルドだけ）。本物のエンジンを別のデータの場所で先に起動して、名前を取る道を閉じる。

## 4. 決定 3: 設定の口（S3）

- **双方が相手のパスを照らす。** engine-host は、つないできたプロセスの実行ファイルが、インストール先の設定画面の exe であることを確かめてから、最初の枠を読む。設定画面は、TIP と同じ規則で、相手が engine-host であることを確かめてから送る。
- **学習の全文を、口に流さない。** 書き出しと取り込みは、設定画面が利用者に選ばせたファイルのパスだけを送り、engine-host がそのファイルを読み書きする。枠の上限と取り込みの上限のずれ（16MiB と 64MiB）も、これで無くなる。パスは信用しない入力として扱う（絶対パスだけ、ネットワークの場所とデバイスのパスは拒む、取り込みはふつうのファイルだけで大きさの上限の中、書き出しは新しく作るときだけ書く・既にあれば上書きの確認は画面で済ませたうえで置き換える）。
  - engine-host は利用者の権限で動くので、利用者が書ける場所にしか書けない（権限は広がらない）。
  - macOS は形が違う（エンジンが Sandbox の中で、任意のパスに書けない。P2 のために、パスは殻の側で選ばせる必要がある）。#274 の設計のままにする。
  - （追記 2026-11-16。実装 W4-s3）枠は `bridge.proto` の `ExportToFile { path, replace }` と `ImportFromFile { path, dry_run }`（後方互換の追加）。返事は今の `ExportReply`（`content` は空）と `ImportReply`。失敗は `BridgeError` の `TRANSFER_FAILED` と理由の固定の語（`reason`。パスは入れない）。`ExportData` と `ImportData` の中継は、Windows の設定の口では `NOT_ALLOWED`。macOS の殻は新しい枠を受けない（`NOT_ALLOWED`）。設定画面の exe の名前は `ikari-settings.exe`（`pipe::peer::SETTINGS_EXE_NAME`）。
- 消去（学習、ユーザー辞書）は、画面での確認のあとにだけ送る。口の側は、確認の有無を見分けられない（守りは相手の確認だけ）。
- 破られたときに残るもの: 相手の確認を越えた者は、設定を書き換え、学習を消し、書き出しをさせられる。どれも、同じ利用者のプログラムがファイルを直接触ればできること（P3）。高い権限には届かない（engine-host は高い権限で動かない。ADR 0067 §4.3）。設定で変えられるものに、実行物のパスや通信の先を入れない（P5。モデルの URL の扱いは ADR 0071）。

## 5. 決定 4: 候補窓の口（S4）

- **TIP は、送る前に、相手がインストール先の `ikari-candidate.exe` であることを照らす。** 違えば閉じて、窓なしで続ける（下線つきの 1 位で入力できる。ADR 0062 §5.4）。守るもの: 候補と注釈の文字（利用者が打っている内容の写し）を、偽の窓に渡さない。
- **窓は、送り手を確かめない（できない）。その代わり、受けたものを「描く文字」としてだけ扱う。**
  - 文字として描くだけ（装飾の指定、リンク、画像、実行は受けない）。行の数、1 行の長さ、座標と倍率に上限を置き、外れたら切り詰めるか捨てる。作業領域の外に出さない。
  - フォーカスを取らない。クリックなどの操作を、送り手や利用者のデータに返さない（片道のまま）。
  - 持ち主の接続だけが `Update` と `Hide` を効かせられる（ADR 0062 §7。#405）。
  - 高い権限では動かない。高い権限の送り手は断る（§2 の 5）。
- 残るもの: 同じ利用者のプログラムは、候補窓に好きな文字を出させられる（自分で窓を作っても同じことができる相手。P3）。
- secure な欄では、TIP は候補を作らないので、何も送らない（今の `shell-core` の動きのまま）。

## 6. 決定 5: LM の子の口（S5）と、止める口

### 6.1 LM の子
- 子に渡すハンドルは、標準入出力の 3 つだけにする（ADR 0067 §4.3 の共通の規則。S5）。エンジンのパイプ、ログ、学習のファイルのハンドルが子に渡らないことを、テストで確かめる。
- 親は、子の返事を信用しない（今のまま: 個数、枠の長さ、装置の語の文字の種類）。数値は有限の値だけを受ける。
- 子は、親だけを相手にする（名前のない口なので、ほかのプロセスはつなげない）。隔離は ADR 0072。

### 6.2 止める口（ADR 0064 §6.2 の「別の口」の中身）
- **engine-host は、起動のときに、名前つきのイベントを 1 つ作る。合図されたら、受け付けを止め、学習を保存して終わる。** できることは「止める」だけ（R6）。
- 名前には SID とセッションを入れる（パイプと同じ作り）。合図を許すのは、自分のユーザー、SYSTEM、管理者。
- 名前を先に取られていたら（作ったのが自分でなければ）、その口は使わない。engine-host は動き続ける（止める口が無いだけ）。
- **インストーラは、インストール先の engine-host の exe で動いているプロセスを、すべてのセッションから探し、合図を送り、決めた時間だけ待ち、残っていれば強制的に終わらせる。** 強制の終了で失うのは、最後の保存のあとの学習だけ（学習は数秒ごとに保存されている）。待つ時間は、実機で終了にかかる時間を測って決める。
- 残るもの: 同じ利用者のプログラムは、エンジンを止められる（プロセスを直接終わらせることもできる相手）。止まったエンジンは、次の入力で TIP が起動し直す（ADR 0067 §4.2）。
- エンジンのパイプの `Shutdown` は、今のまま「保存して返事」だけ（ADR 0064 D6）。

## 7. 決定 6: 上限と締め切り（止まりにくさ）

TIP はすべてのアプリの中にいるので、エンジンや候補窓が固まる・あふれることは、そのまま入力の障害になる。値は、ここでは決めない（計測で決める）。決めるのは、何に上限を置くか。

| 何に | 今 | 決めること |
| --- | --- | --- |
| 同時の接続の数（口ごと） | — | 上限を置く。超えた接続は、受けてすぐ切る。エンジンと候補窓は、実機で TIP の接続の数（アプリとスレッドの数）を数えてから値を決める。設定は小さい固定の数 |
| 枠の大きさ（口ごと） | どの口も 16MiB | 口ごとに分ける。エンジンと候補窓は、実際の最大の枠を測って、その上に余裕を置いた値にする。設定は §4 で全文を流さなくなるので、小さくできる |
| 枠の途中で止まった相手 | — | 枠の最初のバイトから終わりまでに締め切りを置き、超えたら切る（何も送らずにつないだままの接続は正当なので、切らない） |
| 書き込み | 200ms（暫定。#392） | そのまま。値は #392 で決める |
| 固まったエンジンの数え方 | 未決（#404） | #404 で決める |

- **受け口を作れないとき**（名前を先に取られていた、など）: engine-host は、理由の種類を `logs/start-failure.log` に書く（今ある仕組み）。TIP は、相手の確認で断ったことを、種類だけ覚える。利用者に見せる場所は設定画面の状態の欄（「エンジンにつながりません。理由: 相手を確認できない」の形。文は `shell-core`）。候補窓や通知では知らせない（打っている最中に割り込まない）。

## 8. 検討した案

- **エンジンの口でも、相手のパスを確かめる（OS とブラウザなどの一覧を持つ）**: 一覧に無いアプリで変換できなくなる。採らない。
- **口ごとに、起動のときの乱数を合言葉にする**: 合言葉を置く場所は利用者のファイルかレジストリで、同じ利用者のプログラムは読める。パスの照合より強くならない。採らない。
- **止める口を、設定の口の要求にする**: 設定画面を装えれば止められるのは同じだが、設定の口に「止める」が混ざり（R6）、インストーラが設定の口の取り決めを話す必要が出る。別のセッションのエンジンにも届きにくい。採らない。
- **止める口を持たず、常に強制的に終わらせる**: 作りは最も小さい。最後の数秒の学習を毎回失う。合図の口は小さく作れるので、持つ方を採る。うまく動かなければ（§10）、この案に下がる。
- **候補窓が、送り手のパスを確かめる**: 送り手はすべてのアプリなので、確かめられることがない。

## 9. 結果

- `docs/architecture.md` §2.2 の表の「未決」（S3、S4、S5、止める口）に、決める形ができる。表は、実装の PR で直す（今の状態の表なので、この PR では直さない）。
- 設定の口が学習の全文を運ばなくなる（Windows）。macOS は #274 のまま。
- 実装の issue（承認のあとに切る）: 照合の規則の共有と設定・候補窓への適用、書き出しと取り込みをパスにする、候補窓の受け取りの上限、止める口、接続・枠・途中の枠の上限、高い権限の相手を断る、engine-host の引数。
- 失うもの: 口ごとの値（接続の数、枠の大きさ、締め切り）を、実機で測る手間が増える。

## 10. 推測（確かめていないもの。実機の項目にする）

- ふつうの権限のプロセスが作った名前つきのイベントを、別のセッションで動く管理者のインストーラが開いて合図できるか。できなければ、合図は同じセッションのエンジンだけにし、ほかのセッションは強制の終了にする。
- 相手の PID から実行ファイルのパスを取るまでの間に、相手が入れ替わる隙があるか（今の S1 の実装は、PID からプロセスを開いてパスを取る。開いたハンドルを持ったまま比べれば、番号の使い回しは避けられる見込み）。
- WinUI 3 の窓で、行の数や文字の長さを切り詰めたときの見た目。
- macOS の IMK の接続名の先取り（#273）は、この ADR では扱っていない。調べた結果で、macOS の表に足す。

## 11. ユーザーに聞くこと

### 決定済み（ユーザー、2026-11-16。すべて推奨どおり）

- **Q1**: Windows の書き出しと取り込みは、ファイルのパスだけを口に流し、engine-host が読み書きする。macOS は #274 のまま。
- **Q2**: インストーラがエンジンを止める口は名前つきのイベントにし、応じなければ強制的に終わらせる。**別のセッションへの合図は、VM で確かめるまで仮。**
- **Q3**: 受け口を作れない・相手を確認できないときの知らせは、設定画面の状態の欄だけ。
- **確認が済むまで仮のもの**: 止める口（名前つきのイベント）が別のセッションから合図できるかは VM で確かめる。できなければ、§10 のとおり同じセッションだけにする。上限と締め切りの値は、計測のあとに決める。

### （記録）決定の前の問い

- **Q1. Windows の書き出しと取り込みは、ファイルのパスだけを口に流し、engine-host が読み書きする（§4）。** 学習の全文が口を通らなくなり、大きさのずれも無くなる。macOS は #274 のまま（形が違う理由は §4）。**推奨: パスだけにする。**
- **Q2. インストーラがエンジンを止める口は、名前つきのイベントにし、応じなければ強制的に終わらせる（§6.2）。** 強制のときは、最後の数秒の学習を失うことがある。**推奨: この形。**
- **Q3. 受け口を作れない・相手を確認できないときの知らせは、設定画面の状態の欄だけにする（§7）。** 打っている最中には知らせない。**推奨: 設定画面だけ。**
