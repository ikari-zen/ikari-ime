# ウイルス対策ソフトの誤検出について（未署名の配布物）

> [!NOTE]
> **ビルド済みのアプリは、まだ配布していません（[README.md](../README.md)）。**
> この文書は 0.1.0（未署名の macOS 版）の公開に向けた案内（下書き）です。実機確認（#241）やリリースの準備が済んでいないため、配布パッケージの確定名や、作者の署名鍵の公開鍵の置き場所、macOS の未署名警告の越え方などは**未定**です。

ikari-ime の 0.x の配布物は、Apple の開発者署名・公証（Developer ID）や Windows の Authenticode 署名を付けずに配布する方針です（macOS 版は ad-hoc 署名）。署名が無い実行ファイルや配布物は実績が少ないため、安全に作られた公式の配布物であっても、ウイルス対策ソフトや OS の保護機能によって**誤検出（マルウェア扱い・ブロック・警告）が起きる可能性**があります（推測・未署名配布の一般的な性質であり、特定の製品での再現結果を保証するものではありません）。

> [!IMPORTANT]
> **OS やウイルス対策ソフトの守りを切らないでください。**
> ikari-ime の公式文書では、OS の保護機能（Gatekeeper、Microsoft Defender、SmartScreen、Smart App Control など）を無効にする手順や、ウイルス対策ソフトに除外設定を入れる手順は案内せず、勧めません（[SECURITY.md](../SECURITY.md)、[ADR 0069](adr/0069-distribution-authenticity.md) §3 の 5）。「守りを切って入れてください」という案内は ikari-ime のものではありません。

---

## (a) 起きうる症状

未署名であることが理由で、次のような症状が起きる場合があります。

- **ダウンロードが止められる**: ブラウザやウイルス対策ソフトが「一般的にはダウンロードされていません」「危険なファイル」などの警告を出し、保存を止める。
- **展開・配置・インストールの直後に隔離・削除される**: ファイルを開いたり配置したりした直後に、セキュリティソフトがファイルを隔離・削除する。
- **起動や入力の開始時に警告・ブロックが出る**: OS の警告（macOS の Gatekeeper や、将来の Windows 版における SmartScreen など）やウイルス対策ソフトの遮断により動かない。

未署名の配布物が環境や保護方針に合わない場合は、保護機能を切らずに [README.md](../README.md) の手順でソースコードからご自身でビルドして使う方法をご検討ください。

- **macOS の未署名警告の越え方**: 実機での確認（#241）が済んでいないため**未定**です。確認が済み次第、実機で確かめた安全な手順だけを案内します（隔離属性を消すコマンドや Gatekeeper を無効化する手順は書きません）。
- **Windows 版（1.0.0 予定）の補足**: Smart App Control が有効な PC では、コード署名が付くまで動作しません。この守りを切る手順も案内しません（[SECURITY.md](../SECURITY.md)）。

## (b) 配布物の確かめ方

警告や検出が出たときは、まず手元のファイルが**公式に作られた本物かどうか**を確かめてください。

**公式の配布元は、GitHub の `ikari-zen/ikari-ime` の Releases だけです。** ほかのサイトやまとめサイトなどにあるものは公式ではありません。

- 配布ページ: `https://github.com/ikari-zen/ikari-ime/releases`

公式の Release には、本物を見分けるための **3 つの証拠** を付ける設計です（[ADR 0069](adr/0069-distribution-authenticity.md) §3、[publish-checklist.md](publish-checklist.md) §4）。

### 1. SHA-256 ハッシュの一覧（`SHA256SUMS`）

ダウンロード中に壊れていないか、Release ページ上のファイルと一致するかを確かめます。同じ Release ページにある `SHA256SUMS` の値と比べてください。

- **macOS（ターミナル）**:

  ```sh
  shasum -a 256 -c SHA256SUMS
  # 個別のファイルだけ調べる場合:
  shasum -a 256 <ダウンロードしたファイル名>
  ```

- **Windows（コマンドプロンプトまたは PowerShell）**:

  ```powershell
  certutil -hashfile <ダウンロードしたファイル名> SHA256
  ```

### 2. GitHub の成果物の証明（attestation）

そのファイルが、このリポジトリ（`ikari-zen/ikari-ime`）の公開 workflow からどのコミットで作られたかを、GitHub の公開台帳で確認します（GitHub CLI `gh` が必要です）。

```sh
gh attestation verify <ダウンロードしたファイル名> -R ikari-zen/ikari-ime
```

### 3. 作者の鍵による `SHA256SUMS` の署名（minisign 形式）

GitHub アカウントや CI から独立して、作者本人が手元の鍵で `SHA256SUMS` を認めたことを確かめます。

- **作者の公開鍵の置き場所と値**: **未定**（配布の開始までに README、`SECURITY.md`、リポジトリに公開する予定です）。
- 公開鍵の公開後に確認するときのコマンド例（`minisign` が必要です）:

  ```sh
  minisign -Vm SHA256SUMS -p <公開鍵ファイル>
  ```

> [!WARNING]
> **確かめに 1 つでも失敗した場合（ハッシュが合わない、証明や署名の検証に通らない場合）は、そのファイルを開いたり実行したりしないでください。**
> 改ざんや偽造の可能性があるため、公開の Issue には書かず、[SECURITY.md](../SECURITY.md) の「脆弱性の報告」（GitHub の Security タブにある **Report a vulnerability**）から非公開でお知らせください。

## (c) 誤検出だと思うときの報告先

上の「配布物の確かめ方」で本物であると確認できた公式 Release について誤検出が起きた場合は、**GitHub の Issue だけ**から報告してください。作者の個人メールアドレスなどの連絡先は設けません。

- **報告先（GitHub Issue）**: `https://github.com/ikari-zen/ikari-ime/issues`

Issue を立てるときは、次の内容を書いてください（お名前・住所・メールアドレスや、ユーザー名を含むホームディレクトリのパスなどの個人情報は書かないでください）。

1. **Release の版（タグ名）とファイル名**
2. **上の 3 つの検証（`SHA256SUMS`、GitHub の成果物の証明、minisign 署名）を行った結果**
3. **お使いの OS とバージョン**
4. **ウイルス対策ソフトの名前、バージョン、定義ファイルの版**（分かる範囲）
5. **起きた症状と表示された検出名・メッセージ**

公式の Release に対する誤検出であると確認できた場合、作者が各ウイルス対策ソフトの提供元へ誤検出の報告を行います。
