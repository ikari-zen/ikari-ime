# セキュリティ設計（地図）

ikari-ime のセキュリティの設計を 1 か所から引けるようにした地図。理由は書かない（ADR へのリンクにする）。
決定を足す・変える PR は、この地図を一緒に直すこと。今の構成は [architecture.md](architecture.md)、脆弱性の報告の窓口は [SECURITY.md](../SECURITY.md)。

状態（2026-11-16）: 設計の途中。下の ADR はすべて「提案」で、ユーザーの承認の前。実装はまだ始めていない。
既存の指摘の詳細は、公開の文書に書かない（番号 S1〜S5 と issue #411〜#413 だけで参照する。ユーザー決定 2026-11-15）。

## 1. 前提（[ADR 0066](adr/0066-security-premises.md)）

**約束の線**

| # | 約束 |
| --- | --- |
| P1 | ikari は権限の境界を広げない。高い権限のプロセスの中の ikari は、低い権限の者が書けるものを信用しない |
| P2 | OS が守っているもの（macOS の打鍵の読み取りの許可、Windows の高い権限のアプリの入力、別の利用者）を、ikari が抜け道にしない |
| P3 | Windows で、同じ利用者の同じ権限のマルウェアから打鍵を守るとは約束しない。名前の先取りの防止、相手のパスの照合、DACL という安い守りは入れる |
| P4 | 配る物が本物であることを、署名なしでも確かめられるようにする |
| P5 | データは実行物にならない。利用者が書ける場所から読むものは、信用しない入力として読む |
| P6 | 取得の通信は、内容を確かめてから使う |

**信頼の根**

| # | 規則 |
| --- | --- |
| R1 | 実行物は、管理者だけが書ける場所に置く |
| R2 | 実行物の場所は、自分の実行ファイルのパスから決める（環境変数、PATH、HKCU から決めない） |
| R3 | データの場所から読むものは、信用しない入力 |
| R4 | 高い権限のプロセスの中では、利用者が書ける場所を読まない・書かない・つながない |
| R5 | 製品のビルドは、環境変数で挙動を変えない |
| R6 | 1 つの口に、1 つの役割 |

**通信しない**: ikari のどのプロセスも、利用者の操作なしにネットワークへ出ない。操作があって出てよいのは、取得する部品だけ。守りは 3 層（持たない、OS で禁じる、実機で確かめる）。同梱する他社の部品の通信も、ikari の通信として数える。

### 進み具合（再開の手がかり。2026-11-16）

- 書いた順: 前提（0066）→ 置き場所と起動（0067）→ プロセス間の口（0068）→ 配る物の真正性（0069）。残りは、重大度の高い順に 6 → 8 → 7 → 5 → 9（ユーザーの指示）。
- 番号は、ADR 0066 の本文に書いた割り当て（0070 更新、0071 設定画面と取得、0072 LM、0073 秘密の入力とデータ）のまま使う。書く順と番号の順は違う。
- 領域 6 の調べかけ（分かったこと。Microsoft Learn「Data and privacy in WebView2」「Distribute your app and the WebView2 Runtime」を 2026-11-16 に見た）:
  - WebView2 は、Windows の診断データの設定がどうであっても「必須の」診断データを集める。アプリの側から全体を止める口は無い、と文書にある。止められるのは SmartScreen（`IsReputationCheckingRequired`）と、クラッシュのダンプの送信（`IsCustomCrashReportingEnabled`）。
  - Evergreen のランタイムは、Microsoft の更新の仕組みが自動で新しい版を落とす（ikari のプロセスではない）。Fixed Version は自動で更新されず、250MB を超え、アプリが自分で版を上げて配る。
  - ランタイムの実体は別の実行ファイル（`msedgewebview2.exe`）で動くので、ikari の exe にかけたファイアウォール規則は届かない。
- 領域 8 の調べかけ: Windows のデータのフォルダの権限は、プロファイルの ACL に任せている（`core/src/user/util.rs`。Unix だけ 0700）。TIP の `OutputDebugString` は製品でも出る（文字は出ない。`windows/tip/src/com/log.rs`）。TIP はログに実行ファイルの名前を渡す（#398）。
- 実機で確かめる項目（各 ADR の「推測」の節）は、まだ `docs/windows-real-device-check.md` に足していない（領域 9 で足す）。
