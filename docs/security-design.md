# セキュリティ設計（地図）

ikari-ime のセキュリティの設計を 1 か所から引けるようにした地図。理由は書かない（ADR へのリンクにする）。
決定を足す・変える PR は、この地図を一緒に直すこと。今の構成は [architecture.md](architecture.md)、脆弱性の報告の窓口は [SECURITY.md](../SECURITY.md)。

状態（2026-11-16）: 9 つの領域の設計を一通り書いた。下の ADR はすべて「提案」で、ユーザーの承認の前。実装はまだ始めていない。各 ADR の「推測」は、実機と一次情報で確かめる前のもの。
既存の指摘の詳細は、公開の文書に書かない（番号 S1〜S5 と issue #411〜#413 だけで参照する。ユーザー決定 2026-11-15）。

## 1. 前提（[ADR 0066](adr/0066-security-premises.md)）

**約束の線**

| # | 約束 |
| --- | --- |
| P1 | ikari は権限の境界を広げない。高い権限のプロセスの中の ikari は、低い権限の者が書けるものを信用しない |
| P2 | OS が守っているもの（macOS の打鍵の読み取りの許可、Windows の高い権限のアプリの入力、別の利用者）を、ikari が抜け道にしない |
| P3 | Windows で、同じ利用者の同じ権限のマルウェアから打鍵を守るとは約束しない。名前の先取りの防止、相手のパスの照合、DACL という安い守りは入れる |
| P4 | 配る物が本物であることを、署名なしでも確かめられるようにする |
| P5 | データは実行物にならない。利用者が書ける場所から読むものは、信用しない入力として読む |
| P6 | 取得の通信は、内容を確かめてから使う |

**信頼の根**

| # | 規則 |
| --- | --- |
| R1 | 実行物は、管理者だけが書ける場所に置く |
| R2 | 実行物の場所は、自分の実行ファイルのパスから決める（環境変数、PATH、HKCU から決めない） |
| R3 | データの場所から読むものは、信用しない入力 |
| R4 | 高い権限のプロセスの中では、利用者が書ける場所を読まない・書かない・つながない |
| R5 | 製品のビルドは、環境変数で挙動を変えない |
| R6 | 1 つの口に、1 つの役割 |

**通信しない**: ikari のどのプロセスも、利用者の操作なしにネットワークへ出ない。操作があって出てよいのは、取得する部品だけ。守りは 3 層（持たない、OS で禁じる、実機で確かめる）。同梱する他社の部品の通信も、ikari の通信として数える。

## 4. 利用者に約束すること（`SECURITY.md` の書き直しの原案。ビルド済みを配るときに入れる）

**約束すること**
- ikari のどのプロセスも、利用者の操作なしにネットワークへ出ない。操作があって出るのは、設定画面のボタンから起こす取得の部品だけ（モデルの取得、版の確認）。
- ikari は、利用者より高い権限を取らない。管理者として動くアプリの中では、何も読まず、何も送らず、キーをそのままアプリに渡す。
- パスワード欄などの秘密の欄では、変換も、記録も、学習もしない。
- 診断ログには、読み、候補、周辺のテキストを書かない。
- 配る物は、GitHub の Releases だけで配り、sha256 と、作られた経過の証明と、作者の鍵の署名を付ける。
- ikari の文書は、OS やウイルス対策の守りを切るよう求めない。

**約束しないこと（限界）**
- 管理者や OS そのものが敵の場合。
- Windows で、同じ利用者の同じ権限で動くマルウェアから、打鍵と学習のデータを守ること。
- アプリが秘密の欄だと知らせない入力欄（独自に描く欄、端末の中のパスワードの入力、リモートの窓の中の欄）。そこで打った内容は、学習や、メモリの中の文脈に入りうる。
- ikari が入っているアプリが落ちたときに、そのアプリや OS が作るダンプの中身。
- OS の部品が行う通信（OS の更新、ファイルの評判の確認）。
- 利用者が警告を越えて入れたモデルの質。害は檻の中に閉じ込める。
- Smart App Control が有効な Windows では、署名が付くまで ikari は動かない。

**そのほか**: 直す版は最新の版だけ。脆弱性の報告は非公開の窓口へ。約束しない範囲の報告には、この節を示して答える。

## 5. 設計を守り続ける検査

### 5.1 CI（PR ごと。`scripts/check.sh` か、Windows の job）

| 検査 | 守る規則 |
| --- | --- |
| 依存に、HTTP・TLS・ソケットの crate が無い（`ikari-data` を除く） | 通信しない（L1） |
| できた実行ファイルが、通信の DLL を取り込んでいない（`ikari-data` を除く） | 通信しない（L1） |
| TIP の DLL が取り込む DLL が、OS の標準のものだけ | DLL の探索（ADR 0067 §4.4） |
| 製品のビルドに、開発用の環境変数の名前の文字列が無い | R5 |
| プロセスの種類の判定と素通し、相手のパスの照合、口ごとの許可リスト、子に渡すハンドルのテスト | P1・P2、R4・R6 |
| `cargo-deny`（既知の脆弱性、取得元、ライセンス） | E1 |
| workflow の Action が、すべて SHA で固定されている | E1 |
| secure のときにしないことの共通のシナリオ | ADR 0073 §2 |

### 5.2 版を出す前（リリースの workflow と、作者の手作業）

- 製品のビルドであること（開発用の口なし、Smoke なし）。macOS は、エンジンと LM の子の Sandbox の設定を照らす。
- インストール先の ACL、登録、規則、自動起動が、インストーラを VM で流したあとに期待どおりであること。
- 送信の記録を取り、起動・入力・設定画面・更新の間に、ikari のプロセスからの送信が無いこと（L3）。
- 利用者が書ける場所の入力を読むパーサに、でたらめな入力を流すテスト（fuzz）を、決めた時間だけ流す。PR ごとには流さない（時間がかかる）。
- 同梱した他社の部品の版を、修正の入った版に上げたか（ADR 0070 §6）。
- 3 つの証拠（sha256、証明、作者の鍵の署名）がそろっていること。

### 5.3 実機と一次情報で確かめる「推測」（各 ADR の推測の節から。重いものから）

| 何を | どの ADR | 外れたとき |
| --- | --- | --- |
| TIP が、高い権限のプロセス・ストアのアプリ・サインイン画面で素通しになる | 0067 §5 | 判定の作りを直す（P1・P2 に関わるので、配る前に必ず通す） |
| WinUI 3 と .NET の実行時が、自分から通信しない | 0071 §6、0066 §9 | 設定画面と候補窓の方式を見直す |
| WinUI 3 の最小の設定画面（入力欄で ikari を使える、ほか） | 0071 §6 | Slint に下がる |
| Smart App Control の動き（署名なしが止まるか、例外を置けるか） | 0069 §9 | 案内の文を直す |
| macOS: `/Library/Input Methods` で今の作りが動く、ad-hoc で Sandbox が効く、外から XPC につなげない | 0069 §9 | 今の置き場所のまま、限界を書く |
| `crt-static` で、TIP の DLL が OS の標準でない DLL に依存しなくなる | 0067 §10 | 依存する DLL を、絶対パスで読む形にする |
| 止める口（名前つきのイベント）が、別のセッションの管理者から合図できる | 0068 §10 | 同じセッションだけにし、ほかは強制の終了 |
| 低い整合性と AppContainer の子で、GPU（Vulkan）が使える | 0072 §10 | 段から外す、または CPU だけにする |
| OS のエラー報告からの除外が効く | 0073 §8 | 別の止め方を探す。無ければ限界として書く |
| Windows に付いている curl が、要る引数を受ける | 0071 §6 | Rust の HTTP・TLS の crate にする |
| インストーラの道具が、一時の場所を管理者だけが書けるように作る | 0067 §10 | 道具を替える |

## 7. 実装の順の案（承認のあと。重大度と、悪用のされやすさの順）

1. TIP のプロセスの種類の判定と素通し（P1・P2。ADR 0067 §5）。
2. `crt-static` と、取り込む DLL の検査（ADR 0067 §4.4）。開発用の口を feature に分ける（同 §6）。
3. 子に渡すハンドルの限定と、LM の檻の段 1（S5。ADR 0068 §6.1、0072 §3）。製品のエンジンから llama.cpp を外す（0072 §5）。
4. 設定と候補窓の相手の照合（S3・S4。ADR 0068 §4・§5）。画面と窓を作るときに、最初から入れる。
5. インストーラ（置き場所の検査、登録、規則、自動起動、止める口。ADR 0067 §3・§4、0068 §6.2）。
6. リリースの workflow と 3 つの証拠、`cargo-deny`（ADR 0069）。macOS の配布用のビルド（Smoke を外す、置き場所の確認）。
7. データのフォルダの ACL、`app=`、エラー報告からの除外、読む量の上限（ADR 0073）。
8. 口ごとの上限と締め切り（ADR 0068 §7。値は計測のあと）。
9. 設定画面（方式の確認のあと）、取得する部品、版の確認（ADR 0071、0070）。
10. LM の檻の段 2 と、自由指定のモデル（ADR 0072、0060）。
