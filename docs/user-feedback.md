# ユーザーの指摘と、それを受けた決定

実際に使ってみて見つかったこと、ユーザーが示した方針を、具体例つきでまとめる。新しい機能や修正を考えるときは、まずここを読む。詳しい経緯は各 ADR とコミットにある。

最終更新: 2026-10-22

---

## 1. 原則（迷ったらここに戻る）

### 1.1 ユーザーの入力を正とする
- 要件定義書の「基本原則」として追加した（2026-10-12）。入力していない内容を補ったり、確定した文字列を勝手に変えたりしない。
- **「入力を正とする」は「選択肢を制限しない」より優先する**（2026-10-13）。
  - 例: 「ことだよね」と打つと、候補に「ことだよね**〜**」が出た。読みは「ね」だけなのに、表記に「〜」が付け足されている。入力していないものが出ているので、後ろに回すのではなく**出さない**。
  - 「ことだ**YO**ね」（よ を英字にしたもの）は、何も付け足していないので、出すことはあるが、ずっと後ろに回す。
  - 本物の候補を後ろに回すことと、入力していない内容を足すことは、別のものとして扱う。
- **ユーザーの書いた言葉を尊重する**（2026-10-14）。IT の語は、打った読みのとおりのカタカナを1位、英字を2位にする。
  - 例: りなっくす → 1 リナックス 2 Linux、どっかー → 1 ドッカー 2 Docker（以前は Docker が1位）。英字を選べば学習で上がる（ADR 0012 §4.3。B20-3）。
- **カタカナで打った読みは、英字が1位に来たらカタカナを1位にする**（2026-10-15〜16。B32）。例外は置かない。
  - 例: はるしねーしょん → 1 ハルシネーション 2 Hallucination（以前は Hallucination が1位）。URL（ゆーあーるえる → ユーアールエル）、km/h、ChatGPT、COVID-19、MySQL（まいえすきゅーえる → マイエスキューエル）、LM が英字を推したときの Kubernetes も同じ。文の中の1語（ハルシネーションが起きる）も効く。
  - 英字のままにしたい語は、1回英字を選べば1位に戻る（学習で英字の加点がカタカナより多いとき。ADR 0020 E4）。ユーザー辞書に英字だけで登録した語は英字のまま（E3）。

### 1.2 学習は支援であって、決定ではない
- 過去の選択で、今の文脈の判断を覆さない（LearningGuard）。学習で候補を消さない。
- 例: 過去に技術文書で「品詞」を何度選んでいても、「敵の攻撃を受けて兵士は」+ ひんし は「瀕死」のまま。
- 文脈の記録がない入力では、その読みで選んできた表記に戻ってよい（ADR 0013 の back-off。2026-10-14）。原則と両立するのは、覆す相手の「今の文脈の判断」がないとき（文脈の特徴量にその読みの記録がない）だけに効かせ、文脈の証拠がある候補は LearningGuard が守るから。

### 1.3 こまめに確定するのがコンセプト。長文は追わない
- 長文を一度に変換するときの精度や速さのために、仕組みを複雑にしない。長文なら少し待ってもよい（LM の待ち時間を読みの長さに応じて延ばす）。
- 例: LM は zenz-v3.2 small の1つだけにした。長文向けに xsmall や kanakanji-edge と使い分ける案は採らなかった。古いモデル（zenz-v2.5 medium）も追わない。
- 追記（2026-10-16）: 「LM は1つだけ」は今の構成の話で、**モデルを足す案を検討する前提として、見直す余地を残す**（ユーザー決定）。英語まじりの文脈（ADR 0015 §6、E-D）など、zenz small で効かない場面が測れたときに、ADR で実測して聞く。長文向けの使い分けを採らない決定（上）は変わらない。
- LM に読みから直接文字列を作らせて、その結果を候補に足す案は取り下げた。読みと合わない表記を出しうるため（1.1 に反する）。

### 1.4 表記の既定は「公用文の書き表し方」
- 例:

  | 入力 | 期待 | 以前の1位 |
  | --- | --- | --- |
  | そこを + あえて | あえて | 会えて |
  | 確認して + ください | ください | 下さい |
  | 資料を + ください | 下さい（本動詞なので漢字） | 下さい |
  | 困った + とき | とき | と気 |
- 補助動詞、形式名詞、接続詞、一部の副詞はひらがなにする。個人の好みは学習で合わせる（`eval/sets/hiragana.tsv`、KanaStyleRanker）。
- 評価セットに「あえてひらがなで確定する」ケースが足りない、という指摘から作った。

## 5. 今後の候補として記録したもの
- **機械速記**: メジロ式のようなもの。ikari には汎用の速記エンジンだけを入れ、キー配置や表はユーザーが作る定義ファイルから読む（GPL の素材を同梱しない）。定義ファイルで再現できなければ実装しない。ほかの作業が終わってから（`docs/research/steno-survey-2026-10.md` §8）。
- **辞書の版**: SudachiDict Core のままにするか Full にするか（ユーザーの判断待ち）。
- **変換の品質の残課題**: 「じどうか」「さいてきか」は直った（811530c）。こうぞうか、かくちょうせい も直った（#13）。文脈のあとの1文字（自動＋か、洗濯＋き）と、副詞の直後の名詞（そうじき）は ADR 0007、0008 で実装中（B13、B14）。残りは docs/tasks.md の B17。
- **キーボードごとの配列**（2026-10-21）: 内蔵は QWERTY、Bluetooth は大西配列、有線は薙刀式、のようにキーボードごとに配列を切り替えたい。打鍵のキーボードを特定できなければ、最後に打鍵があったキーボードの配列で変換する案。難度は高い（物理層に近い）。#201（#199 の入力配列の上に乗る。#199 も P1 に上げた）。
- **住所と郵便番号**（2026-10-21〜22）: 住所の一発変換（#202）、住所と郵便番号の相互変換（#203。日本語は既定でオン、英語は既定でオフ。町名だけでも後ろに郵便番号を出す案は要検討）、「て」「テ」「te」＋数字で〒つきの候補（#204。スイッチは有効／無効のみ、既定は無効）。**地名に限って補完を出してもよいが、要検討。** 「中野区の」のように、地名の頭と同じ読みで始まる文を打つときに邪魔になるので、まずは補完を入れない前提（#202）。例は公開されている地名だけで書く（ユーザーの住所は issue や文書に書かない）。
